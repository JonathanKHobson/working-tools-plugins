# Licensing and attribution

New first-party code editions use AGPL-3.0-only. New first-party documentation, prompts, skill text, methods and eligible creative templates use CC BY-SA 4.0. Original author: Jonathan Kyle Hobson, public-facing Kyle Hobson.

Read the [authoritative overview](../LICENSING.md), [code license](../legal/LICENSE-CODE-AGPL-3.0.txt), [documentation policy](../legal/LICENSE-DOCS-CC-BY-SA-4.0.md), [brand and attribution](../legal/BRAND-AND-ATTRIBUTION.md), [NOTICE](../NOTICE.md) and [third-party notices](../THIRD_PARTY_NOTICES.md). Each package contains its own LICENSE-SCOPE.json and licensing documents.

Imported code, source methods, fonts and mixed adaptations retain their underlying grants. The new policy covers only author-owned contributions. Personal and official identity marks are reserved; eligible fictional template artwork remains reusable under its scoped creative license. Recipient data, external corpora and provider assets are excluded.

Earlier releases remain available under their original grants. Their licenses are preserved in legal/prior-grants and are not revoked. Each new patch edition carries these license documents; tags, release assets and earlier download bytes are preserved.

## Use in client work and commercial projects

Commercial use is permitted by the scoped first-party licenses. Start with the exact file's entry in `LICENSE-SCOPE.json`; a package-wide label does not replace an upstream license or grant rights to recipient data.

| What you do | What to retain or check |
| --- | --- |
| Run the tools to produce your own report, lesson, chart or video | Running the program alone does not place unrelated output under AGPL. Check whether the output actually copies protected code, template text or artwork. |
| Modify or distribute covered software | Keep copyright/license notices and mark changes. Convey covered source under AGPL; when distributing object code, provide its Corresponding Source through a permitted route. A modified network service must offer Corresponding Source to its remote users as section 13 requires. |
| Share or adapt a covered method, worksheet, guide or creative template | Credit the author, link the source and CC BY-SA 4.0, retain supplied notices and identify changes. Shared adaptations use CC BY-SA 4.0 or a permitted compatible license; do not impose restrictions that remove those rights. |
| Use a bundled OFL font in a design | Ordinary typeset documents and graphics do not become OFL-licensed. When bundling or modifying the font itself, retain its exact license and copyright; observe any Reserved Font Names. Do not sell the font by itself. |
| Incorporate an external dataset, reference, photograph, recording or provider asset | Check that material's own rights and the intended use. Search results, availability and attribution alone do not establish permission. This repository does not relicense recipient inputs or external provider output. |
| Use the Working Tools identity | Attribution is welcome. The reserved official name/identity does not authorize endorsement, impersonation or use as your own product branding. Follow the brand policy. |

The software distinction follows [AGPL sections 2, 4–6 and 13](https://www.gnu.org/licenses/agpl-3.0.en.html) and the [GNU output FAQ](https://www.gnu.org/licenses/gpl-faq.en.html#WhatCaseIsOutputGPL). Content terms follow the [CC BY-SA 4.0 deed and linked legal code](https://creativecommons.org/licenses/by-sa/4.0/). Font guidance follows the [SIL OFL FAQ](https://openfontlicense.org/ofl-faq/), especially document use and bundling. The exact licenses control; this table is a practical guide, not a new grant.

For example, a chart drawn from your own data is not automatically AGPL because a tool rendered it. A shared worksheet that adapts an included CC BY-SA template needs that template's attribution and share-alike treatment. A document containing a separately licensed photograph still needs the photograph's permission. Whether a particular combined output is an adaptation depends on what it incorporates; inspect those components before promising exclusive rights to a client.

A useful attribution record contains the component title, author, source URL/version, license, and changes. Keep it with the delivered artifact and include the actual font or upstream notices whenever those files are redistributed. Preserve prior-grant terms when using an earlier edition.
