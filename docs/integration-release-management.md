# Optional host integration release

`codex-host-hooks` is an independently downloaded integration outside the 31-plugin registry. `catalog/integrations.json` records its source scope, SemVer, release notes, compatibility and verified assets. The existing `codex-host-hooks/v0.1.0` release is the baseline. Its ZIP contains exactly the nine reviewed files under `integrations/codex-host-hooks/` at source commit `27e1d491d44b134f30fe68cda55029c9f2fab9cb`. This integration never installs or trusts hooks automatically.

For a future source change, the authoring agent first commits the reviewed integration files. The README's Download section must name the proposed version's exact tag and ZIP. The agent writes `catalog/integration-changes/codex-host-hooks.json` with `product_id`, full `source_commit`, sorted exact `changed_files`, `level` (`patch`, `minor` or `major`), and specific `summary`, `why`, `notes`, `compatibility`, `upgrade_guidance`, `validation` and `source_review`. If the source file set changes, `approved_source_files` must list every registered path. An unchanged integration needs no note or version increment.

The explicit `scripts/complete_update.py --publish` batch event invokes `release_manager.packs.complete(root, notes_dir)` before Site synchronization. It verifies a clean committed source scope, exact changed paths and note, then applies the SemVer rule. It refuses to push an unpublished source commit that changes files outside the registered integration folder. It builds a deterministic ZIP, `SHA256SUMS.txt` and `source-release-manifest.json` from the exact source commit. After a fast-forward push, the shared publisher prepares and byte-verifies a draft release, publishes it, and records the release in the integration ledger. The ledger and authored note are committed together, separately from the tagged source, so its source commit remains exact. Failed publication retains the prior ledger. A repeat against the same commit resumes or verifies existing assets. A ledger written or committed but not pushed is recovered only when it has the matching completion receipt and its pending commit contains precisely that ledger and note.

`release_manager.packs.history_products(root)` imports every GitHub release whose tag matches `codex-host-hooks/v<SemVer>`, resolves the exact tag commit, checks every asset's downloaded bytes against its GitHub SHA256, validates the ZIP against all files in the tagged integration tree, and cross-checks the manifest and checksum file. The highest fully verified stable release becomes the integration's current download in the unified history. The Site card must keep manual review, installation and trust instructions visible; a published archive is not native activation evidence.
