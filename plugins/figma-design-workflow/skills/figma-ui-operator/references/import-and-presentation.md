# Imported screens and stakeholder presentation

These are generalized lessons from an observed 2026-09-09 Stitch/Figma task. Historical project names, design contents, file keys, and private recordings are intentionally excluded. They do not establish current state or additional authorization.

## Inventory before arrangement

After a user or another task pastes screens, inventory names, root count, parent paths, dimensions, and editable children. Match accepted variants to the source manifest before moving anything. Do not infer “everything imported” from a populated canvas or import only the first three screens then claim the full set arrived. Keep older variants or flow maps if the user wants them; changing the presentation lead does not authorize deleting supporting work.

## Container bounds before spacing

A presentation row can visually overlap the next row even when child X/Y values are correct: its parent height, padding, auto-layout sizing, or clip-content setting may be wrong. Inspect those properties before shifting every child. Account for the tallest screen plus headings, callouts, and row padding. Check both overview and readable screen zoom after reparenting. Recheck imported screen widths and actual hierarchy; visual overlap does not prove nesting.

Keep headings and annotations outside phone-screen content unless they are part of the UI design. For review presentations, use short callouts beside actual elements with a clear pointer/anchor. Put dense flow maps in a supporting area when that is the user's chosen hierarchy. The useful amount of annotation depends on the audience; do not impose an old project's exact count or layout universally.

## Input and API failures

If an API quota is reached, do not spend more calls probing the same operation. Continue through the already authorized computer-control route, reacquiring selection and mode. If the user specifically chose UI operation, do not run bulk plugin code merely to speed up arrangement.

A stalled source Copy step is distinct from a Figma layout error. Reconcile the copy/paste manifest before modifying containers. After any human assistance, observe actual state instead of continuing a cached action sequence. Do not compete with another task operating the same foreground apps.

## Closeout anchors

Use a small map of the actual rendered views. Example roles, not observed facts: A1 overview of imported roots; A2 one screen at reading zoom; A3 Layers hierarchy and editable text; A4 the tallest row and the following row boundary; A5 a key callout. Record real source/viewport, location, observed fact, intended action, and final result for each. Report unsynced or untested behavior explicitly.
