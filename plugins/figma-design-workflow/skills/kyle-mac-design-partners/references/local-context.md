# Receiving-host context: synthetic verification template

This replaces the original private author-machine snapshot. No app, account, browser profile, project path, mounted volume or remote-control access is asserted for the receiving host.

## Verify capabilities before use

- Discover Claude Desktop/Code/Design availability and current visible navigation, model and account plan. A listed surface does not prove generation, workspace access, export or remaining quota.
- Use the browser requested by the user; inspect signed-in Stitch only within task authorization. Never persist tab IDs, internal frames, account identifiers or copied profile/cookies.
- Discover the real Figma app/window and accessible files. Connector and desktop access can differ. Preserve existing unsent work and attachments.

## Files and remote hosts

- Resolve the actual project owner and explicitly selected scratch workspace. Synthetic example: `project/design-review/` for evidence and `project/scratch-mockup/` for isolated files. These are placeholders, not an existing project.
- Inspect actual mounts and symlinks before using external storage. A file-sharing mount does not prove remote desktop access or ability to run another host's apps.
- Follow recipient storage conventions. Verify the browser's export destination before moving needed artifacts into the project; do not relocate Downloads.

## Pressure and recovery

Use an available receiving-host pressure diagnostic before substantial parallel/resource-heavy work. Warnings remain advisory; preserve unrelated apps, user sessions, mounted drives and other tasks. Cleanup requires proof of ownership and staleness; low CPU/age alone is insufficient. If a host locks or a service is unavailable, preserve evidence and continue independent authorized work; retry the exact blocked inspection after recovery. Consult the recipient's applicable operating protocol when available.
