# Stitch Design Partner

Use [Workbench](../stitch-workbench/SKILL.md) for browser access and draft preservation. Then:

1. Build a compact brief from the existing work: audience and task, content hierarchy, actual source assets, screen size, style anchors, constraints, and the specific decision needed. Label unknowns. Use [the brief template](../stitch-workbench/references/brief-and-handoff.md) only as needed.
2. State what must survive: identity, navigation destinations, meaningful content, accepted layout decisions, accessibility behavior, and any project-specific icon or file-format rules.
3. For an unresolved direction, request two or three meaningfully different approaches and concise rationale. Compare hierarchy, density, image role, navigation, and reading path. Do not generate an entire website for each option by default.
4. Select a direction using the audience’s task and the user’s known taste. A recruiter needs fast role and evidence discovery; a service buyer needs offer, fit, proof, and contact; an event visitor needs atmosphere, details, accessibility, and booking. Reuse design principles across these audiences without silently merging their identities or links.
5. Generate the smallest representative screen or component that can test the decision. Supply actual imagery where available. Request distinct small-screen behavior and meaningful empty/error/success states where applicable.
6. Inspect the actual result. Make an anchor map before visual claims. Give scoped revision prompts with an anchor, observed problem, intended change, and preserved features. A compliment or “make it premium” is not an actionable critique.
7. Stop ideation once a direction solves the decision. Hand the selected result to [export](../stitch-export-handoff/SKILL.md) and implementation; do not repeatedly replace accepted work with a new style.

## Prompt shape

“Design [bounded output] for [audience performing task]. Prioritize [content and action]. Use [provided sources] and preserve [accepted decisions]. At [viewport], [layout/behavior]. The component must include [states]. Explore [specific choice], avoiding [project-specific exclusions]. Deliver [view or export needed].”

Let one authoritative theme/design system own colors and typography. If the project has an attached theme, do not inject conflicting tokens into every prompt. Use [Design system](../stitch-design-system/SKILL.md) when ownership is unclear.

## Consultant handoff

Claude, Figma, or another design partner may provide a critique or mockup when it helps one decision. Use an available personal app skill for access and plan limits. Pass a compact brief and selected references, then record which suggestions were accepted and why. AI consensus is not user research, and a generated rationale is not evidence of measured improvement.

Deliver one selected direction, its artifact, and the next implementation action.
