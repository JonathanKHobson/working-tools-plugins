# Stitch Library Evidence

Do not harvest a library just because this skill is installed. Use it when the user asks to recover past work. Follow [Workbench](../stitch-workbench/SKILL.md), preserving drafts and existing projects.

1. Start with a named project, client, topic, date range, or source lead. Search/browse the current UI and inspect likely candidates. Bound the search; report absence or uncertainty honestly.
2. Record provenance before storytelling: project/screen name and stable link, visible date if available, who authored it, source/context that connects it to the user, and its actual stage. If ownership or timing is uncertain, mark it unknown rather than inferring from account access.
3. Prefer original exports or clear screenshots of the real artifact. Save an untouched source, then make readable crops/annotations separately. Capture enough context to identify the version. Redact unrelated private information from public derivatives while preserving private originals.
4. Classify every visual: original historical artifact; historical iteration; newly reconstructed concept; newly designed proposal; generated presentation artwork; or implemented result. A current reconstruction cannot stand in for an original screenshot without a nearby label.
5. Assemble a concise story: problem and constraints, the user’s actual role, action/decision, visible artifact, and supported result or open question. Lead with the result when it is substantiated. Otherwise lead with the problem and demonstrated contribution. Do not invent metrics, testimonials, clients, dates, launches, or outcomes.
6. For before/after, verify chronology and comparable task/scope. If only one side is evidenced, label the comparison “original / proposed” or describe the actual stages. A visual revision is not proof of better business or usability outcomes.
7. Turn dense prose into evidence-led sections: one clear claim, one meaningful screenshot or comparison, a brief caption connecting the decision to the audience’s task, then optional detail. Decorative imagery cannot supply missing proof.
8. Promote only reviewed, attributable artifacts into the active case-study library. Keep source leads and unsupported candidates separate. A generated screen or consultant recommendation is not user research.

## Evidence record

Use the evidence fields in [the shared template](../stitch-workbench/references/brief-and-handoff.md). Keep raw URLs, private correspondence, invoices, client names, and unredacted screenshots in the user’s private evidence workspace, never in this plugin or an automatic public export.

Deliver selected candidates with support/gaps and usable visual files. If evidence is missing, state the gap; a labeled reconstruction is a separate new deliverable only when it serves the user’s request.
