# Local MCP method admission

The complete admitted two-method support tree came from MCP Workbench 0.1.0. Its generated manifest explicitly identifies “first-party local Codex skills” and names both canonical methods. The original roots still exist, and 26 of 28 historical source hashes match the current roots; the two head files subsequently evolved. The historically admitted version is preserved here, rather than silently importing later private additions. `docs/first-party-lineage.json` records the bundle manifest/README and canonical file identities without personal locators. Current owner authorization licenses the original admitted methods and support under MIT. No third-party source grant is inferred from the old Private label.


The preserved methods remain operational references. Host-specific names, absolute paths and private incident pointers were generalized. The legacy Codex exposure incident in the debugging method was reduced to its reusable three-layer diagnostic procedure; it is not a claim that the historical helper commands exist on another machine. External skill links were changed to installed-plugin route names, and source-local relative references resolve within this package. No live client configuration, private corpus, credentials, or runtime database was copied. Sample config snippets contain placeholders only.

The reviewed `master-security-toolkit:agent-artifact-scanning` wrapper scanned the source builder tree (26 files, 0 active findings), debugging skill (1 file, 0 active findings), staged library (27 scanner-eligible files, 0 active findings), active route (1 file, 0 active findings), and staged docs (12 scanner-eligible files, 0 active findings). The one JSONL fixture is outside the scanner file set; its single synthetic retrieval case was read manually as data. These deterministic results are a static screen, not runtime or rights clearance. Manual data-to-execution review found these meaningful paths:

- `assets/python-local-mcp/build_index.py` reads operator-selected JSON and writes/replaces an SQLite index; its temporary path cleanup is limited to the selected index path. `mcp_server.py` starts a stdio server only when executed as the main program. Both are templates requiring project-specific input and output review.
- `scripts/check_local_mcp.py` and `scripts/smoke_claude_profile.py` launch operator-selected server commands. Their check/smoke names do not make them passive. They must not be invoked during package admission.
- `scripts/compare_client_mcp_configs.py`, `check_claude_mcp_fleet.py`, and shared fleet parsing read selected or default client configs/logs; `generate_claude_fleet_report.py` also writes a selected report path. `scripts/clean_external_python_artifacts.sh` deletes matching AppleDouble artifacts beneath its argument. Review path scope before any use.
- Config snippets and printed commands can become executable if copied into a shell or live client config. Treat placeholder values as data; serialize real argv for the chosen client and review the merged config before activation. No package import automatically writes config or launches a fleet.

There is no package scheduler, hook or automatic context re-injection in the imported methods. Static review did not exercise candidate code, install dependencies, start MCP processes, change client config, or test runtime network behavior. Keep helper scripts inspect-only by default. A project that needs one should review its exact source, command, inputs, output paths and host permissions, then perform an isolated project-specific test. Source examples cannot override current user authorization or the active host's tool requirements.
