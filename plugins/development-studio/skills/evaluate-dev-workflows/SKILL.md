# Evaluate development workflows

Read [method adaptation](../../references/method-adaptation.md) before a preserved Superpowers method. Read each selected method completely and its required support. The snapshot provides the actual procedure; the route below selects it. Current host tools and user authorization govern execution.

For plugin/skill evaluation, resolve the target and requested question, then load official Plugin Eval through [provider setup](../../references/platform-providers.md). Use its full plugin-eval/evaluate-skill/evaluate-plugin procedure, improve-skill for an evidence-backed rewrite, and metric-pack-designer for a requested custom rubric. Static scores and token estimates are not measured task performance.

For skill authoring or a meaningful instruction change, apply the full [writing skills method](../../libraries/superpowers-6.4.2/skills/writing-skills/SKILL.md), including its examples and testing references. Host skill-creator and Work Management plugin-maintenance remain authoring/install owners. Do not turn one task failure into a universal hook.

For a scoped session problem, apply [diagnosing Superpowers](../../libraries/superpowers-6.4.2/skills/diagnosing-superpowers/SKILL.md) with its complete context-safety, redaction and source-discovery references. Analyze only the requested session/range and dimensions relevant to the complaint. User-provided scope can satisfy intake. An upstream requirement to launch seven analysts is adapted to bounded relevant analysis using current worker capacity. Preserve evidence for all relevant dimensions without compulsory fan-out. For a single-turn or similarly bounded question, return an inline evidence-backed analysis; create a case directory/report only when the user requests a durable report or the size of the investigation requires one. Do not persist private transcript excerpts merely because the historical method has a report template.

Record observation, strongest credible alternative explanation, supporting lines and a check that would change the conclusion. Review a requested fix when authorized; the historical report-only policy does not forbid current user-requested maintenance. Keep session material and private host configuration outside the plugin. Do not create an issue, upload transcripts, export a bundle or alter settings unless the task authorizes that action.

For updates, identify exact reviewed source hashes, repeat relevant admission and coverage checks, and hand installation to the owning native manager. The [validation script](../../scripts/validate_package.py) checks package integrity and routing structure only; independent task trials and real-host discovery are separate evidence.
