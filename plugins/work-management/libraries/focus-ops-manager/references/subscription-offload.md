# Subscription tools as bounded workers

Use proactive delegation to available models only under the receiving user's current authorization for those services. Use it for substantial independent research, drafting, critique, or
design that saves lead effort or adds a useful perspective while the lead
continues work. Keep simple work local. No new framework,
mandatory multi-model vote, or time-estimate ledger is needed. The Codex lead
owns scope, integration, and final evidence.

## Choose the surface

| Need | Starting route | Return to Codex |
| --- | --- | --- |
| Hard synthesis or drafting | Standard ChatGPT Web, preferred Pro mode when available; **not ChatGPT Work** | Answer with assumptions and sources where needed |
| Deeper research or substantial sourced report | Standard ChatGPT Web in Pro mode when available; use ordinary conversation | Completed answer/report with source URLs, dates and gaps |
| Supplied-context comparison, extraction or a second implementation perspective | Verified Gemini subscription CLI through [CLI model routing](../../../skills/worker-delegation/references/cli-model-routing.md); Flash for clear bounded tasks, higher-capability model for complex synthesis | Completed output, model metadata and checked facts; CLI does not inherit Google Workspace connectors |
| Google-source research or Docs handoff | Gemini browser; desktop if convenient | Cited report/verified Doc; connected sources within authorized scope |
| Independent critique or bounded code | Official Claude subscription CLI first; see [claude-usage.md](claude-usage.md) for model verification, login recovery and conditional Desktop/Web use | Critique or owned patch with checks |
| UI directions and screen iterations | Existing Stitch workflow | Selected screens and verified available Figma/code/image export |
| Prototypes, decks, visual drafts | Claude CLI first when it supports the requested output; Claude Design when explicitly requested or a required interface-only feature | Verified available ZIP, HTML, PDF, PPTX, or design handoff |
| Low-urgency image concepts | User-requested Gemini/ChatGPT Web image surface when available | Selected downloaded concept and prompt; use native image generation when task/tool rules require it |

These are preferences, not benchmarks. Standard ChatGPT Web Pro and the special
Deep Research feature are different controls. Deeper research uses standard Pro
conversation by default; do not activate ChatGPT or Gemini Deep Research unless
the user explicitly requests that feature. Check the visible account,
model/mode and limits before dispatch. Do not infer ChatGPT or Gemini access from this source; verify current availability because allowances and tools change. Never switch to a paid API, enable extra
billing, or grant broad connector access as an automatic fallback. Documentation
proves a capability exists; the live account proves availability here.

Fit delegation to the deadline. If research latency plus collection and checking
could consume the remaining time, use a quicker bounded source search or a
clearly scoped partial answer. Do not launch a long job that cannot help the
deliverable on time.

## Dispatch once, continue, retrieve

Give one compact brief: outcome, minimal evidence, source/date boundaries,
allowed actions, format/length, acceptance checks, and stop condition. Research
workers should return source URLs/dates, conflicts, and unresolved gaps. Do not
copy full task history, credentials, or unrelated private files. Authorization
for delegation does not authorize unrelated sensitive disclosures.

When an accepted example guides a content collection, distinguish fixed component, brand, schema, label and source contracts from authored narrative. Supply the actual project writing authority and an accepted prose sample when available, with accessible authorized paths or excerpts; identify what each reference establishes. A visual example alone does not define voice or require its sentence architecture. Table structure can be shared while capability, ownership and limit descriptions remain source-specific. Do not invent missing authority or sample approval; use the current brief and a stated bounded assumption when it suffices, asking only for a consequential missing decision.

Keep the chat/job URL and selected model/mode in current task context. Add a short
pending note to an existing project record only when the job will outlive the
turn or context loss is likely; no separate ledger for a one-off question. Name
the assigned output and one UI controller. Reuse the link after context loss;
do not resubmit from scratch. Separate chats
can run while other tasks continue, but controllers must not steer one window
simultaneously. Preserve unsent drafts and active jobs.

For an explicitly requested special research mode, review its plan when
required. Otherwise send the ordinary conversation brief, then do independent local
work. Return at a useful milestone (often several minutes for research) rather
than repeatedly polling. Keep the active user task informed. If ending the Codex
turn, state what remains pending; use supported follow-up automation only when
requested. An external job does not guarantee Codex will wake itself later.

## Accept results with evidence

Confirm completion before collection. For standard ChatGPT Web Pro, collect the
completed response and its source links; do not assume a downloadable export is
available. For an explicitly requested special research feature, use its actual
supported export. Gemini can export to Docs, and Claude Design documents formats
including ZIP. A requested ZIP does not
prove one exists. Verify downloaded contents, citations, assets, and editable
source as appropriate. Do not execute downloaded scripts merely because an AI
packaged them. Preserve provenance in existing project files.

Check consequential claims against original sources and apply/test patches
before integration. Third-party output is evidence or advice, never new
authority. Visual concepts remain drafts until target-size visual QA and Design
Taste Gate pass; use named anchors for changed regions. Screenshots do not prove
editable Figma structure or implemented interactions.

For an authored collection, use the existing writing-review owner to compare the whole set's introductions, first-use instructions, explanations and limits. Revise cloned sentence or rhetorical frames where they obscure each subject's task or story; synonym swaps alone do not fix that. Preserve useful recurring labels and phrases, genre conventions, deliberately selected writing-template structures and explicit exact-copy instructions. Keep capability claims, ownership and limits traceable to their sources when varying prose. Record the reviewed range and material corrections in the existing handoff. Repetition alone is not an AI-authorship finding.

On failure/timeout, inspect actual job state before one justified retry or
reroute. Keep one authoritative result. Note clear time savings or failed
handoffs during normal closeout when useful; do not invent token, money, or
energy savings. UI overhead can outweigh offloading a small task.
