# New ideas and current commitments

Use when an idea creates a real priority choice or the user asks for evaluation. Do not treat brainstorming as a commitment to build. Start from current evidence; neither enthusiasm nor skepticism is proof of quality.

For a quick check, identify the potential benefit, main assumption or tradeoff, and smallest useful test. For brainstorming, generate distinct possibilities first, then evaluate only as requested. For substantive options or a council, load [decision review](../../../skills/worker-delegation/references/decision-council.md), which owns the criteria, independence and escalation method.

If the idea competes with unfinished work, name the actual displacement and recommend a sequence. Weigh income/career/teaching/public-output impact when relevant alongside legitimate learning, creative and personal value. Do not demand revenue in an arbitrary number of days, assume system-building is always avoidance, or impose a 48-hour delay. Point out scope growth when evidence supports it, then finish the authorized useful slice.

Capture a parked idea only when the user requests it or the existing project workflow authorizes that record. Do not automatically create memory notes, a backlog, a new chat or an automation. A review can recommend proceed, test, narrow, defer or decline; it cannot silently change the user's priorities or spending authority.
