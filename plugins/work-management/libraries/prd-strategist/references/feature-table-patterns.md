# Feature Table Patterns

Use these patterns when the output benefits from structured tables, especially in PRDs, one-pagers, delivery packs, or formal documents.

## Audience Map

Headers:

- Audience
- What They Need to See
- What Builds Trust

Use when defining primary segments, buyers, admins, or internal operators.

## Feature Priority Table

Headers:

- Feature
- Priority
- Why It Matters

Priority meanings:

- `P0`: must ship
- `P1`: high value next
- `P2`: useful later

Use when the user needs a clear MVP boundary.

## Feature Priority Table With Notes

Headers:

- Feature
- Priority
- Why It Matters
- Notes

Use when tradeoffs, dependencies, or open questions need to sit next to the feature list.

## Slice Map

Headers:

- Slice
- MVP
- Expand
- Scale

Use when delivery is organized by vertical user outcome instead of component or team.

Example slices:

- account setup
- primary task completion
- collaboration
- reporting
- admin controls

## RACI Matrix

Headers:

- Workstream or Decision
- Responsible
- Accountable
- Consulted
- Informed

Use for ownership-heavy projects, cross-functional launches, or stakeholder confusion.

## Traceability Matrix

Headers:

- Requirement ID
- Acceptance Criteria
- Metric
- Slice
- Phase

Use when the user needs auditability, QA traceability, or stronger delivery governance.

## Risk Matrix

Headers:

- Risk ID
- Description
- Likelihood
- Impact
- Score
- Mitigation
- Owner
- Watch Metric

Use for rollout, compliance, platform migrations, or any feature with meaningful failure cost.

## Open Questions List

Organize by category:

- Product
- Technical
- Design
- Data
- Legal or compliance
- Operations

Within each category, number the unresolved questions and add owner plus closure path when known.

## Headline or Positioning Options

Headers:

- Option
- Why It Works

Use when the user wants help comparing names, positioning statements, or one-line pitches inside the product-planning workflow.
