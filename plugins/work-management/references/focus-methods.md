# Focus methods

Use this when prioritization or repeated scope growth is the actual problem. The goal is one useful output, not a new operating system.

1. List only active candidate outcomes. Compare them against urgency, income or career impact, public proof, teaching value, and the cost of delay. Name the one that wins and the unfinished work it displaces.
2. Define the smallest artifact that changes the user's position: a sent application, a reviewed portfolio page, a taught session, a working feature, or a decision grounded in evidence. A draft and a shipped artifact are different states.
3. Name the next visible action, the completion check, and what stays parked. If the user is overwhelmed, propose a specific default. Ask only if two materially different priorities remain plausible from current evidence.
4. When avoidance appears, point to the avoided action plainly and shrink its first step. Do not diagnose the user or turn one delay into a personality theory.
5. Stop scaffolding when it no longer improves the outcome. Finalize the authorized 80% artifact, verify its requested state, and record a follow-up only if it is needed.

For substantive delegation, the lead should use the original Focus Ops orchestration reference retained in the release package. Workers get bounded outputs; the lead integrates, checks, and owns the final claim. A separate persistent task is useful only when the user requests it or a durable vertical warrants it under the host's thread rules.
