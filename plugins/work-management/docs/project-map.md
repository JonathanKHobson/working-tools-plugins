# Project map: work-management

- `.codex-plugin/plugin.json`: identity and native discovery.
- `skills/`: independently selected runtime entrypoints and their narrow supporting material.
- `skills/project-structure/`: owning-project boundaries and recipient-selected storage. Resolve symlinks and verify the intended mounted volume before large downloads/renders; limit internal storage and preserve references during any relocation.
- `references/operations/download-hosting.md`: forward-looking Sites download destination and link-verification rule, routed from project structure, tool workflow and shared-site publication. Existing downloads remain in place without an explicit migration request.
- `skills/evidence-review/`: manual checkpoint and claim cards. Domain validation, CLI and private immutable storage are separate helpers; sources/cards stay in the owning project. Verify with `python3 -B tests/test_evidence_review.py -v`; no added hook or MCP.
- `skills/evidence-review/references/feedback-to-method-review.md`: bounded learning closeout for authorized current-task signals; source-to-owner dispositions and validation/rollback live in project records. Existing prompt hook reminds only; no new capture hook, history scanner or automatic skill/memory mutation.
- `skills/evidence-review/references/corpus-and-publication-handoff.md`: manual known-backlog inventory, Obsidian pointer notes, career relevance, separate rights/history states and authorized friend/collaborator digests or useful hosted handoffs with recipient-access/delivery proof. Private contacts and histories stay project-owned. `skills/work-handoff/references/interface-learning.md` owns selected conditional app lessons. Neither adds capture hooks, contacts, history stores or schedulers to this plugin.
- `skills/parallel-work/`: Codex-only opt-in claim board guidance and state helper; upstream MIT runtime provenance is in `docs/parallel-work-provenance.md`.
- `scripts/` and `optional-hooks/`: adapted Coordinator project lifecycle, manual Doctor, marker-only SessionStart and own-claim Stop guard. The distributed hooks are registered in the plugin manifests and still require the recipient's native enable/trust/settings step. The author's host-bound `hooks/` overlay is preserved outside the distributable payload.
- `scripts/codex_work_start.py`: opt-in UserPromptSubmit reminder for a receiving user's explicitly confirmed native-goal, project-structure, plugin and worker preferences. Emits bounded context only; no goal-storage writes, transcript reads or worker launches. Native goal tools and current user/tool rules own execution. Check with `python3 -m unittest discover -s tests -v`; host hook adoption requires review and trust.
- `skills/find-skills/`: task-triggered gap discovery and security-gated admission into existing owners; complete upstream attribution is in its provenance reference and inactive `libraries/find-skills/` snapshot. No installer, hook or scheduler is added.
- `references/` or `libraries/` where present: conditional shared/deep resources; never load everything by default.
- `libraries/focus-ops-manager/references/mcp-registry.md`: recipient-ready activation and inventory method. The author's populated `mcp-registry.author-private.md` is a canonical-only private overlay and is excluded from distribution.
- `README.md`: ownership, private-source boundaries and install workflow.
- `docs/`: source-to-target and maintenance notes. Work Management owns the shared `skill-plugin-map.md`.
