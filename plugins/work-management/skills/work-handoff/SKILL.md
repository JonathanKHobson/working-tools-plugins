# Work handoff

When orientation helps, briefly name this skill’s outcome, needed input and expected result, then proceed. Broader help uses the [plugin introduction](../../README.md); skip maintainer notes unless needed.


Prepare or resume a bounded handoff with source ownership, current state, decisions, next action and verification evidence.

## Complete procedures to load

Select by the triggers below. Read the complete chosen procedure and its required support; skip unrelated variants. These links preserve the full methods.

- [Full phase handoff](../../references/operations/phase-handoff.md) — For a work handoff or resumption; state, decisions and next evidence.
- [Full ship-state protocol](../../references/operations/ship-log.md) — When recording a delivered release; distinguish preparation from verified delivery.
- [Delegation handoff contract](../../libraries/focus-ops-manager/references/subscription-offload.md) — When handing work to a subscription worker; bounded dispatch and checked return.

## Workflow

1. Identify the owning checkout/artifact and the recipient’s permitted scope. Resolve current state from evidence, not a stale status note.
2. Read the complete phase-handoff protocol. Include the smallest sufficient source pointers, accepted decisions, open problems, next action and proof target.
3. Preserve prepared/sent/submitted/published distinctions. Send to another task only when the user authorizes that coordination.

## Deliver and verify

For visuals, decks, video or interactive exports that someone will revise, use [editability handoff](references/editability-handoff.md) to state which parts remain editable, where their source lives, and what was actually checked.

For a reusable kit, template family or system composed across studios, use [reusable package handoff](references/reusable-package-handoff.md). Bind selected sources and test a recipient task in the actual delivery copy, with type-specific checks and honest verification limits.

Produce the handoff at the requested stage; if authorized to send, verify dispatch separately from completion. Do not create extra trackers by default.

## Example boundary

Good: “Source fixed, tests passed; hosted page unverified; verify this route.” Bad: “All done” because a draft exists.

For a source-supported portfolio/content or authorized friend/collaborator handoff, read [corpus and publication handoff](../evidence-review/references/corpus-and-publication-handoff.md) for relevant evidence, digest versus hosted artifact selection and recipient-access/delivery proof. For a selected reusable browser/app interaction correction, read [interface learning](references/interface-learning.md); current controls and state must be rechecked before reuse.

For setup or a cutover waiting on a genuinely human-only action, read [human-only setup](references/human-only-setup.md) to prepare the next action and its verification while continuing independent work.

## Shareable web artifacts

When the user requests a shareable or Sites artifact, read [the shared-site procedure](references/shareables-site.md). If they selected or explicitly configured an existing maintained site, add a page there and update its homepage; otherwise establish the intended destination from the current task. Do not register a separate site without that scope.
