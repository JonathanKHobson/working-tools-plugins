# Receiving host map

This is an explicit recipient binding template, not verified access or live synchronization. Configure only hosts/accounts the user authorized.

| Role | Account source root | Access from source host | Recipient value |
| --- | --- | --- | --- |
| Source production account | source account skill/plugin roots | local filesystem or authorized share | Unconfigured |
| Second local account | destination account roots and reviewed mirror | local filesystem where authorized | Unconfigured |
| Remote work/design account | remote account roots | verified mounted home share or chosen transport | Unconfigured |

Verify hardware identity and mounts; network service names do not establish the hardware. Remote paths are not local paths. A mounted SMB share enables file operations, not remote command execution or control of a running task. Preserve user-owned screen-sharing sessions. SSH failure does not establish that an authorized mounted share is unavailable.

Record source and destination complete capability sets, methods, native format, ownership and validation evidence. Inventory observations are not quality endorsements or tool availability. Preserve format-specific specialists on their current host; do not replace them with a thinner shared workflow.

For a local-account continuation, declare a recipient-owned reviewed metadata bridge if wanted. A file bridge is not a shared cloud conversation. No recurring cross-computer synchronization is installed by this package. Leave bindings unconfigured until the receiving user supplies and verifies them.
