# Cross-Codex Workflow Exchange

Read `references/host-map.md` when selecting the host or recovering an access
path. Read `references/shared-working-preferences.md` when cross-account context
materially affects a decision. Do not load either for unrelated self-contained
work. This is a reviewed handoff snapshot, not automatic live synchronization.

1. Identify the user-requested deliverable and owning project/host. Inspect the
   current filesystem and applicable instructions before trusting historical
   paths. Existing SMB mounts may provide file access even when SSH fails.
2. Compare full relevant skill folders, scripts, templates and references. For
   plugins, distinguish maintained source, installed cache, and actual activation;
   do not edit a cache as if it were the maintained source. Count an inventory as
   installed files, not proof that an active conversation loaded them.
3. Preserve preimages and hashes. Install missing skills; leave identical copies
   alone. Merge differences by applicability and evidence, never timestamps.
   Keep format-specific expertise in its specialist; share only cross-format
   methods. Retain host-specific tool and storage rules on their owning host.
4. Check for current changes before writing and verify written bytes afterward.
   Never have two writers modify the same skill or project. Respect existing
   symlinks. Do not use destructive mirror/delete synchronization.
5. Validate entrypoints and relative resources, then exercise any imported or
   edited helper when its behavior matters. Report file installation separately
   from plugin registration and live invocation. Start a fresh task to refresh
   loaded instructions; do not interrupt another active task just for pickup.
6. Keep durable preferences and handoff metadata concise. Do not copy credentials,
   authentication, sessions, SQLite databases, or writable memory stores between
   accounts. Current approvals and live project state stay in their owning
   project. Record a reviewed memory update only when requested and allowed.

For optimization, measure what is actually observable: files, duplicate package
hashes, entrypoint length, validations, or delivered results. Do not infer task
counts, usage, money, compute, or time savings from a skill inventory. Use current
account tools for usage if requested and available. Do not persist exact-model
availability or subscription assumptions as permanent capabilities.
