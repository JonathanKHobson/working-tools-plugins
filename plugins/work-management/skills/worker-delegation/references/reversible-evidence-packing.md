# Reversible evidence packing for a worker

Use this only when a large local tool result or log would crowd out a bounded worker brief. If the worker needs to edit or review source code, give the exact file path and relevant range instead. Small or already dense material passes through unchanged.

1. Keep the complete original in the owning project or current task. Record its path, source command or tool, exit status, timestamp, and SHA-256. Do not make a new shared memory store for a one-off handoff.
2. Make a separate short view of the newest result. For repeated rows, retain the first and last examples, distinct categories, errors, failures, warnings, numerical outliers, and sudden changes. Preserve exact diagnostic lines, stack frames, IDs, counts, units, and source line or row anchors that the assigned decision may need. Never abbreviate user instructions, permissions, security findings, code under review, or the facts that would establish completion.
3. Mark every omitted span with its original line or row range and count. Give the worker the local original path and hash when that worker can read it. Otherwise provide only authorized excerpts and state that the rest is unavailable; do not imply a remote worker can retrieve a local file.
4. Before dispatch, answer the assigned question using the short view and check it against the original, including one edge or failure case. If the needed fact is missing, provide the original slice. If the short view is no shorter or fidelity is uncertain, pass the original evidence through. Record input and short-view byte or token counts only when actually measured.
5. Ask the worker to cite the original anchors it used and to name any requested slice it could not inspect. Judge its result against the original evidence before using it for a decision or completion claim.

This is a manual handoff procedure, adapted from Headroom's selective retention, protected recent input, reversible retrieval, and pass-through gates. It does not require Headroom's proxy, model, MCP, hooks, telemetry or session mining, and it makes no claim about token savings or answer accuracy.
