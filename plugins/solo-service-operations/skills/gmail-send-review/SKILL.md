# Gmail send review

Finish the user's requested email action. If they authorized sending, complete the reviews below and send without asking for an additional approval. If they requested a draft, approval, or an exact-text send, preserve that instruction. An exact-text send gets a check without silently rewriting their words. This skill never supplies missing permission to send.

For native Gmail scheduling, personalized batches or recovery after a browser scheduling error, read [scheduling and batch verification](references/scheduling-and-batches.md). A request to schedule authorizes that schedule, not an immediate send.

1. Use the recipient's current voice/style instructions and relevant authorized personal writing samples. Reuse guidance already in this chat. Search only the most relevant connected source; when no suitable references exist, record `unavailable` and continue honestly. Do not store retrieved writing samples on disk. A separately installed, licensed voice tool may assist, but no proprietary Write Like Me body is bundled or required.
2. Review the exact final prose for the reader and purpose: preserve facts, uncertainty, commitments and authentic quoted material; remove unsupported claims and make the ask clear. Use the receiving environment's approved editorial method when available. Reuse a completed review only while content and audience are unchanged.
3. For consequential, persuasive, sensitive or conflict messages, apply an appropriate communication review. Research/design follow-ups should connect evidence, implication and requested next action without inflating findings. The gate's `communication-crafter` and `ux-research-follow-up` audience tags identify review scope; they do not install or require a proprietary skill. Routine confirmations use `routine`. Deep source/style audits are conditional. Edit only authored prose and preserve attachments and genuine forwarded material.
4. Verify final recipients, sender, subject, authored content, reply target, and attachments. For a registered Gmail connector send, record the review for the exact final tool arguments, then call that send tool. For browser actions, record an honest manual review and provider readback under the scheduling reference; do not invent a connector gate receipt. Review receipts attest the agent's work; the helper cannot judge prose or establish user authorization on its own.

Use no em dashes in newly authored outgoing subject or body. The gate checks known connector `send_email` and `forward_emails` subject/text MIME fields before creating a receipt and again before the send. It decodes RFC 2047 subject encoding, HTML entities, and base64url text parts; it checks reader-visible `alt`, `title`, and `aria-label` text. Ambiguous text parts with both direct and encoded bodies are rejected. It leaves quoted history, forwarded original messages, and attachments intact. For an exact-text request containing an em dash, tell the user about the conflict; do not silently change their text or send it unchanged. The check covers only the registered connector payload and recognizable quoted markup/text, so review the rendered complete message as well. The quote exclusion assumes that `blockquote`, `gmail_quote`, plain `>` lines, and forwarded-message boundaries contain authentic source material; the helper cannot prove provenance. Manually check any newly authored blockquote or quote-like section before send.

## Replies: prevent duplicated thread history

For ordinary replies, keep the new body concise and preserve the actual conversation through reply headers. Do not paste the full thread into the authored body or depend on Gmail's three-dot trimming to hide it. Preserve intentional quoted excerpts, inline answers, forwarded content, and attachments when the task needs them.

The connector's `send_email` and `create_draft` with `reply_message_id` were observed to append the prior message as flattened quoted text, including nested history, after the supplied body. The direct send path therefore transmits content not covered by a payload-only review. The local gate blocks that direct reply path; this is agent repair, not another permission request.

Use the following route for connector replies:

1. Create an unsent reply draft with the correct `reply_message_id`, subject, explicit recipients and sender. Read its underlying message to inspect the complete generated MIME body and reply headers.
2. Use `update_draft` to replace `payload` with the intended authored MIME tree and any intentional quotes/attachments. It does not append quotes. Omit reply context and other unchanged fields to preserve them. Supplying `payload` replaces attachments too, so carry every required attachment/inline part forward; never silently drop them.
3. Re-read the updated message using its newly returned message ID. Verify the entire body, not merely the prefix before `gmail_quote`. Check that thread ID, `In-Reply-To`, `References`, subject, sender and recipients still match the intended reply. No long copied history should remain unless explicitly needed. A draft's message ID may change while its draft ID remains stable.
4. For an authorized send, review that exact saved draft, record the `send_draft` receipt with `--draft-verified` and the reviewed draft snapshot described below, then send it without intervening edits. Respect the tool's authorization requirements and any user draft-only hold. If unavailable, use a native Gmail reply composer with complete body review; do not omit reply linkage and pretend a new message is a reply.
5. Verify Sent readback includes the correct linkage and the complete intended body without newly appended history. Do not trim away unreviewed suffixes while asserting the send matched. If the user specifically needs quoted history retained and collapsed, preserve its HTML structure and inspect the rendered Gmail result; class names alone do not prove collapse across recipients' clients.

This keeps prior messages in the conversation, without embedding another copy in each new message. Sender-side screenshots do not prove recipient rendering. Do not promise a particular three-dot treatment in every email client or send test mail to others without authorization. Already delivered mail cannot be repaired in a recipient's inbox by editing the local record.

## Record the completed review

Run `python3` (Python3.9+ on a POSIX host) with this skill's `scripts/gate.py review`. Pass `--session` using the current `CODEX_THREAD_ID`/session ID (or the exact session ID supplied by the hook), `--tool` using the actual Gmail tool name, `--voice matched|user-supplied|unavailable`, `--audience routine|communication-crafter|ux-research-follow-up`, `--authorization send`, and `--skills-reviewed`. Feed the exact final tool argument object to stdin as JSON. Prefer a quoted heredoc or a subprocess stdin pipe; do not interpolate email text into shell code. No content or recipients are saved by the helper: it stores only a hash and review metadata.

A completed receipt lasts 30 minutes in this chat. Changed content, recipients, sender, attachments, subject, or reply target require a new receipt; revising the draft after review invalidates its fingerprint automatically. Reading skills once is enough while they remain in context, but review the actual revised message. An expired receipt can be renewed without repeating unchanged editorial work. The hook's normal return preserves the user's existing tool approval policy.

For `gmail_send_draft`, read the current saved draft in full, verify the draft ID and underlying message, complete any edits with `update_draft`, and re-read it before recording with `--draft-verified`. The review CLI requires stdin JSON shaped as `{"tool_input":{"draft_id":"..."},"reviewed_draft":{"draft_id":"...","subject":"...","payload":{"mime_type":"text/plain","body":{"content":"..."}}}}`; use the actual complete saved MIME tree, including all text parts and attachments. The `reviewed_draft` is an agent-supplied snapshot of the saved draft, with matching ID, subject and MIME payload; the CLI checks its authored text for em dashes. The helper does not save the snapshot. This receipt is single-use and expires in two minutes. Send it immediately with no intervening draft edits. Gmail's send-draft call exposes only an ID, so the hook cannot independently inspect the saved body or detect concurrent edits in Gmail; do not claim content-hash enforcement for this path.

If a hook blocks an unchecked send, complete this work and retry automatically when sending is authorized. The block is not a human approval request. If Gmail returns an ambiguous timeout, check Sent Mail before any resend to avoid duplicate delivery. Finish with the actual sent-message readback; saved, reviewed, and sent are distinct states. This local hook covers the registered Gmail connector actions, not browser clicks or other clients.
