# Existing client workflow routing

Use the current client's owning private project and approved invoice builder/template when available. Ask for the project or supplied agreement/evidence if it cannot be identified from current task context. No named client, personal host path or historical chat is assumed.

Read the agreed service terms, current evidence cutoff and invoice state before compiling work. Attribute activity to a client only from supplied file/project context and confirmed human work; a foreground design app is not a universal client attribution rule. User-confirmed time remains distinct from reconstructed intervals and unattended agent work.

For an existing builder, inspect its current input contract and preserve the last approved invoice/template. A visual reference supplies design, not current facts. Replace historical dates, invoice numbers, line items, rates, hours and amounts from current verified data. Do not change an approved invoice to fit a template or copy private records into this package.

For a requested document, use a separately available document builder and verified template chosen for this client. This package does not bundle document-rendering services or a personal invoice design. If the exact template is missing, prepare complete structured invoice data and identify the missing document capability without inventing an attachment.
