# Daggerheart Adapter

Use this skill only when the user names Daggerheart or asks for Daggerheart
rules, teaching, prep, or live adjudication.

## Source Policy

- Verify the current official Daggerheart SRD, changelog, errata, play guide,
  GM guide, and license status before making authoritative rules claims. Confirm the
  edition/version on the publisher's official site because current sources can
  change.
- Never rely on remembered beta/playtest rules.
- Do not quote or package non-SRD commercial text, cards, art, maps, adventures,
  or proprietary downloads without explicit rights.
- Label each rules answer as `official`, `table-ruling`, or `verify-after-play`.

## Workflow

1. Identify the current fictional choice and table urgency.
2. Check official-source availability and ruling log.
3. Translate the neutral GM intent into Daggerheart procedure.
4. Teach only the rule/resource needed for this choice.
5. Support fluid spotlight without letting the assistant become initiative
   controller.
6. Mark uncertainty and post-session verification.

## Adversary and Hybrid-Rule Checks

- Treat adversary type as a combat role, not a creature count. A lone enemy is
  not automatically a Solo. If a creature is labeled Solo, compare its HP,
  features, and spotlight capacity to current Solo examples. Otherwise use the
  role that matches how it behaves, such as Standard or Skulk.
- When damage can trigger both a reaction and defeat, state the order. Unless
  a feature explicitly overrides defeat, marking the last HP prevents a flight
  or phase-change reaction.
- Distinguish an Evolution from a Phase Change. An Evolution alters the same
  adversary and can trigger only once per scene. A Phase Change replaces one
  stat block with another. For a homebrew creature with several forms, state
  whether encounter planning counts those forms once or separately, and state
  explicitly when defeat is overridden, resolved, or followed by a death
  effect that summons new adversaries.
- Write Group Action Rolls as one complete procedure: one lead action roll,
  fitting reaction rolls from participating PCs, then +1 per helper success and
  -1 per helper failure. Do not describe this as ordinary help.
- Check every four-outcome table at every legal trigger state. A benefit such as
  becoming Vulnerable is not a benefit if the trigger already made the target
  Vulnerable.
- For hybrid mechanics, state exactly which official roll types are eligible.
  Do not let a custom reroll or push silently modify reaction, Group Action, or
  Tag Team Rolls unless that interaction was deliberately designed and tested.
