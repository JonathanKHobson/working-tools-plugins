# Portable startup and external bindings

Install Python 3.10+ and the MCP Python SDK in a dedicated environment: `python3 -m venv /path/to/venv`, then `/path/to/venv/bin/python -m pip install -r requirements.txt`. This task does not install packages or register a marketplace entry. The server runs over stdio, with `video-style-library` and all existing tool/resource IDs preserved.

`.mcp.json` uses `python3` from PATH and the compatibility host plugin-root variable; `mcp.json` supplies the portable root variable. Set `VIDEO_TEMPLATES_PYTHON` to an MCP-equipped interpreter if the host's python3 lacks it. Alternatively store a small private JSON object in `~/.config/video-templates/bindings.json` (or `VIDEO_TEMPLATES_BINDINGS`) with optional `interpreter`, `catalog`, `storyboard_db`, `shared_ui` and legacy `templates_root` keys. Do not package that file or a host profile. Environment overrides are `VIDEO_LIBRARY_CATALOG`, `VIDEO_STORYBOARD_DB`, `VIDEO_TEMPLATES_CHOOSER` and, for the old Video launcher, `VIDEO_TEMPLATES_ROOT`.

The defaults load the bundled catalog and chooser. The existing private state path remains `~/.local/share/video-production-studio/storyboards.sqlite3`; it is created only by storyboard writes. An explicit DB binding must be outside package source. Keep references/media in the project, not in this plugin.

HTML export requires Pillow but does not import the MCP SDK: `python3 scripts/video_style_library_mcp.py --export-html /absolute/review/video-library.html`. Export the empty storyboard editor with `--export-storyboard-html /absolute/review/storyboard.html`. These files are inspection fixtures; they do not prove native host interaction. Public media playback/downloads require network and current upstream availability.

Migration: install/enable the new plugin, configure its interpreter and external state, then remove the old `video-style-library` registration to avoid duplicate servers. The old source launcher is a compatibility route and reads the former external `~/.config/studio-tools/design-library.json` interpreter only when no new interpreter binding/override exists. Its source runtime symlink exists solely for old developer test/import paths, must be excluded from future Video Production Studio package payloads, and cannot establish installed-cache portability. A legacy cache requires an explicit `VIDEO_TEMPLATES_ROOT` or `templates_root` binding. Existing installed caches were not modified by this source change.
