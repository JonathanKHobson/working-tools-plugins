# Platform-native content cycles

Load only the requested platform/phase for planning, repurposing, conversation,
inbox or measured learning. Use [platform coverage](platform-coverage.md) for owners.
These are editorial methods; observed official feature facts are cited separately.
No fixed posting rate, hashtag formula or cross-platform engagement benchmark is
imposed. Existing project cadence and native records govern dates.

## Common intake and handoff

Reuse the project's source inventory, voice, channel policy and publication history.
Record the requested reader/action, owned source ID/version, rights/privacy,
claims/caveats and selected useful derivative. Follow [source to derivatives](source-to-derivative.md)
for complete passage and recording time lineage, [connected publishing](publishing-ecosystem.md)
for allowed channels, dependencies and calendar, and [account learning](account-learning.md)
for actual feedback. A source trigger enters that established workflow; it does not
authorize every possible platform or a new automation.

The minimum output is the requested piece or cycle: usable payload, source basis,
chosen platform action, actual readiness/state, release dependency and next owner.
Add measurements only when they exist. Keep production edits with Video/Graphic,
writing with Writing/Social, strategy with Marketing and native actions with Social
Publishing. Do not interrupt a one-post request with a mandatory system rebuild.

## LinkedIn: professional proof and relevant conversation

1. Choose one audience decision: understand an approach, assess demonstrated work,
   try a technique, consider a teaching opportunity or follow a useful resource.
   Verify current professional facts and inspect the proof artifact. Use the
   [trend method](linkedin-trend-research.md) only if the angle claims currentness.
2. Choose format by the idea: a concrete professional example for text, an actual
   demonstration for native video, a sequenced method/comparison for a document,
   deeper analysis for an article, or a continuing editorial promise for a newsletter.
   Carousel copy goes to Channel Adaptation; final assets go to Graphic's existing
   composition/review route. Preserve a plain-text useful summary and source trail.
3. Reconcile the project's whole queue and related topics, not just this campaign.
   Verify destination availability, actual audience and native scheduling limits.
   Read back the saved post/article record through the existing publishing reference.
4. For authorized conversation work, inspect the specific thread, answer its point
   and preserve the person's context. Add a resource only when helpful. Tag real
   contributions; no reciprocal comment quotas or automatic future comments.
5. For inbox work, use the authorized private account slice and current native
   categories. Inspect complete relevant conversations before triage or reply.
   Prioritize concrete work/teaching/collaboration opportunities and obligations;
   do not convert reactions or profile visits into permission for cold outreach.
6. Compare relevant same-age formats using native definitions. Separate member
   metrics from Page metrics, exposure from response and actual qualified inquiry
   from profile activity. Choose one test supported by a source or repeated pattern.

Official distinctions, checked 2026-10-04:

- [Document uploads](https://www.linkedin.com/help/linkedin/answer/a519831) supports a titled document; the uploaded document itself cannot be edited in the post. Final document QA happens before upload; updating its description is a different action.
- [Messaging filters](https://www.linkedin.com/help/lms/answer/a542831?lang=en-US) describes Focused, Other, Archived and Spam with relevant Jobs/Unread/Starred/InMail filters. Available categories still require live inspection.
- [Member post analytics](https://www.linkedin.com/help/linkedin/answer/a518885?lang=en-US) describes estimated reach and post interactions, profile activity and external-link visits with limits; private or missing data must not become inferred zero.
- [Authentic engagement policy](https://news.linkedin.com/2026/authentic-content-and-conversations), published 2026-03-13, prohibits engagement pods and automated comments. Preserve the existing attended-action boundary in account learning; native schedules for content do not establish schedules for replies.

## YouTube: discoverable teaching with fulfilled promises

### Plan and package

Frame the viewer's task and expected result before writing a title. Note prerequisites,
what is demonstrated versus discussed, the exact source/render version and the next
useful resource. For a series, order lessons by learner dependency and place the
topic before series numbering. A course export still needs a complete viewer entry
point; it does not inherit the course navigation automatically.

Use authorized native Trends/search data or supplied analytics to identify viewer
questions. Record the source/window and distinguish a search gap from a demand
forecast. Choose a title and thumbnail that accurately promise what the opening and
body deliver. Review opening clarity, readable screen detail, narration, captions,
chapters and result at actual display scale. SEO is truthful question/answer alignment,
not tags as a growth mechanism. Existing catalog packaging owns metadata, thumbnails,
playlists, caption tracks and experiment controls.

### Repurpose and release

Apply the complete source-to-derivative method. Select a demonstrated step/result,
specific decision, correction or coherent teaching beat for a Short. Include needed
prerequisites; remove dependence on “as mentioned earlier” and show the result.
An engaging fragment without its qualification is not an acceptable derivative.
Video's course-shorts owner keeps output-timed captions, reframing, cut integrity and
render QA. Clip batch review compares overlap before candidates enter the calendar.

Use a verified related video when a Short offers a useful next lesson; do not make
it the only payoff. A linked long-form resource must exist with intended visibility.
Continue through existing YouTube/LinkedIn scheduling for native ID, checks, visibility,
caption state, exact schedule and public readback. Keep link-promoting LinkedIn
companions behind source availability. A later Substack issue should deepen the
explanation or combine compatible clips, not repeat the transcript.

### Conversations and audience learning

During an authorized account review, inspect published and held comments for the
selected video/window. Answer a concrete learner question, provide an exact useful
timecode or correct resource, and distinguish viewer opinion from an established
fact. Read actual comments before accepting an AI-generated topic summary. Identify
repeated confusion for a caption/description clarification or a future lesson;
do not silently recut a published lesson. Moderation/deletion uses its own authority
and readback. A pinned comment or heart is a real account action, not a draft.

The working relationship queue may include comments/mentions and an already verified
contact route. No private-message tool was verified here; do not assume a generic
creator inbox or move public commenters into private sales outreach.

Compare packaging, delivery and outcomes separately:

| Question | Evidence to inspect | Bounded next change |
| --- | --- | --- |
| Do suitable viewers discover it? | Relevant traffic source/search terms, registered thumbnail impressions, CTR in comparable source/window | Clarify truthful title/thumbnail or playlist/resource placement |
| Does it fulfill the opening promise? | Retention interval, opening content, traffic/audience mix, similar-length comparisons | Clarify setup or demonstrate the result earlier while preserving prerequisites |
| Where is teaching unclear? | Exact retention interval plus comments and full playback | Improve explanation, screen framing/captions or a follow-up example; a dip alone does not prove boredom |
| Does a Short stand alone and lead somewhere useful? | Stayed-to-watch/engaged views, coherent payoff, related destination and available follow-through evidence | Test one first beat or clearer payoff; do not infer clicks from subscribers |
| Does the channel support its real goal? | Returning audience, qualified questions, resource use or verified work/teaching inquiries | Keep, change or defer the topic/format based on usefulness and effort |

Official facts, checked 2026-10-04:

- [Trends](https://support.google.com/youtube/answer/11962757?hl=en) describes searches and Shorts content gaps, with country/language/device limits and a July 2026 Studio rollout. Verify account availability.
- [Related video for Shorts](https://support.google.com/youtube/answer/14075157?hl=en) requires advanced-feature access and a public or unlisted video from the channel; verify selected ID in the native record.
- [Content analytics](https://support.google.com/youtube/answer/12220281?hl=en) now says views count at play start across formats from 2026-08-24. Keep metric-definition/version when comparing historical periods. Engaged views, watch duration, retention and traffic sources remain distinct; a view does not establish learning.
- [Review and reply to comments](https://support.google.com/youtube/answer/9482367?hl=en) describes published/held review and native replies, reactions, pins and conditional AI summaries. Availability does not mean an action occurred.
- [Native title/thumbnail tests](https://support.google.com/youtube/answer/16391400?hl=en) use watch time and have feature/format eligibility requirements. Prefer an authorized native eligible test; an inconclusive result stays inconclusive. Sequential manual changes are observational, not a controlled A/B result.

## Substack: sustained editorial value and reader relationships

### Plan an issue, not a transcript deposit

Write a one-sentence promise: which reader problem the issue addresses and what the
reader can understand or do afterward. Decide whether one source has enough depth
or several compatible source items should be combined. Retain their claim lineage.
Distinguish evidence, author's supplied perspective, interpretation and imagined
example. A useful article may be source-led teaching, researched explanation,
reported case or a reflective essay; do not invent experience to achieve a style.

Build an independently useful body: clear opening, complete explanation or argument,
concrete example/exercise where useful, caveats and a purposeful ending/resource.
Title/subtitle should state an honest editorial promise; use the existing Writing
template/voice owners without flattening the author's individual tone. Source claims
near their use. Interior media must explain, prove or help act; preview email fallback
so essential teaching does not disappear with an interactive embed.

Reuse the existing Substack publishing procedure for native draft/settings, source
notes, SEO, tags, purposeful visuals, Mobile/Desktop/Email preview, audience/comment
controls, delivery selection and native schedule readback. Free/paid access and web
versus email/app delivery are actual reader decisions; never inherit a blank draft's
defaults silently. An optional paid model needs audience/offer strategy and real
authorization, not an engagement assumption.

### Distribute and converse according to surface

An issue can support one useful Note: a complete small idea, a grounded excerpt with
context, a real question or a relevant resource. Select it only when it adds value;
Notes need not copy the headline or become daily quotas. Respect the existing spacing
of related YouTube and LinkedIn content. A later LinkedIn adaptation gains professional
context and keeps the source; a subscriber receives meaningful new value rather than
four indistinguishable promotions.

Use each conversation surface intentionally:

| Surface | Method / completion evidence |
| --- | --- |
| Article comment | Read the passage and actual thread; clarify or discuss the issue, then read back the specific reply if authorized |
| Public Note/reply/restack | Address the public idea with supported context; quote attribution and reuse rights remain intact; verify the actual profile/post record |
| Publication Chat | Verify subscriber audience and permissions; host a focused discussion/activity with a reason to participate; subscriber access is not private one-to-one correspondence |
| One-person DM | Confirm recipient, complete prior context, current purpose and actual send authority; prepare a personal bounded reply and verify the native thread after sending |
| Email response | Use the existing correspondence owner and authorized email workflow; newsletter delivery does not authorize personal mail to subscribers |
| Reading Inbox | Intake for reading and potential source discovery; it is not a client-response queue or permission to republish another writer |

Reader language can inform an issue, but no private DM or subscriber identity becomes
public evidence without appropriate permission. Recommendations should reflect real
reading and relevance; reciprocal promotion cannot manufacture endorsement.

### Measure the issue promise and return value

Record post ID, delivery choice, free/paid audience, issue length/type, collection time,
post age, traffic source, source of metrics and the native definitions. Compare issues
of similar purpose and age. Review views, delivery/open measures, link activity,
subscriptions, meaningful comments/replies and actual business/teaching outcomes
separately. If paid is active, distinguish estimated annualized revenue from money
received and from a demonstrated cause. No universal “good open rate” is required.

Inspect substantial reader responses before changing tone or cadence. A weak first
response may be distribution, topic, source audience or timing; choose one supported
test such as a clearer promise, more useful example, better resource or a delivery
choice. Maintain the issue's substantive value. Unsubscribe/cancellation evidence, if
available, needs its period and context; absence is unknown, not success. Keep the
publishing effort sustainable before adding another format or platform.

Official facts, checked 2026-10-04:

- [Posts guide](https://support.substack.com/hc/en-us/articles/15853567274772-Guide-to-your-Substack-Posts-page), updated 2026-02-06, separates Published/Drafts/Scheduled. It states delivery/open calculation now includes app receipt/view behavior; do not label these email-only or compare definition changes silently. Views include repeat web/email/app views; estimated revenue is not cash received.
- [Post stats in the app](https://support.substack.com/hc/en-us/articles/27851853697556-How-can-I-access-my-post-stats-from-the-Substack-app) describes Performance and Discussion views with traffic/subscription sources; a discovery-source label is not proof that one promotional Note caused a signup.
- [Notes and Chat](https://support.substack.com/hc/en-us/articles/18791701372180-What-is-the-difference-between-Notes-and-Chat) have different visibility and reply controls. Inspect actual controls rather than treating Chat as a public Note.
- [DMs](https://support.substack.com/hc/en-us/articles/10551066288404-Can-I-direct-message-another-reader-or-creator-on-Substack), updated 2026-08-10, supports private one-person conversations on web/app. Documented capability does not authorize sending.

## TikTok: useful source, shared production and attended native scheduling

Use [TikTok native scheduling](../../skills/social-publishing/references/tiktok-manual-publishing.md)
for the complete selected-source, cover/hook/caption, clean-master, sound/disclosure,
current-native-preview, queue/native-schedule and separate eventual public-receipt procedure. Every new Short gets an assessed
TikTok candidate, with a reason; selected backfill inspects history and independent
value. Assessment is not publication and creates no quota or additional render by
default. Video retains media/EDL/output-caption/render responsibilities.

Current authority can permit the user or Codex to select the file, upload, review and
save a future native schedule through an attended browser, on different account
calendar days and at most one TikTok video per day. Direct source exports and custom
adaptations both fit, including authorized owned-account reuse; retain distinct
variant IDs/receipts without overwriting published variants. Immediate/Now
posting is prohibited. Verify shared-source public availability before scheduling;
check the existing queue and live horizon, record date/time/timezone/native receipt
and verify eventual public release separately. Outside the live horizon, keep the
item prepared for the next attended handoff. A draft/approval hold still governs.
Keep account capability and numeric limits in the dated project record; no posting
API, external scheduler service, bot, unattended UI loop or automatic LinkedIn fanout.

For authorized learning, use actual native metrics and comments with definitions,
window and post age. Missing metrics remain unavailable, not zero. Make one supported
change; preserve existing releases and holds. Studio notifications and app chats remain
different surfaces; any conversation/DM action needs separate current authority.

## Private inbox action record

When inbox work is requested, reuse an existing project relationship/action record.
Keep only necessary thread pointer, recipient/account, last relevant inbound/outbound
date, purpose, commitment/deadline, next useful action, authorization and state.
Useful triage classes: respond, clarify, resource request, opportunity, obligation,
wait, no action or opt-out. Avoid speculative relationship scores and generic
follow-up loops. A draft, a sent reply and a response received are separate states.

Before an authorized send, read the current thread, exclude already completed or
superseded actions, confirm recipient and final payload, then use the supported native
action and readback. An uncertain result calls for thread reconciliation before retry.
Preparation may continue when sending is unavailable; name the exact access/action
gap. Only a requested recurring review belongs in an existing automation; these
methods themselves create no timer, watcher, engagement bot or inbox scraper.
