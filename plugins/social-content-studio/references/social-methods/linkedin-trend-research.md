# Verified trend selection and useful hooks

Load when a LinkedIn idea depends on current events, a claimed trend, current reader
language, or a trend-linked hook. The research method transfers to other channels;
their packaging still follows their own cycle. A timeless work example does not need
a trend grafted onto it. Use `research-methodology-local:current-social-research` for
the actual bounded public evidence search, then hand facts to Social/Marketing.

## 1. Set a decision and evidence window

State the intended reader, work/teaching question, channel, geography if relevant,
decision date and search window. Choose a window appropriate to change speed: a
short release window, a recent month, or a longer sparse-topic window. These are
editorial choices, not proof a topic is trending. Search named entities and aliases;
confirm identity. Ask what current evidence could change the content decision.

Start with the existing project's candidate/history record. An optional trend table
belongs there, not in the plugin. Do not create a database, scraper or subscription
merely to draft a post. When a maintained database is requested, reuse that project's
existing storage and keep the following fields in its schema:

| Record | Minimum useful fields |
| --- | --- |
| Candidate | ID, reader question, entity/topic, geography/language, intended decision, search window, discovered_at, owner |
| Event | Original event date, announcement/publication date, update date, status/availability, primary URL, exact relevant passage/locator |
| Signal | Source URL, author/org, source type, published_at or undated, observed_at, observed language/behavior, metric definition/window if any |
| Verification | Primary-source check, independent source lineages, disagreement, missing lanes, confidence and reason, last_checked, expires/recheck trigger |
| Editorial decision | User-supplied position or supported interpretation, reader relevance, owned proof, hook/format, rights/privacy, ready/verify/skip and reason |
| Handoff / learning | Related content/source IDs, native state/URL if later acted, actual results window, observation/hypothesis, next bounded test |

Do not equate a blank date with today. Preserve source locators so a later reviewer
can reproduce the claim. A database row is a candidate, not approval or publication.

## 2. Establish what happened before calling it a trend

Find the original announcement, release note, paper, dataset, legislation, product
record or attributable creator statement. Record the event date separately from
article date: a recently republished old story is not a new event. Check whether the
claim describes announcement, rollout, beta, availability, prediction or measured
adoption. For numeric claims preserve population, denominator, units and period.
Read enough original context to preserve caveats and note later corrections.

Then find independent signals relevant to the intended audience. Several articles
quoting one release are one source lineage. Seek a different perspective or behavior
lane: primary update plus practitioner response, actual public usage evidence, dated
search signal or independent reporting. Search a plausible counter-query. Record
disagreement and who is absent. Do not call a selected handful of posts consensus.
Vendor trend reports can reveal positioning; they do not establish broad adoption.

Classify the result explicitly:

- **Verified event:** primary evidence establishes what happened and when; demand or broad interest remains unproven.
- **Observed current signal:** dated sources show particular people/questions/behavior in the specified slice; state coverage limits.
- **Emerging pattern:** multiple independent relevant observations recur within a defined period; confidence remains bounded by sampling and access.
- **Platform-labeled trend:** the native surface labels it trending for a region/window; report the surface and filters, without implying universal interest.
- **Editorial hypothesis:** a useful connection worth testing, not an observed trend or the author's established opinion.
- **Insufficient/stale:** original basis, currentness or relevance is missing; verify, choose an evergreen angle, or skip.

Google Trends reports normalized sampled search interest, not absolute demand or a
poll. Record query/topic, geography, range and retrieval time; its 0–100 scale and low
volume behavior cannot support a claim that a profession agrees. Use it as one signal
alongside others. [Official data FAQ](https://support.google.com/trends/answer/4365533?hl=en),
checked 2026-10-04.

## 3. Select relevance before speed

For each candidate answer: What actual reader decision does this change? What can
the author add from verified work, a usable explanation, a fair comparison, or an
explicitly qualified interpretation? Does the author hold this view, or is it a
proposal for their review? What would be misleading if compressed?

Keep a small shortlist with ready/verify/skip and reasons. Prefer inspectable proof
and a complete payoff over being first. A current event can earn an explanatory
post without being a trend. Newsjacking means borrowing event attention for a weak
connection; reject it when the professional/teaching relevance cannot be stated
concretely, the author lacks a useful contribution, or urgency outruns verification.
Sensitive events require a contribution appropriate to the event and audience;
shock, tragedy, or a named person's distress is not a convenient sales hook.

Check reuse rights, quotation scope, screenshot permission and private identifiers.
A publicly visible asset is not automatically reusable or licensed across platforms.
Credit the original creator and link the consequential source near the claim. If
reuse is uncertain, describe the idea with a source link and use an owned visual.

## 4. Build a truthful hook with an independent payoff

These are editorial structures to adapt to supplied voice, not guaranteed growth
formulas. Fill only with checked facts, demonstrated work or an attributed view:

| Structure | Required basis / useful body |
| --- | --- |
| Change → practical consequence | Exact dated change; explain who is affected, who is not, and one supported action |
| Reader question → demonstrated answer | A real question or clearly framed anticipated question; show the action/result and prerequisite |
| Evidence → interpretation | Inspectable source/owned artifact; distinguish observation from interpretation and give the caveat |
| Comparison → decision rule | Comparable documented alternatives; criteria, tradeoff and circumstances rather than a universal winner |
| Mistake → correction | Actual observed mistake or labeled hypothetical; corrective method and verifiable result |
| Current event → durable lesson | Verified event plus meaningful professional connection; reader still gains value after the news cycle |

Do not invent personal conviction, an anecdote, a provocative disagreement, broad
consensus, urgency, an audience quote or an outcome to fill a template. If the author's
position is unknown, deliver a proposed angle labeled as such. Avoid withholding a
simple answer for clicks; the body should fulfill the opening's promise. A carousel
needs a useful sequence and readable evidence; a longer article must add analysis
or teaching depth beyond the initial post.

## 5. Handoff, expiry and bounded learning

Deliver a compact brief: decision/window, selected candidate/classification, original
event/source dates, 2–5 relevant source links when available, strongest support,
counter-evidence/coverage gaps, reader payoff, proposed hook and actual author-position
basis, rights and readiness. The source count is a useful reporting range, not a
quota or proof threshold. A thin source lane stays visibly thin.

Recheck facts likely to change just before scheduling/publishing: availability,
price, role, feature rollout, event logistics or rapidly developing news. Retain the
existing calendar and release dependencies. Record a recheck date or event-based
expiry in the project's candidate record; no new watch job is implied.

After release, use [account learning](account-learning.md) to compare a relevant
same-age slice and substantive responses against the intended outcome. A successful
hook is an editorial observation, not proof that a trend caused career traction.
One post cannot establish a reusable algorithm rule. Preserve useful learning with
the existing owner and choose one change for the next supported piece.

## Platform discovery sources and limits

Checked 2026-10-04; these are sources to inspect when relevant, not subscriptions
configured by this reference.

- [LinkedIn Analytics & tools](https://www.linkedin.com/help/linkedin/answer/a1432215) includes account analytics and, when available, AI-generated post ideas. Such ideas are proposals, not current evidence or an authentic opinion.
- [YouTube Trends](https://support.google.com/youtube/answer/11962757?hl=en) supports topic/search and content-gap discovery; availability and the Studio layout vary. A suggested gap requires a useful answer from the author's evidence.
- [TikTok Creative Center Trends](https://ads.tiktok.com/resources/help/article/how-to-use-trends?lang=en) supports industry/time filters and hashtag analytics. Record filter context; ad-oriented evidence does not predict an organic post's performance.
- [TikTok Creator Search Insights announcement](https://newsroom.tiktok.com/creator-search-insights?lang=en), published 2024-03-13, describes search topics and content gaps in selected regions. This is historical first-party feature evidence, not a verified current account entitlement or current topic trend.
