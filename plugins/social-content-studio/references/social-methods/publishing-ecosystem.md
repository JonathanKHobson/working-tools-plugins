# Connected publishing and evidence

Read when a video, course update, article or reviewed project checkpoint enters an
authorized recurring publishing workflow. An attachment alone is not publication
authority. Read the current request and project policy first: a draft-only request,
excluded channel or existing human-review hold governs every downstream derivative.
This procedure is agent routing, not an always-running file watcher.

## Intake and lineage

Find the existing project map, source inventory and channel ledgers before creating
records. Reuse a stable source ID and version/hash. Retain transcript/output times,
rights/privacy, author/contributor attribution, supported claims and public state.
Find the existing channel owner/chat; use Work Management for authorized coordination.
Pass source pointers and a small complete payload, not an entire private archive.
The receiving owner records source ID/hash, request date and authorization reference,
allowed channels/exclusions, supplied assets, dependencies and downstream owner/status.
Use a cited standing grant where it applies; record a narrower current request over it.
One owner controls each live editor/session; file writers own disjoint outputs.

Read the shared publication history and native queues before choosing dates. Preserve
existing native IDs and user edits. Reconcile uncertain attempts before retrying.
Build a source-linked candidate for each authorized useful derivative, then schedule
according to the project's spacing budget; candidates are not an obligation to flood
every channel. Combine related excerpts into one substantial article where warranted.

For weak article material, retain the candidate and state the missing depth rather
than manufacture an anecdote or thin article for every Short. An article should offer
an independently useful explanation, example, decision or resource. Several compatible
evidence items can support one theme; preserve contribution and claim lineage.
Portfolio publication remains a separate decision. TikTok assessment does not automatically produce a LinkedIn companion. TikTok supports direct exports and custom adaptations, including authorized owned-account reuse; keep distinct variant IDs/receipts under the same source and preserve published variants. TikTok uses attended native future scheduling only, at most one video per account calendar day; verify the shared source public before scheduling and keep local queued, native scheduled and eventual public states distinct. Record selected / defer / unsuitable and the reason for each newly made Short; curated backfill uses the requested catalog slice and duplicate/history checks, not a quota. Deferred channels, audio extraction
and paid products stay deferred until the project authorizes them.

## One calendar, several native ledgers

Keep an index over existing records, not a second competing source of platform truth.
Store, where applicable:

- content ID, source-parent ID/version and project/theme tags;
- channel/account, format, intent and career/teaching/collaboration purpose;
- final copy/assets/alt text/caption paths and hashes;
- claim/rights/readiness state, contributor credit and related evidence IDs;
- native ID/URL, desired date, actual native date, timezone and dependencies;
- last same-source/topic post, next eligible date and explicit spacing exception;
- receipt source/checked time, analytics review date and owner;
- status: candidate, prepared, native draft, reserved, native scheduled, published,
  publicly verified, deferred, failed or uncertain.

Reserved dates and scheduled agent runs are not native content schedules. Never infer
publication from a past date. Link-promoting content cannot precede availability of its
destination. A native-video post can stand alone if it does not depend on a private URL.

Anchor planned offsets to the upstream saved native schedule receipt and reconcile with
the verified public release after it occurs. A changed, canceled, failed or late source
release invalidates dependent dates: mark affected items for review, notify the authorized
owner and inspect/reschedule dependent native records within scope before they publish.
If a necessary repair needs unavailable access, report the exact at-risk item and date.
Every handoff/account review checks dependency state, not merely calendar collisions.

Use project-specific cadence and compare against every relevant queue, including
career, course, project stories, articles and event campaigns. If no spacing policy
exists, propose a modest editable default; do not claim an algorithm requires it.
Useful constraints include minimum gap between primary posts, same-topic cooldown,
longer unchanged-case cooldown and a narrow exception for substantial active changes.
Push new candidates later instead of silently canceling unrelated posts. Dates beyond
the actual native horizon stay prepared/deferred. Reconcile them at the next authorized
content handoff or existing scheduled review; do not invent another scheduler.

## Craft, credit and accessibility

Use Writing Quality for authentic voice and plain language; Marketing for audience,
search intent and measurement; Graphic Design/imagegen for purposeful new visual assets;
Video for exact timing, framing and caption QA. Use a genuine question or useful reader
action, not engagement bait. Attribution is not co-authorship: verify contribution and
native author identity before adding a co-author. Do not upload someone else's private
work because a shared link or password grants viewing access.

Make visuals explain the idea. Vary images, diagrams, native video and text as evidence
warrants. Inspect final rendering and mobile readability, meaningful alt text and timed
captions. A mockup or source extraction does not prove the actual native preview.
For new generated art, define the source-specific message before choosing props. State
in one sentence what the image helps its reader understand, verify or recognize. A
specific marketing purpose is valid; decorative polish alone establishes no SEO or
engagement benefit, and a useful post need not contain an image.
Check the visual's meaning as well as object relationships: magnification/reflections,
perspective, contact/shadows, readable diagrams and plausible interactions. Decorative
symbols or polished texture do not rescue an incoherent concept. Use Graphic's generation
and review owners, UX for attention/comprehension and Writing's anti-slop review for copy
within its actual remit. Prefer a real proof crop or deliberately drawn diagram when it
communicates better. Forward craft feedback does not authorize replacing approved
published or already scheduled artwork.

Also review whether the visual is interesting and quickly understandable at its actual
display size. Correct facts inside dense colored text cards are not automatically a
successful article image. Use Graphic Design for focal hierarchy, meaningful visual
contrast and composition; use Data Visualization Toolkit's strategy-and-critique route
when a comparison, mechanism or evidence relationship needs visual explanation. Avoid
fabricated charts and do not replace the visual idea with a miniature article.

## Feedback and completion

Use [account learning](account-learning.md) during authorized handoffs and existing
recurring account reviews. Keep creative, compassionate and critical thought ahead of
raw interaction volume when these are the project's stated principles. Optimize toward
the user's real outcome, such as qualified work opportunities or useful learning.

Completion requires actual native receipt readback for scheduled content, clear deferred
items, and updated source links in the shared index. Read the live account/content/assets,
audience, time/zone and stable ID. Follow the existing post-release verification owner.
Record a proven interface lesson only in the owning conditional reference, with date,
observed control/failure/correction and evidence; never capture credentials or private
analytics in a reusable plugin. A new hook is not needed merely to remember a UI lesson.
