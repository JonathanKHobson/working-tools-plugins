# Instagram formats: carousel, Story, and repurpose

Use this method for Instagram-native carousel copy, Story sequences, or a week of derivatives from one long source. It keeps source-to-derivative lineage and existing Graphic and Video ownership. Source provenance: [Instagram agent review](../../libraries/instagram-agent/PROVENANCE.md).

## Carousel

Choose a carousel when the idea has sequence, a framework, a before/after, or information worth rereading or saving. Choose a Reel when motion, a face, or a demonstrated payoff carries the meaning. A single claim that needs neither should remain a single post or route to the appropriate Reel method. Treat engagement and dwell claims as hypotheses unless supplied account evidence supports them.

Draft the slide copy before requesting asset production. A useful sequence is:

```
COVER       concrete promise, short enough to read in the grid
STAKE       why the reader should care
BODY        one idea per slide, with a short heading and only necessary detail
RECAP       standalone summary that works without the preceding slides
CTA         one action
```

Select the slide count from the material. Do not impose a universal quota or copy a caption into slides. Keep each slide legible at the intended mobile viewport, number slides when it aids orientation, and keep essential text inside the design system's safe area. The exact upload aspect ratio, item limit, file type, and size must be checked against current official guidance or the live composer when material. Do not import an upstream HTML-to-image shell recipe as an automatic build path.

Route composition, typography, imagery, and rendered visual QA to Graphic Design or the owning design system. Use the actual approved assets and identity. Supply alt text for the cover and meaningful sequence, or frame-level descriptions when the receiving workflow supports them. Keep caption work with `instagram-writing.md`, usually caption-led when the deck carries the main explanation. Respect any requested review hold; finish authorized copy and rendering without an extra approval loop. Upload/publish authorization and native readback remain separate.

```
CAROUSEL REVIEW
source: <ID and claim basis>
slides: <count selected and why>
1 COVER: <copy>
2 STAKE: <copy>
...
CTA: <one action>
alt text: <cover and sequence description>
asset owner: Graphic Design | existing project owner
render state: copy only | rendered and visually reviewed
publication state: prepared; nothing uploaded
```

## Story sequence

Stories serve an existing audience and a conversation or action, not the same job as a discovery feed post. Build a sequence around one event, process, result, question, or offer. Use enough frames to make the story understandable and no more than the source needs. A common shape is open, develop, ask, close:

1. Open with something concrete happening, a face, hand, artifact, or source-grounded scene.
2. Develop the process, result, mistake, or useful explanation, one idea per frame.
3. Place one interaction surface where it can be seen: poll, question, quiz, slider, link, countdown, or another currently available sticker. Choose it for the information or action needed, not for a quota.
4. Close with the answer, outcome, next step, or a truthful invitation to reply.

Choose the interaction by its job, then verify it exists for the account:

| Surface | Useful job | Check before handoff |
| --- | --- | --- |
| Poll | Compare two or more meaningful choices | Options are understandable; results are responses from participants, not representative research |
| Question box | Collect actual questions or feedback | Explain intended use; anonymize and obtain permission before reusing private responses |
| Quiz | Practice a checkable fact or concept | Verify correct answer and explanatory feedback; do not invent accuracy claims |
| Slider | Invite a lightweight reaction | Do not interpret the decorative scale as a calibrated measure |
| Link | Deliver an actual resource or next step | Check destination, label, access and promise |
| Countdown | Point to a real dated event | Verify date/time/timezone; never manufacture urgency |
| Add Yours or participation prompt | Invite voluntary contributions | Check current control, privacy implications and rights to reuse contributions |

Question-box responses can inform a later post or Reel: retain the exact question privately, remove identifying details as needed, distinguish a paraphrase from a quote and obtain permission for attributed reuse. This is an optional editorial handoff, not an automatic response or content queue.

Keep critical text within the current Story safe areas. Verify viewport and sticker controls in the current preview or composer. Do not assume a sticker, link, archive, highlight, or expiry setting exists for every account. A repost of a feed post needs a useful reason to return to it. If the Story invites a DM, the person should act first; keyword responses may use an explicitly verified provider feature, but bulk unsolicited messaging remains out of scope.

```
STORY REVIEW
date/context: <project context>
1 [visual] on-screen text / spoken line / accessibility note
2 [visual] on-screen text / spoken line / accessibility note
3 [sticker] prompt, options, and purpose
4 [close] outcome or next action
answers: what will be reviewed and how it informs the next draft
state: prepared sequence; nothing posted
```

## Repurposing one long source

Accept a transcript, article, newsletter, script, call summary, livestream, or owned video. Read the whole source before extracting. If a URL is unavailable to the current provider, ask for pasted text or a supplied transcript. If owned footage matters, request the actual media so the edit can use the real moment rather than inventing a re-record.

Extract, with source locations and counts:

- claims that could be challenged;
- numbers, dates, costs, durations, or percentages;
- stories with a person, scene, and consequence;
- mechanisms explaining how something works;
- mistakes or admissions;
- quotable lines that stand alone.

If the source yields too little material for the requested set, say so rather than squeezing thin derivatives. Map each extract to a format: claim, mistake, or story to a Reel candidate; mechanism or numbered process to a carousel; a quotable line to a Story frame. Preserve rights, consent, source/asset IDs, qualifiers, and chronology. Each derivative must stand on its own for someone who never saw the source. Do not imply that every candidate must be produced or published.

Use the existing `source-to-derivative.md`, `channel-adaptation-rules.md`, and `clip-batch-review.md` where applicable. Video owns time remapping, captions, audio, and media QA. Graphic owns visual composition. Social owns copy, claim lineage, variant IDs, and publishing handoff. Produce the requested set of complete derivatives, choosing only supported candidates and keeping intentional reuse visible.

```
REPURPOSE INVENTORY
source: <title, ID, version, rights/consent>
found: <claims / numbers / stories / mechanisms / mistakes / lines>
candidate map:
<source location> -> REEL | CAROUSEL | STORY, reason, variant ID
shared claims and qualifiers: <notes>
missing or risky source items: <notes>
state: candidates only; no render, upload, schedule, or publish
```
