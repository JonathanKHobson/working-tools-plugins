# Account learning and relationship review

Use during a requested analytics review, a content handoff in an authorized continuing
workflow, or an existing recurring social task. Read the project's goal, audience,
cadence, private contact preferences and current platform permissions first. Research,
drafting, scheduling and sending are separate actions; preserve the authorized scope.

## Inspect a useful slice

Confirm account identity and inspect recent live posts, native scheduled content and
the existing action history. Search the selected project's evidence, relevant Google
Drive folders, prior work and narrowly relevant Knowledge Atlas/memory/chat pointers.
Use original artifacts to verify claims. Open-source organizational work does not
expose participant data, private correspondence or credentials. Client work can be
captured privately while public examples need their own release/claim clearance.

Select candidate stories by relevance to the user's goals, proof strength, freshness,
topic balance and available assets. For a career-focused account, include concrete
work examples and appropriately spaced statements of current availability. Verify
current role interests/availability instead of deriving them from an old profile.
Keep friend promotion tied to public work, real contribution and audience usefulness.

For the selected account or asset, include a bounded search/discovery check: available
native search terms and referral sources, the reader's likely question, truthful title
and description alignment, relevant profile/article keywords, and the actual link
preview. Inspect public indexability only where relevant and supported by evidence.
Missing search data is unknown, not zero. Recheck current official documentation before
changing platform-specific metadata; keyword stuffing, hashtag counts and first-comment
links are not established ranking improvements. Avoid turning every review into a full
account or website SEO audit.

## Measure without inventing causality

Record platform/native ID, collection time, publication time/zone, format, topic,
sample/window, source of metrics and their denominators. Compare similar post ages and
formats. Distinguish impressions, views, retention, clicks, comments, profile visits,
qualified inquiries and actual opportunities. Missing values are unknown, not zero.
Do not imply that likes caused job offers or that watching established learning.

Read substantive comments for confusion, resource requests and useful disagreement.
Call a topic trending only with current dated evidence and coverage limits. Use current
official platform documentation for feature behavior; marketer claims about ideal times,
hashtag counts and link penalties remain hypotheses unless independently supported.

Choose one bounded adjustment when evidence supports it: opening, title/search intent,
visual explanation, length, pacing, resource, timing or topic mix. Retain principles,
source meaning, natural voice and honest limitations. Log observation, hypothesis,
change, comparison window, result and confidence. A single successful post does not
justify silently rewriting shared skills or expanding frequency. Reusable corrections
can enter the existing owner after repeated evidence and normal maintenance validation.
Keep raw account data private and minimal; do not create a public analytics archive.

Record a useful finding in the existing project action record with its source/window,
observation, hypothesis, proposed test, target outcome and review date. Identify the
affected owner: Social for topic mix, format and calendar; Marketing for audience,
search intent and measurement; Video for edit, pacing and captions; Writing Quality for
voice and readability; Graphic Design for visual explanation. Within current authority,
pass a compact source-linked handoff to that existing owner and record whether it is
pending, applied, deferred or rejected with a reason. Do not launch a new chat or rewrite
shared guidance merely because a metric changed. Repeated findings or a verified
reusable interface correction may update the owning skill through normal maintenance
and installation checks; current campaign facts stay in the project.

## Conversation and relationship boundaries

Inspect relevant threads before drafting replies. Suggest an answer that addresses the
actual person's point and may ask a specific question. Mention/tag someone for a real
contribution or directly relevant question; never mass-tag or create reciprocal
engagement quotas. Respect unanswered outreach, opt-outs and the project's action caps.
An engagement-only contact must not become a report recipient.

Check the platform's current supported action rules. LinkedIn's March 13, 2026 policy
explicitly prohibits automated comments through extensions/scripts/third-party tools
without human action. For unattended review, prepare replies and useful resource
comments for an attended session; do not operate comment bots or engagement pods.
When the user is actively present and explicitly requests computer-use assistance,
assist with individual relevant comments through normal visible controls within that
authorization and read back the actual result. Do not infer presence solely because a
timer fired, schedule future comments, install comment automation, or claim the platform
has endorsed a policy exemption. Native scheduled posts/articles are a separate
capability. Recheck policy if it changes.
[Official LinkedIn explanation](https://news.linkedin.com/2026/authentic-content-and-conversations).

Links in a first comment are an editorial choice, not a proven universal distribution
advantage. Preserve the reader's ability to find the resource. Future comments must not
be labeled scheduled unless a supported mechanism actually saved them. A thoughtful
discussion prompt can appear in the scheduled post itself.

## Recurring run closeout

Update the existing automation, never duplicate it solely for a new content source.
Preserve its notification settings, usage constraints, privacy rules and other owners'
reserved/native content. Model choice must match the actual scheduler/thread capability;
writing a model name in a prompt does not configure its runtime. Use bounded extraction
or writing workers when valuable, with one final judgment/browser owner.

Return the useful account result: verified schedules/actions, ready drafts for human
comments, measured observations, next experiment, source-linked candidate backlog and
specific access gaps. Do not narrate unchanged scheduled checks. Before retrying an
uncertain external action, reconcile the exact account record by ID and content.

For LinkedIn arithmetic use [performance](linkedin-performance.md); for a claimed trend use [verified trend selection](linkedin-trend-research.md). Keep observed native definitions and collection dates when they change.
