# Coordinate YouTube lessons, Shorts, and LinkedIn posts

Read for a cross-platform course release that includes scheduled YouTube videos or Shorts and corresponding LinkedIn posts. Platform statements below were checked 2026-09-30 against official documentation. Verify the current account, UI, and policy when acting. The project owns its release order and dates.

## Inventory and dependency decisions

1. Read the exact channel/profile/Page identity and the public, unlisted, private, and scheduled inventory before creating a record. Match each candidate by stable video/post ID, content, and intended role. If a public clip already exists and only its metadata needs correction, update that record in place; do not upload a duplicate. Read back the changed live title, description, captions, and URL.
2. Check source/third-party redistribution rights, privacy, and the exact final render hash. Confirm complete reviewed captions. For YouTube, upload a timed caption file or correct its automatic track before release. For a native LinkedIn video, attach an SRT on desktop if available; scheduled LinkedIn auto captions become reviewable only *after* the video posts, so they cannot serve as prepublication caption QA. [YouTube captions](https://support.google.com/youtube/answer/2734796?hl=en); [LinkedIn SRT captions](https://www.linkedin.com/help/linkedin/answer/a552177/); [LinkedIn auto captions](https://www.linkedin.com/help/linkedin/answer/a1360638).
3. A Short can stand alone before a full compilation. If useful, add YouTube's clickable **Related Video** after the Short upload, choosing an existing public or unlisted channel video; this needs advanced feature access. Do not delay the Short solely to create a compilation. URLs in Shorts descriptions and comments are non-clickable, so a pasted lesson URL is not an equivalent path. [Related Video](https://support.google.com/youtube/answer/14075157?hl=en); [YouTube link behavior](https://support.google.com/youtube/answer/13748639?hl=en-419).

## Native schedule and link checks

- YouTube Studio schedules a private upload for a chosen date, time, and time zone. Its help page states no maximum advance horizon; do not assume one. Review the actual scheduled record and revisit it if the account has a publishing restriction. [YouTube scheduled publication](https://support.google.com/youtube/answer/1270709?hl=en).
- LinkedIn's native personal-profile composer supports 10 minutes to 3 months ahead; Pages support 1 hour to 3 months. The composer normalizes to UTC using device time-zone settings. Use the relevant profile/Page control and read back the stored date, time, time zone, account, and content. [Profile scheduling](https://www.linkedin.com/help/linkedin/answer/a1362517/schedule-posts?lang=en); [Page scheduling](https://www.linkedin.com/help/linkedin/answer/a548192/scheduled-posts-for-linkedin-pages?lang=en).
- A YouTube scheduled/private video's URL is not publicly playable before release. If a LinkedIn post links to it, schedule LinkedIn *after* the YouTube public time with a practical buffer, then verify the target and preview when public. LinkedIn may fail to fetch link preview data; a stored URL alone does not prove a useful preview. This timing and preview recommendation is an inference from the documented access and preview behavior, not a platform guarantee. [Private-video access](https://support.google.com/youtube/answer/77272?hl=en-GB); [LinkedIn link previews](https://www.linkedin.com/help/linkedin/answer/a525301/sharing-articles-or-links?lang=en).
- If using APIs, YouTube's `status.publishAt` applies only to a private video that has never been public; unverified upload API projects may remain private until audited. LinkedIn's current Posts API creates with `lifecycleState: PUBLISHED` only, so do not assume it can make native future scheduled posts. [YouTube videos API](https://developers.google.com/youtube/v3/docs/videos); [YouTube upload API](https://developers.google.com/youtube/v3/docs/videos/insert); [LinkedIn Posts API](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/shares/posts-api?view=li-lms-2026-03).

## Accurate packaging and AI provenance

- Apply the current **project brief's** editorial owners before release. When a course project specifies them, route every public title, description, overlay, and post through `writing-quality-studio:natural-prose-editor` and its public editorial gate; use `social-content-studio:social-content` for the channel-fit LinkedIn draft, `marketing-strategy-studio` for the actual learner's search intent and claim boundaries, and `creative-writing-studio:show-vs-tell-craft` for one concrete teaching example where it improves comprehension. Ground each example in the lesson transcript, label fictional exercises, and do not invent anecdotes, results, or trendy claims. This is a project-scoped release requirement, not a universal gate for unrelated posts. Record which review occurred rather than implying that naming a skill completed it.
- Use a specific task or question in the title and opening description, an accurate thumbnail, and a concrete LinkedIn takeaway with the verified lesson URL. Put series numbering after the main topic. YouTube says title/thumbnail/description and relevance/engagement matter; tags generally play a minimal discovery role. Avoid clickbait, keyword stuffing, and unsupported performance claims. [YouTube search](https://support.google.com/youtube/answer/16090438?hl=en); [title guidance](https://support.google.com/youtube/answer/12340300?hl=en-GB); [description guidance](https://support.google.com/youtube/answer/12948449?hl=en); [tags guidance](https://support.google.com/youtube/answer/146402?hl=en-419); [LinkedIn distribution](https://www.linkedin.com/help/linkedin/answer/a516930).
- Authentic screen recording with actual human narration, plus AI-assisted outlining, title work, or captions, falls within YouTube's examples that do **not** require its GenAI disclosure. YouTube also lists cloning one's *own* voice for voiceovers/dubs as exempt. Realistic fabricated advice, actions, events, or scenes require disclosure. A generic synthetic narrator is not categorically resolved by the examples; describe voice provenance honestly and use the disclosure when the result could mislead viewers about who spoke or what occurred. [YouTube GenAI disclosure](https://support.google.com/youtube/answer/14328491?hl=en). LinkedIn displays supported C2PA Content Credentials on signed media but says it cannot identify all AI media; do not present absence of a label as proof of human creation. [LinkedIn Content Credentials](https://www.linkedin.com/help/linkedin/answer/a6282984).
- YouTube guidance updated for new Shorts on 2026-09-24 says an active claim on a Short over one minute no longer automatically blocks it in every case; a claim still needs review and may affect availability or monetization. Older help text can conflict. Prefer original or properly licensed audio and visuals. [Current Shorts music eligibility](https://support.google.com/youtube/answer/13486873?hl=en).

## Receipt and safe retry

Record asset hash, account/channel, platform ID/URL, visibility, scheduled time and zone, caption status, AI-use selection if relevant, and the provider's confirmation. Then verify the public URL after release. For an uncertain upload or schedule result, query the account inventory and exact ID first; retry only after excluding an existing record. Keep prepared, uploaded/private, scheduled, posted, and publicly verified as separate states. A future schedule is complete as a schedule only; set a post-release verification step.

## Native UI execution lessons

- Before opening the browser, prepare one reviewed handoff record containing final copy, media, timed captions, render hash, intended platform IDs/links, and target times. Use the existing writing and marketing owners above; this workflow does not need another marketing plugin. Preserve the supported API or native UI owner for the operation. Keep one browser action owner per session; delegate media, transcripts, copy, or read-only validation with a compact handoff while the lead owns native UI actions.
- Inspect the relevant dialog or content card with scoped DOM reads; avoid repeated whole-page dumps. Let the editor hydrate, identify title and description separately, then read both back after filling: a loading race can put description text into the title. Resolve assets to existing absolute real paths before a file chooser; unresolved `../` paths can produce an unreadable upload. Re-observe the UI after each action rather than trusting the prior control state.
- Wait for the caption dialog to close before navigating to visibility. Identify **Add Related Video** and **Add subtitles** by their section/dialog context on Shorts, rather than a fixed `nth` index. Read back the caption track and selected Related Video ID.
- Record `schedule_accepted_processing` separately from a saved **Scheduled** row with the exact ID and time. A toast, future date, or processing/checks panel is not that row. No notices displayed does not prove checks completed; preserve the actual pending/completed checks state. A **Draft** label does not prove **Private** visibility.
- A LinkedIn composer can enforce a day-count limit that rejects a date permitted by a calendar “3 months” interpretation. Keep an out-of-window post prepared locally at its intended date; do not shift the release to make it fit. The helper's default 90-day window is advisory, with boundary dates marked `check_live_composer`; the current composer decides. **Saved** alone does not mean scheduled. Queue badges can be stale, and lists can be virtualized: scroll and verify the actual cards/IDs, content, and times.
- Native content edits must preserve the intended date and links, then read them back. Literal `.md` filenames may autolink to unwanted domains in LinkedIn; use plain wording such as “AGENTS file” when the filename is not intended as a link. Preview the resulting links in the actual composer.
- If an upload or save outcome is uncertain, inspect inventory by stable ID before retrying. Historical past-dated records call for a live recheck, not an automatic unpublish or date change. Create timers or recurring publishing maintenance only when explicitly requested. When the user authorizes that scope, a future website media handoff can trigger publishing and review of eligible deferred posts instead.

## LinkedIn article controls

Observed October 2, 2026; recheck in the current account:

- The article editor can remember a newsletter as its destination. Select **Individual article** when that is the intended format; verify the author and destination before entering the reviewed copy.
- The article scheduling dialog rejected an out-of-window date with **Select a date within the next 3 months** and disabled **Next**. An ordinary-post dialog separately used **90 days**. Treat these as separately observed controls, not proof of identical boundary arithmetic; test the intended date in the actual flow.
- A rejected schedule can still leave an autosaved article under **Manage → Drafts**. Record its native ID and draft state, then resume that record when eligible instead of creating a duplicate. **Scheduled** is a separate tab and requires the saved date/time readback.
- The article caption can disappear across the date-selection transition. Read it back and restore the reviewed copy if needed before the final schedule action. Preserve existing scheduled articles while checking a different draft.

## Read-only queue check

From this skill folder, run `python3 scripts/inspect_queue.py <ledger.json> --as-of YYYY-MM-DD [--horizon-days 90]`. The ledger uses a `timezone` and an `items` object keyed by release ID, with platform IDs, URLs, states, and aware `*_publish_at` timestamps. The script uses only the Python standard library, reads only the supplied ledger, and emits compact JSON. Actual invalid input returns nonzero; same-platform date collisions and past records are warnings. Counts preserve the recorded state exactly and do not infer scheduling from dates or pending checks. Candidate dates use the declared zone and an explicit local-midnight as-of date, not the current clock; missing LinkedIn dates remain missing. All candidate eligibility requires `check_live_composer`. Tests: `python3 -m unittest discover -s scripts/tests`.
