# Instagram action and readback boundary

Read only for an authorized Instagram publish, schedule, profile edit, comment, reply or one-person DM. The Studio's writing, research, planning and profile methods prepare useful material; installing them does not connect an account or authorize an external action. Keep the existing Social Publishing workflow and current conversation authorization. Preserve draft-only and human-review holds; do not repeat approval for a concrete action already authorized.

## Verify the actual surface

Identify account, requested operation, final text/media, recipient or post ID where relevant, visibility, accessible fields, and schedule/timezone if supplied. Check current native app or existing connector capabilities. A social preview tool is not a publishing provider. Do not introduce an unofficial automation service, scraper, credential store, posting bot, DM campaign, account-type conversion or developer app as a side effect.

Official Instagram APIs exist for eligible accounts and approved permissions, but a copied skill does not supply those permissions. Do not repeat the upstream blanket claim that every third-party route is prohibited or that every API setup requires the same account linkage. Account types, login flows, permissions, format support and quotas must be checked against current official documentation and the actual provider. Installation, authentication, action authority and successful operation are separate states.

## Prepare and act

1. Apply the exact final prose, source, privacy, rights and accessibility checks. Confirm any resource promised by a keyword response exists and can be delivered to that recipient.
2. For Reels, inspect final media, cover, captions, sound/rights, crop, native overlays and disclosures. A timed script is not a rendered video. For carousels, verify file order, each crop and supported per-image accessibility. For Stories, verify actual sticker/link controls and audience; supplied copy does not create a functioning sticker.
3. Resolve limits in the current composer or official provider documentation when they matter. Caption text-window simulations do not prove native truncation. Do not reuse a cached hashtag cap, field limit or safe-zone rectangle as universal policy.
4. For a scheduled action, reconcile the existing queue and the account's timezone. Keep candidate, reservation, saved draft and native schedule separate. Do not silently convert a future schedule into an immediate post if scheduling is unavailable.
5. Perform only the concrete authorized action. A single reply does not authorize contacting everyone who liked a post. User-requested native profile edits use exact field values; a recommendation to archive/delete/pin content is not itself authorization.

## Read back and reconcile

Read the native record after the action: account, content, ordered assets, visibility, post/message or profile identifier, scheduled time/timezone when applicable, and URL where available. A schedule is not public release. For a comment/reply/DM, match the actual destination and text; sent is not received or read. For a profile change, verify each changed field and destination. For visual changes use observed before/after anchors and the current rendered viewport.

If receipt or network state is uncertain, inspect the native record before retrying to prevent duplicates. If no eligible provider exists, return the finished payload and the specific missing capability. Do not claim a working Instagram connection from methods or files alone. Keep all account data and receipts in the owning project.
