# Social preview

Render or review a social post mockup through the Studio’s Social Post Previewer app, using supplied assets or requested generated imagery.

## Complete procedures to load

Read the task-matching files below in full before applying that procedure. Load only the relevant variant and its required support. These contain the operative methods, examples and templates; this entrypoint does not replace them. A plugin is a package, not a requirement to read every skill.

- [Full app workflow](../social-content/references/social-post-preview.md) — read only when rendering or inspecting a visual post preview.

## Workflow

1. Read the full preview contract and verify the current app’s supported platform and input route.
2. For newly generated imagery, generate first and use the exact returned asset in the generated-preview call. For supplied assets or explicit text-only content, use the ordinary preview route.
3. Inspect the actual rendered mockup for text, crop, hierarchy and source accuracy; correct material issues within the request.

## Deliver and verify

Show the actual preview or explain the specific provider limitation. Preview is neither scheduled nor published. Do not silently use another platform layout.

## Example boundary

Good: preview supplied Instagram content using its actual image. Bad: preview LinkedIn by passing an unsupported platform value.

Private voice samples, accounts, calendars and analytics belong in the user’s project. Current authorization governs external actions; a request to draft does not authorize posting. Use Research Studio for live social evidence and Marketing for strategy/SEO. Do not claim engagement outcomes without measured data.
