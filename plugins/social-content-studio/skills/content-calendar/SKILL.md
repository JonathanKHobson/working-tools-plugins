# Content calendar

Plan a social content matrix or calendar from evidence-backed pillars, source objects, cadence and review status.

For an ongoing multi-channel workflow, read [connected publishing](../../references/social-methods/publishing-ecosystem.md). For analytics, conversation review, topic discovery or recurring account operations, read [account learning](../../references/social-methods/account-learning.md). Reconcile native queues and existing career/project activity before assigning dates; a reservation is not a native schedule. Keep measured feedback and private contact preferences in the owning project.

## Workflow

1. Identify audience, goals, channels, source inventory and realistic cadence.
2. Use the complete matrix procedure to create specific ideas; map each to proof, format, owner and state.
3. Sequence the calendar around real assets and deadlines; leave unsupported claims or missing proof visible.

## Deliver and verify

When turning a supplied posting request into calendar fields, extract platform, requested time with timezone if supplied, topic, asset requirements and missing information. Preserve the source phrase for each field. Post Metadata Extractor is an optional external helper, not a scheduler; compare its results against the original because it can omit explicitly stated fields or absorb timing into the topic. Use direct extraction when it is absent or incomplete. Do not infer a posting time or claim a schedule from an extraction result.

Deliver an actionable matrix/calendar with dates or cadence, source links and review/publish states.

## Example boundary

Good: a specific post title tied to a shipped demo. Bad: fill every day with generic “thought leadership”.

Private voice samples, accounts, calendars and analytics belong in the user’s project. Current authorization governs external actions; a request to draft does not authorize posting. Use Research Studio for live social evidence and Marketing for strategy/SEO. Do not claim engagement outcomes without measured data.

When the calendar includes a batch of related recording excerpts, use [clip batch review](../../references/social-methods/clip-batch-review.md) before placing them. Keep intentional reuse visible and do not mistake an accepted candidate for a native scheduled post.

For LinkedIn weekly planning (li-plan), read [LinkedIn planning](../../references/social-methods/linkedin-planning.md). For a postmortem or supplied analytics (li-audit), read [LinkedIn performance](../../references/social-methods/linkedin-performance.md) and use the local metrics helper for reliable arithmetic. Existing calendar/queue and project cadence remain authoritative.

When assessing platform coverage, use the [coverage map](../../references/social-methods/platform-coverage.md); apply the selected [platform cycle](../../references/social-methods/platform-content-cycles.md) for planning and measured learning. This adds no schedule or new channel runtime.
