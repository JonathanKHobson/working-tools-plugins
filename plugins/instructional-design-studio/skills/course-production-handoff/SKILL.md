# Course Production & Handoff

Treat course production as inspectable assets with distinct states. Use the relevant [production guide](references/production-guide.md) section for platform packaging, operational readiness, or maintenance; its dated Coursera patterns are conditional, not universal requirements.

For scripts, exported lesson clips, transcripts, learner downloads, and lesson-page integration, use [course media integration](references/course-media-integration.md). It extends this register with clip/chapter and course-revision evidence; it does not require a new workflow or authorize publication.

For an LMS package or delivery request, use [target LMS adapter and learner test](references/target-lms-adapter.md) with the existing production register. The worksheet is unconfigured until a real target and current specification are supplied; authoring it alone does not establish live compatibility.

For course exercise files needing problem, solution and explainer variants, read [exercise packaging](references/exercise-packaging.md). Reuse current IDs, directories and tools, then verify the actual learner package.

## Prepare the package
Confirm the destination, source version, learner environment, and deliverables. Build a compact asset register linking each objective to scripts, recordings, slides, practice files, answer keys, transcripts, captions, and assessments. Record owner/reviewer, rights/access, version, and current status.

Pilot one representative task end to end before multiplying a fragile pattern. Verify that learners can get the materials, follow the instructions, recognize success, and recover from the likely failure. An internal checkmark or a rendered HTML file is not proof of an LMS import or a successful learner launch.

For dependencies that determine readiness, record the condition, owner status, due point, evidence, and fallback. Include facilitator preparation and time to use the skill when relevant; an uploaded asset alone does not establish implementation readiness.

For SCORM/xAPI or other LMS requests, inspect the target specification and available tooling. Produce only the requested package; verify launch, scoring, completion, resume, and accessibility in an appropriate test environment before claiming compatibility. If the environment is unavailable, return the package and an explicit untested handoff checklist.

## Deliver
Return production-ready assets within the authorized scope, the asset register, review findings, and exact remaining delivery dependency. Publishing, enrollment changes, account creation, learner messaging, and private-data uploads require applicable authorization at the actual step. Do not interpret “make a course” as permission to deploy it.

When external tools are unavailable, provide usable source assets. Do not install a toolchain just to produce a checklist. For updates record what source or interface changed and the affected lessons, then recheck those lessons rather than redoing the entire course by default.
