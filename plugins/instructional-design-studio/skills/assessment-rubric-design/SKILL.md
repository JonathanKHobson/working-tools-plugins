# Assessment & Rubric Design

Start with what the learner must demonstrate and what decision follows. Retain supplied outcomes, standards, institutional rules, and allowed aids. Infer routine context; ask only when a missing condition would change the key, evidence, or intended use. A short knowledge check needs a usable task and feedback, not a full course redesign.

Keep purpose (diagnostic/formative/summative), response format, cognitive demand, context, comparison basis, conditions, and stakes separate. A scenario is a context, not a response type. Cognitive demand is not observed difficulty. Recall can be a legitimate target or retrieval practice; it cannot stand in for an untested performance.

## Design evidence before scoring

Apply [learning beyond the activity](../instructional-design/references/addie-decisions.md#preserve-learning-beyond-the-activity) to tasks and scoring: elicit the intended understanding or capability, including procedural judgment when relevant, rather than crediting story or artifact completion alone.
Use claim → evidence → task → response → scoring → feedback → validation as a practical authoring sequence, not a validated named model. For a bank or consequential assessment, blueprint outcome coverage before generating items. For one item, keep the same reasoning compact. Map each task and rubric dimension to an outcome and state the inference limit. A performance outcome needs performance evidence; a cognitive verb alone does not establish rigor.

Draft task, key/rubric, source support, feedback, and retry together. Use stable item and option IDs, source versions and precise locators; retain conflicts instead of inventing authority. Label fictional teaching facts. Keep accepted alternatives and disqualifying contradictions explicit. Missing/unobserved evidence is distinct from demonstrated incorrect performance. Do not score speed, spelling, accent, camera use, confidence, or visual polish unless part of the construct.

Set weights by importance, not equal distribution by habit. State the maximum score and any threshold; justify a proposed threshold and mark it provisional until reviewed. Do not present 80% as a universal mastery rule. Critical errors may need a separate retry condition rather than being averaged away.

## Challenge the draft
Try to disprove the key: find a second defensible answer, a wording shortcut, an unsupported fact, an answer leaked by another item, or an irrelevant barrier. For multiselect, state selection and scoring rules and test selecting all/none. For rubrics, score strong, partial, flawed, and crossed/mixed samples; use mutually exclusive observable bands plus an unobserved state. Calibrate human raters with evidence and a disagreement process. AI feedback remains evidence-linked and reviewable in proportion to stakes.

For a JSON bank, use the bundled read-only checker described in [the authoring contract](references/item-authoring.md). Structural success does not establish key correctness, validity, reliability, fairness, or learner understanding. Report review and pilot status separately; use [quality and validation](references/quality-and-validation.md) to plan the missing evidence.

Return learner directions/task, an author-only key and scoring guide, alignment, feedback/retry, a scored example when useful, and actual review/pilot status. Keep keys out of learner exports when confidentiality matters. Embedded answers in a standalone practice file are inspectable; it is not a secure exam system. Preserve learner privacy. Authoring does not authorize administration, grade changes, publication, or sending results.
