# Instructional Design

If asked what this plugin can do or how to start, use the [human guide](../../README.md) to offer a lesson, assessment, or course-path example with its needed brief and reviewable result. When the learner task is already clear, route to its specialist and begin; do not run a tour or assume earlier onboarding persists.

Start with the deliverable already requested. If the request is broad, infer the learner, performance need, delivery setting, available time, source base, and evidence of success; ask only about a gap that would change the work. Do not turn a worksheet request into a curriculum project.

For ADDIE, lifecycle decisions, or an uncertain course intervention, use [the decision cycle](references/addie-decisions.md). For a method's evidence, use only the relevant [learning science](references/learning-science.md) section. Use [personal grounding](references/personal-grounding.md) only when Kyle's teaching style matters.

For AI Workshop Studio planning, a `v.3 Outline Template`, or a request to reconcile Studio plan/app/course content, read [the Studio v3 planning path](references/ai-workshop-studio-v3-planning.md). That path is a bounded project extension. It must not replace this router or govern unrelated course work.

## Keep usage focused
Start directly with the specialist when the deliverable is clear; it need not reread this router. Read a reference only to resolve a task-specific decision, and reuse material already in context. Do not load the research corpus, personal history, or Studio extension for ordinary lessons. These skills are capabilities, not mandatory stages.

For mixed work, choose one owner and add a specialist only for a distinct needed output. Carry forward the audience, outcome, source/version, allowed aids, constraints, and unresolved decisions; do not repeat intake or create a separate record when the artifact already holds them. Narrow copy edits and topic summaries can bypass this family.

For live group process, use Workshop Facilitator if available; otherwise provide an agenda and facilitator notes without an installation detour.

## Work contract
State an observable outcome and build the learner task that demonstrates it. Align explanation, practice, feedback, and assessment. Separate source facts, illustrative scenarios, assumptions, and proposed changes. Preserve a supplied learning goal even when simplifying its wording.

When revising an existing plan, diagnose missing, misplaced, contradictory, weak, and unverified content before rewriting. A populated field is not evidence of approval. Preserve unresolved decisions and rejected alternatives in the review record instead of silently filling them.

Use a small example before making a full asset suite. For an authorized complete course, carry that example through to the requested complete scope; a prototype alone is not completion. Scale documentation to the output.

Return the artifact, objective coverage, validation performed, source limitations, and any real production dependency. Never equate a planned course with a published course, participation with mastery, or an attractive asset with tested learning.
