# Access review by learning task

Use this reference to inspect a real artifact. It is not a certification checklist.

## First preserve the construct
Name what is essential. If learners must reason from evidence, make the evidence readable and allow equivalent expression. If they must demonstrate a physical procedure, an essay alone may not suffice; arrange an accessible authentic demonstration with the responsible educator.

## Checks
| Surface | Inspect | Useful evidence |
|---|---|---|
| Document | Heading order, readable type, table headers, meaningful links, image alternatives, logical reading order | Rendered pages plus structural or assistive-technology check |
| Video | Accurate captions, usable transcript, visibility of task states, descriptions of essential visual actions | Playback at relevant moments; captions checked against speech |
| Interactive lesson | Keyboard operation, focus visibility, labels, error recovery, zoom/reflow, contrast, timing controls | Actual interaction, not screenshot alone |
| Workshop | Room access, hearing and visual access, processing time, contribution alternatives, breaks | Setup check and explicit participation options |
| Assessment | Equivalent evidence, avoid irrelevant speed/language demand, accessible submission | Test the alternative against the same objective |
| Low bandwidth | Offline instructions, small files, reconnect path, no mandatory video | Open files and complete sample task offline |

For web-specific numerical criteria consult the current W3C source linked in the main learning-science reference. Avoid presenting an incomplete checklist as a full WCAG audit.

Describe essential visual meaning, not merely the presence of an object: “The reviewer chooses a rating before recording supporting evidence” communicates a relevant action; “as you can see here” does not. Plan this with the script where possible. [W3C description of visual information](https://www.w3.org/WAI/media/av/description/).

## Language and culture
Explain unfamiliar terms with concrete examples. Preserve correct technical vocabulary when it is a learning target. Avoid idioms where they create unnecessary language burden. Represent varied contexts without stereotypes. Do not make disclosure of diagnosis, trauma, or identity the price of participation.

## Report format
Anchor or source locator → affected learner action → observed barrier → proposed change → equivalent success criterion → verified/unverified. Prioritize blockers to beginning or finishing the task before decoration.

## Example
A drag-only sorting exercise assesses classification, not dragging. Provide keyboard-selectable category controls or a plain table alternative. Confirm that both routes expose the same cases and feedback. Do not remove the classification challenge while solving the input barrier.

## Shared-board participation check

For a facilitated visual canvas, check whether a participant can identify the current task, find its input, contribute, tell when that step is complete, and understand the next use of the contribution. Offer a route that does not require precise dragging: an agreed text channel, a suitable response field, or a scribe who reads back the recorded contribution. Passing is valid when participation in that particular prompt is optional. Keep any text companion aligned with the actual board's purpose, route, prompts, decision or completion rule, contribution options, and resulting record; do not let it promise a step or output the board lacks. Preserve original wording and stable IDs when a facilitator transcribes or synthesizes responses.

Rehearse the chosen route with the actual board, role, device, browser, and assistive technology when available. Record observed access and navigation findings separately from evidence of learning. A product's documented capability or an untested checklist does not verify screen-reader, keyboard, or collaborative behavior for this artifact.
