# Application statements

Use this skill when an application asks for a personal statement, statement of purpose, motivation letter, scholarship or program essay, or a substantive short answer. Employment cover letters belong to this plugin's `cover-letter` skill; campaign packet coordination belongs to `campaign`; form execution and receipts belong to `submissions`.

Start with the exact prompt, audience, limits, evaluation criteria if published, and applicable rules on AI assistance. Identify which facts come from the applicant, which program/job facts are verified, and what material answer remains unknown. Ask for a missing personal fact only when it changes the requested response; continue with supported sections. Do not invent experiences, research interests, adversity, personal motives, eligibility, program details, metrics, or future commitments. Preserve the applicant's natural voice and any important qualification.

For an admissions, scholarship, or volunteer statement, read [statement shapes](references/statement-shapes.md). A program motivation letter is not simply a reformatted employment letter. For a job form's screening question, answer that question directly, then add concise proof if requested or useful. Keep the question paired with the answer and its source/user confirmation; a bare yes/no answer must never migrate to another form. Sensitive disclosures and demographic fields are the applicant's choice. Do not infer work authorization, salary, availability, relocation, or license status.

Check prompt coverage, exact word or character count, consistency with resume and portfolio, truthful program/job fit, and the applicant's ownership of the story. Remove bracketed drafting notes before a share-ready answer. If the destination is a document or PDF, use the [output providers](../../references/providers.md) and inspect the rendered file. A drafted answer is not a submitted application; hand execution to `submissions` when authorized.
