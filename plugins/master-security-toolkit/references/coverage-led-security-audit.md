# Coverage-led source audit: conditional host adaptation

Trigger only for a specifically requested **multi-surface source security audit** where a coverage ledger and independent confirmation of candidate findings would improve the outcome. Keep the existing [scoped application review](application-security-testing.md) as the default for focused reviews, API questions and fixes. This route adds the full [Cloudflare security-audit method](../libraries/cloudflare-security-audit-original/skills/security-audit/SKILL.md), including its reconnaissance, hunting, attack-class, validation/reporting, schema and validator files. Read all files selected by that method for the actual target, not just this adapter. The original MIT license is preserved with it.

Use the original guidance and its `coverage-ledger.json`/`findings.json` state discipline: record each in-scope surface, each untested surface and each candidate's observed status. A source path can support a hypothesis; `confirmed` requires the original method's bounded observed result and independent verification. A blocked test stays `needs_validation` with the exact missing condition and no severity. Do not call an incomplete or partially covered run a comprehensive audit.

**Host gate:** Before any target-controlled build, test, process, browser, emulator, fuzzer or fixture processing, verify the original method's full OS-enforced sandbox contract: disabled external networking, sanitized allowlisted environment, resource limits, scratch-only writes, isolated agent paths and trusted artifact promotion. This host's `danger-full-access` shell does not supply those controls. Without a verified sandbox, do source-only review and retain validation as unresolved. A permission question or user approval does not substitute for containment. Do not silently run target code, fetch dependencies, access live targets or upload private source.

The preserved `validate-findings.cjs` and `validate-coverage-ledger.cjs` are admitted as **bounded local JSON-record validators**. Their full code and synthetic tests were manually reviewed: the validators import only Node built-ins, open one local regular file without following symlinks, cap input at 5 MiB, decode UTF-8 strictly, and emit diagnostics without writing files, running target code or using the network. The reviewed tests create only synthetic temporary records and invoke these two validators; `node --test validate-findings.test.cjs validate-coverage-ledger.test.cjs` passed 65/65 tests. Use them only on local audit records, then have an independent reviewer check the evidence and final report as the original method requires. These tests establish helper behavior, not completion of an audit. Target-controlled dynamic validation remains held behind the verified sandbox gate above.
