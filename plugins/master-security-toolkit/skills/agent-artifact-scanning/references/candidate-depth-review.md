# Conditional context and trigger check for agent artifacts

Use only when a candidate skill/plugin can **retain or re-inject model context**, or can **run later without a direct user request**. The existing agent-artifact-scanning adapter already covers MCP metadata, scripts, dependencies, reachability and line-level adjudication; use it first. The eight local deterministic rules do not detect memory poisoning or a cross-file trigger-to-effect chain.

For the specific retention or trigger path, record: (1) exact hook/scheduler/tool entrypoint and when it runs; (2) untrusted source text or metadata collected; (3) storage location, retention and any provider/network transfer; (4) how stored content returns to a later prompt, tool call or file mutation; and (5) the user-visible control and an unexecuted synthetic test case with a benign item plus a hostile instruction. Keep test cases as data during static review; candidate execution belongs only in a separately authorized isolated evaluation. Cite each file and line that connects input to effect. Distinguish observed code from inferred behavior and name files or dynamic paths not inspected. A matched word, static score or clean scan is not proof of safety.

This original checklist was prompted by [NVIDIA SkillSpector's declared memory-poisoning and trigger-abuse categories at commit `2226747e4ca97198bb82faf5085b8a75f2e1dc02`](https://github.com/NVIDIA/SkillSpector/blob/2226747e4ca97198bb82faf5085b8a75f2e1dc02/README.md). No upstream rule, code or procedure was copied. It adds a manual route, not a detector, runtime integration or permission to send candidate text to an external model.
