# Local operation

Use a local model when the task benefits from local data handling, low marginal cost or a bounded offline transform, and when the model has demonstrated useful quality for that task family. Keep the lead responsible for scope, source provenance and acceptance. A model being downloadable or hardware-compatible does not establish quality.

Read [CLI operation](references/cli-operation.md) for loading and unloading rules. Read [task fit](references/task-fit.md) when selecting a model or assigning work. Read [benchmarking](references/benchmarking.md) when producing comparative evidence. Read [computer use](references/computer-use.md) only when a CLI path is unavailable or the user specifically requests UI operation.

## Route deliberately

- Use a small local model for reversible extraction, classification or formatting only after a representative test passes.
- Use a larger local model for synthesis, coding or nuanced writing only when memory and latency remain acceptable and its task rubric passes.
- Keep research requiring fresh sources, external tools, private account access or consequential judgment on a provider with those verified capabilities.
- Do not treat local models as substitutes for Claude, Gemini or Codex merely because they share a task label.

Before delegation, state the task, supplied evidence, output contract, context/output bounds, allowed side effects and stop condition. Verify the output against the rubric and record the actual model, variant, runtime, context, duration and failure state.
