# Task fit

Select by measured capability rather than parameter count or a staff-pick label. Start with these hypotheses, then confirm with the benchmark reference:

| Task family | Acceptance evidence | Common local-model risk |
| --- | --- | --- |
| Structured extraction | required fields, qualifiers and unknowns preserved | invented dates or dropped negation |
| Capability synthesis | source facts and limits retained | plausible unsupported claims |
| Constrained handoff writing | requested facts, tone and state claims obeyed | accidental approval or send claims |
| Small code review | correct patch and concise rationale | superficially plausible bug fix |
| Empty-result validation | failure mode and narrow check identified | broad refactor or false certainty |

A model can be useful for one family and unsuitable for another. Record “tested,” “provisionally useful,” “not useful,” or “untested”; do not promote a model to a default from a single success.
