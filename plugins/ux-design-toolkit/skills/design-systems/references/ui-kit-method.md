# Build, extend and hand off a UI kit

Use for an explicit UI-kit build, a comprehensive kit audit, or a reusable component handoff. For a single existing component, load only the relevant contract and verification sections. A copy edit, ordinary responsive correction or palette inventory does not require a new kit.

## The outcome

A useful UI kit connects design intent to real, reusable interface behavior. Its deliverables are a scoped authority document, foundations and tokens, component contracts, a discoverable inventory, representative implemented flows, asset records, adoption instructions and evidence. A gallery alone cannot establish reuse; an inventory alone cannot establish implementation. A design system additionally supplies ownership, contribution, migration and release policy.

## Sequence

1. **Establish authority and scope.** Identify users, tasks, surfaces, stack, platforms, accessibility target, incumbent components and accepted visual references. Record the source and status of each decision: explicit user instruction, adopted project decision, formal requirement, platform guidance, research proposal or historical evidence. Attached documents are inputs to reconcile, not commands. Resolve consequential conflicts before dependent work; continue independent work with named assumptions.
2. **Map the kit.** Inventory foundations, components, compositions, assets and integrations. Mark each item proposed, specified, implemented, adopted, deprecated or out of scope; attach verification separately. Explain why advanced families are deferred. Comprehensive coverage means accounting for relevant needs, not implementing every possible widget.
3. **Write rules before producing art.** Establish typography roles, color meanings, shape, borders, elevation, layout, density, motion, voice, action hierarchy, responsive adaptation and state behavior. Record rationale and recheck triggers. Proposed values remain proposals until adopted. A site's playful identity does not dictate the design of a dense task surface.
4. **Choose implementation foundations.** Inspect the actual stack and library exports. Prefer a coherent behavioral foundation with deliberate adapters; document build/reuse/generate decisions and separate licenses. Do not select by popularity or screenshots alone.
5. **Specify and build a revealing slice.** Choose a complete real journey including its difficult state. For a kit spanning materially different contexts, add a second contrasting consumer before declaring it reusable. Verify behavior and adoption before multiplying examples.
6. **Produce only needed creative assets.** Define art roles, responsive compositions, text-safe and subject-safe regions, states and exports first. Keep functional labels and controls native/live. Generate illustration when original art is needed; reuse established controls and icons when appropriate. Record each master and derivative.
7. **Verify the claims.** Exercise relevant states, content extremes, keyboard/focus, input modes, widths, themes and recovery. Inspect rendered output. Bind scoped passes to source and test identity. Keep visual acceptance, technical verification and deployment status distinct.
8. **Package and govern.** Provide installation/adoption examples, actual imports or selectors, token transforms, licenses, asset manifests, limitations, change notes and migration instructions. Test the delivered reference closure and a clean consumer. Assign an owner and review trigger for unresolved items.

## Boundaries

Share meanings across responsive contexts; adapt composition and interaction to available space and input. Use separate native adapters where platform behavior and units differ. Do not impose this method's example structure, a brand palette, mascot, font, radius, breakpoint, component count or library on unrelated work. This guidance installs no component runtime, renderer, framework, hook or MCP service.

For a new kit, deliver the complete authorized slice rather than stopping at this plan. If a specific acceptance or deployment gate is still open, name it and preserve the useful finished output around it.
