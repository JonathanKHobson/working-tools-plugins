# Design Studio

For an authorized interface review involving a user flow, recurring usability issues, or release/handoff evidence, proactively consider `ux-heuristic-compass` without requiring its name. Use a bounded tool-backed triage when it fits the requested review, and briefly state what it contributes. Offer the formal rubric, grades and report when that depth would help the decision; infer neither a complete audit nor a score from ordinary polish. Routine isolated edits stay in this workflow.


For “what can UX Design Studio do?”, setup or getting-started help, read the capability, first-task and setup sections of the [plugin introduction](../../README.md) and recommend one relevant first task; skip maintainer notes unless updating the package. Help alone does not start a diagnosis, scan, audit or external action. For a concrete request, use the matching procedure below without loading the whole plugin.


For a bounded interactive widget embedded in a product, chat or side panel, read [widget UX guidance](references/conversational-widgets.md) to choose the task, interaction model, states and evaluation. Apply its conversation-continuity guidance when the widget participates in a conversation. For library options presented for human choice inside chat, also read the [compact library chooser pattern](references/mcp-app-widgets.md). Build MCP owns protocol and supported host capabilities; AI-only backend retrieval stays separate from human-facing presentation.

For motion graphics within a requested website or Sites build, use [motion prompts and Sites handoff](../motion-and-performance/references/motion-prompts-and-sites.md) alongside the chosen provider. Consider one purposeful motion moment; preserve the brief rather than adding animation by default. Graphic Design Studio supplies visual direction when needed.

For a product surface containing charts, scales or trait scores, apply the [reader-comprehension gate](../dashboard-design/references/delivery-and-qa.md#reader-comprehension-acceptance): default to lay readers, accurate everyday labels, meaningful ends and middle with numeric ranges, distinct upfront questions, compact familiar layout, a named details button and ordinary web reading text at least 16px. Preserve uncertainty and distinguish targets from observations. Model agreement cannot establish empirical validity. This gate is a bounded review within the current task, not a dashboard rebuild.

Identify the single user outcome and the surface before choosing a mode. **Audit** produces findings from observed evidence; it does not edit unless fixes are requested. **Concept** resolves a visual direction or interaction approach. **Implement** makes the authorized change in the owning artifact. **Verify** checks the rendered result, interaction, and delivery state. A task can pass through several modes in one turn; do not require a concept ceremony when the brief and source already settle the design.

Go directly to the specialist for copy-only work (`ux-writer`), formal scored audits (`ux-heuristic-compass`), dashboard hierarchy and customization ([dashboard-design](../dashboard-design/SKILL.md)), an explicit Stitch UI/export/library task ([stitch-design](../stitch-design/SKILL.md)), chart meaning or correctness (`data-visualization-toolkit:data-visualization`), an explicitly named provider such as Sites or Graphic Design Studio, UX research/design-review follow-up communication, or framework selection (`pattern-picker`). Bespoke web chart code can still use the installed Build Web Data Visualization specialists. Asset-heavy work uses the [asset integration library](../../libraries/visual-asset-integration/SKILL.md) only when needed. Consult [provider boundaries](references/providers.md) only when a handoff is needed. A draft, local preview or review request stops at that requested stage; an authorized publish request continues through the provider's delivery verification.

Read only the relevant reference: [review](references/review.md), [product and web](references/product-web.md), [Figma and Stitch](references/figma-stitch.md), [shared graphic principles](references/graphic-design.md), [UX writing](references/ux-writing.md), [data visualization](references/data-visualization.md), [verification](references/verification.md), [device and application routing](references/device-routing.md), [spreadsheet usability](references/spreadsheet-usability.md), or [providers](references/providers.md). Teaching and game design are outside this skill. Graphic Design Studio remains a separate production specialist; a poster-only task can go straight there.

For unresolved audience/problem assumptions, use [research inputs](references/research-inputs.md). For competing interaction directions or optional simulated task perspectives, read [decision alternatives](references/decision-alternatives.md); it keeps hypotheses distinct from observed user evidence and routes independent work to the existing Work Management owner. Survey construction belongs to the separate Survey Studio plugin: use `survey-strategist` for survey design, implementation and exports. Keep interaction and rendered review here; do not duplicate its survey engine. For an actual type or brand decision, use [typography and brand](references/typography-brand.md). These are conditional inputs, not prerequisites for a routine UI change.

For a fuzzy first app idea or an existing app experience that has lost its throughline, use [beginner app planning and checkup](references/beginner-app-planning.md); load its deeper Vibe Check library references only for the relevant question.

When the user asks to learn from a named website's visual language for another design, use [reference-site analysis](references/reference-site-analysis.md). It turns observed composition and supported style values into a bounded transfer brief. A mentioned URL alone does not activate it; the user's design question sets the scope.

For the layout or review of a collaborative whiteboard, use [collaborative board hierarchy](references/collaborative-boards.md). It covers one clear active task, evidence on demand, comparisons, and laptop-scale QA. Figma Studio owns editor execution; Workshop Facilitation owns the group process. Do not turn a requested board into a website or force a full workshop design onto a narrow visual correction.

For broad UX method choice or research framing, the [UX Oracle library](../../libraries/ux-oracle/SKILL.md) retains the full source method and examples. For a substantial frontend design implementation, use the [frontend UX library](../../libraries/frontend-ux/SKILL.md); for a focused final craft critique, use the [design taste library](../../libraries/design-taste-gate/SKILL.md). These are conditional depth sources under this entrypoint, not separate default routes.

For a maintained system needing inventory, extraction or migration, use [design system evolution](references/design-system-evolution.md); a routine small fix does not need it. For onboarding/first-value flows or robust-state work beyond default/error/accessibility basics (malformed data, interrupted or stale async actions, retries, recovery), use [interaction resilience](references/interaction-resilience.md). For added or changed motion, or a reported/suspected performance problem, use [motion and performance](references/motion-performance.md). For adapting a surface across device, input, orientation, safe areas or locale beyond responsive shrinking, use [context adaptation](references/context-adaptation.md). Each is conditional: load only the one the current task needs.

When the task calls for the native detector, advisory design hooks, local live variants, or a native palette/font/component utility, load [native design runtime](references/native-design-runtime.md). It routes the pinned engine and licensed playbooks through the owned adapter; ordinary design judgment does not need the runtime.

Start from current task evidence. Name the authoritative source for content, appearance, behavior, and constraints. When sources disagree, record **Change / Keep / Defer** before editing. Inspect the owning project and related prior designs in source and rendered form before designing or implementing an adjacent surface. Map the shared components, tokens and interaction rules, and name only the differences the new task requires. Reuse existing code and styles where they fit; preserve approved content and behavior outside scope. If related designs are inaccessible, state the evidence gap rather than inventing continuity. An explicit request for a new visual direction can change the mapped conventions within scope. For a visual judgment, capture 3–8 anchors with source, viewport or page, region, observed fact, and intended action. Recheck anchors affected by the change.

For implementation, make the smallest coherent change that delivers the outcome. Make the primary action recognizable at a glance; people should not have to read surrounding instructions to discover it or prose to learn whether it worked. The invoking control itself should acknowledge a click with a distinct pending, confirmed success, unchanged/already-done, or error/retry state as applicable; nearby status copy can add detail but cannot carry the whole result. Use a short state label and recognizable icon alongside color, with a screen-reader equivalent and reduced-motion behavior. Preserve meaningful control labels, consequence copy and consent. Check meaningful states, keyboard access, responsive layout, and clear copy as applicable. For a new or changed entry/action path, exercise the intended journey from an unseeded first visit through the server-confirmed outcome; inspect the clicked control itself after a first click and a repeated or no-op click, then record visible pending, success, and failure evidence or mark any unexercised state. Never imply success before the authoritative outcome. Use a bounded rendered review, correct material defects, and verify the changed path. Report observed checks separately from inferred or untested behavior. Distinguish draft, attached, submitted, generated, exported, implemented, published, and verified.

This skill supplies judgment and routing. It does not replace specialist Figma, Stitch, browser, asset, print, or code workflows. Discover and read the current provider skill before calling its tools; a catalog entry or file inventory does not prove that a provider is callable.

For delivered design artifacts and templates, maintain a concise source-grounded `DESIGN.md` using [the existing design specification contract](../design-systems/references/template-design-contract.md). A template's `SKILL.md` links it, and its bundle retains all linked support. Keep routine changes proportional by updating the incumbent specification; do not create a new brand system or extra UI to document an existing design.

For image-led production of a website/product still, poster, document illustration or storyboard asset, use `graphic-design-studio:graphic-design`, which now owns the complete Visual Production Workflow. Load that full source and its asset/provenance/export checks. This handoff does not replace this skill's UI behavior or motion/audio responsibilities.

For methods inherited from Product Design, Frontend Design Premium, Design Partner, UXCritique or UI UX Designer, select and **read the complete matching procedure** from [this workflow’s source map](../../docs/procedures/design-studio.md), applying its [host adapter](../../docs/full-design-host-adapter.md). Load only the relevant method and required support.

For pointing, carried memory, feedback, interrupted work, consequential error, workload or emotion claims, select and read the complete task-matching card through [human-systems decisions](references/human-systems-decisions.md). This maintained guidance supersedes inherited fixed visible-option caps and checklist-count workload scores; it preserves useful effort and applies accessibility criteria at their stated conformance level.

For a bounded component/detail polish request involving nested corners, optical alignment, icon weight/render size, image edges, text wrapping or transition timing, read the [interface craft adapter](references/interface-craft.md) and its complete task-matching source method. It preserves the existing system and treats upstream values as testable examples, with no automatic runtime or global aesthetic mandate.

## Scoped Atlas reference

For local ux concepts, frameworks, activities or source definitions, read [the scoped Atlas library](../../references/atlas-library.md). Use its relevant-only search and full-source selection before adaptation; human browsing and assistant retrieval share the same source records.

For a new visual direction, a supplied gallery or an unresolved reference question, use [public design resources](../design-reference-lookup/references/public-design-resources.md). Agents can browse Godly, select Transitions.dev examples and route deck/showcase references to their existing owners within the authorized task. Capture observed anchors and original adaptations; preserve approved design and keep the search proportional.

For an explicitly requested browser presentation, PPTX-to-web conversion or existing HTML deck revision, read [HTML presentations](references/html-presentations.md). Native slides remain the owner when that is the requested output; keep browser stage, faithful conversion, notes privacy and actual save/export behavior explicit.
