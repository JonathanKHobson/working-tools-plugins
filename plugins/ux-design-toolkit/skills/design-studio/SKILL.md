# Design Studio

Use this skill to review an interface or coordinate a UX/UI design change from source evidence to a rendered result. Bring the requested user outcome, surface, available source or screenshots, and delivery state. Produce findings for an audit, a resolved direction for a concept, an authorized artifact change for implementation, or observable checks for verification. Match the output to the user's requested stage.

Identify the single user outcome and the surface before choosing a mode. **Audit** produces findings from observed evidence; it does not edit unless fixes are requested. **Concept** resolves a visual direction or interaction approach. **Implement** makes the authorized change in the owning artifact. **Verify** checks the rendered result, interaction, and delivery state. A task can pass through several modes in one turn; do not require a concept ceremony when the brief and source already settle the design.

For “what can UX Design Studio do?”, setup or getting-started help, read the capability, first-task and setup sections of the [plugin introduction](../../README.md) and recommend one relevant first task; skip maintainer notes unless updating the package. Help alone does not start a diagnosis, scan, audit or external action. For a concrete request, use the matching procedure below without loading the whole plugin.

## Shared workflow

For a new surface or authorized redesign with material choices still open, use [product-grounded design direction](references/distinctive-direction.md) before building. Resolve the primary question, domain material, composition and copy from evidence; preserve existing identity and familiar controls. Settled designs and narrow repairs bypass concept exploration. This also applies outside an established brand; absence of a brand is not permission to fall back to a generic layout.

Start from current task evidence. Name the authoritative source for content, appearance, behavior, and constraints. When sources disagree, record **Change / Keep / Defer** before editing. Inspect the owning project and related prior designs in source and rendered form before designing or implementing an adjacent surface. Map the shared components, tokens and interaction rules, and name only the differences the new task requires. Reuse existing code and styles where they fit; preserve approved content and behavior outside scope. If related designs are inaccessible, state the evidence gap rather than inventing continuity. An explicit request for a new visual direction can change the mapped conventions within scope. For a visual judgment, capture 3–8 anchors with source, viewport or page, region, observed fact, and intended action. Recheck anchors affected by the change.

For implementation, make the smallest coherent change that delivers the outcome. Make the primary action recognizable at a glance; people should not have to read surrounding instructions to discover it or prose to learn whether it worked. The invoking control itself should acknowledge a click with a distinct pending, confirmed success, unchanged/already-done, or error/retry state as applicable; nearby status copy can add detail but cannot carry the whole result. Use a short state label and recognizable icon alongside color, with a screen-reader equivalent and reduced-motion behavior. Preserve meaningful control labels, consequence copy and consent. Check meaningful states, keyboard access, responsive layout, and clear copy as applicable. For a new or changed entry/action path, exercise the intended journey from an unseeded first visit through the server-confirmed outcome; inspect the clicked control itself after a first click and a repeated or no-op click, then record visible pending, success, and failure evidence or mark any unexercised state. Never imply success before the authoritative outcome. Use a bounded rendered review, correct material defects, and verify the changed path. Report observed checks separately from inferred or untested behavior. Distinguish draft, attached, submitted, generated, exported, implemented, published, and verified.

For a new branded website, read [website composition](references/product-experience-methods.md#website-and-landing-page-composition), then use [rendered review](references/review.md) and [source comparison](references/design-comparison-qa.md) against the selected brand components.

For authored interface or website copy, apply [UX writing](references/ux-writing.md) for information placement and the final everyday Humanizer handoff.
