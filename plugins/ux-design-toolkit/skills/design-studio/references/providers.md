# Provider routing and boundaries

This skill owns design judgment, scope, and evidence. Current provider skills own their application commands, connector schemas, permissions, and recovery details. Discover the relevant installed skill by name or capability at invocation and read only its entry point and needed references. If it is unavailable, use an available supported route or report the capability limit. A directory listing or skill catalog is not evidence that a tool is callable in this session.

Use the Figma provider skill for Figma MCP calls and its exact design-to-code or edit direction. Use the personal Figma UI operator for direct UI selection and mutation, and [Stitch design](../../stitch-design/SKILL.md) for explicitly requested Stitch browser drafts, submissions, selection, export, or library recovery. For a Figma-to-Stitch or Stitch-to-Figma task, load the appropriate Figma-owned cross-app handoff skill plus the two endpoint operators only as needed. Do not duplicate those mechanics here.

Use the current browser or computer-use skill for observed interactions and screenshots. Use an image-generation skill when new visual assets or an unresolved visual concept would materially help; it is optional for a small existing-system fix. For web implementation, use the owning repository's build and testing workflow. For promotional print production, use the graphic-design and print-preflight specialists. For product microcopy, use the UX-writing specialist. For a formal heuristic assessment, use the formal audit specialist; a quick design review does not require a formal score.

Do not assume a provider's documented capability is exposed, authenticated, or permitted in the current session. Do not claim a result in an external application from a local mockup or exported image. Avoid new runtimes, background hooks, and provider setup unless the requested operation requires them. Preserve specialized deeper workflows as optional dependencies rather than claiming this general skill replaces them.

## Named boundaries

- **Graphic Design Studio** stays an independently invocable specialist. Reuse hierarchy, typography, reading fields and asset provenance in UI; leave campaign copy, compositing and print acceptance with that package.
- **Build Web Data Visualization** owns chart choice, encoding, statistical truth, complex renderers and analytical interactions. Use its narrow specialist for meaningful chart layers; use the [shared visualization guidance](data-visualization.md) to integrate them into the surrounding UI.
- **Sites** owns its setup, project identity, preview and deployment lifecycle. Use it for an explicitly requested Sites task or work on a verified existing Site, and respect an explicit choice of another host or local-only work. Its presence does not authorize deploying an unrelated code change. Read current Sites instructions; do not copy its scripts or invent tool parameters. A successful deployment receipt and a tested user journey are distinct evidence.

  For Sites design work, apply [product and web](product-web.md) and the relevant [system craft checks](system-craft.md) during implementation and review. For new or updated downloads, route file hosting and exact-link verification to `work-management:work-handoff`, reference `references/operations/download-hosting.md`, while keeping page and render assets in Sites. Sites retains its own component, imagery, setup and hosting rules; do not patch its vendor package. When a Sites task explicitly needs mechanical detection or local live comparison, use the existing [UX-owned native runtime](native-design-runtime.md) against that site's authorized project or dev URL, without installing a second runtime in Sites.
- **Build Web Apps** supplies task-relevant framework and testing guidance. Load database, payments or backend-specific material only when those capabilities belong to the request.
- **Build MCP Apps** owns the supported app bridge, resources/tool metadata and host interaction mechanics. UX Design Studio owns the [compact widget design contract](mcp-app-widgets.md). Keep backend-only retrieval separate from user-facing app presentation; verify send/copy and inline/expanded capabilities in the current host rather than assuming native template controls are available.
- **work-management:product-definition** translates a vague idea into a concrete product/engineering task when that is the missing input. It is not a required preflight for a clear request.
- **vibe-check** belongs to broader discovery and systems/requirements synthesis when needed; do not run its entire process for routine UI work.
- **writing-quality-studio:communication-crafter** handles consequential design/research follow-ups using its evidence-based follow-up reference. Source, author and posting-status checks apply when relevant; ordinary short messages can be drafted directly. This route creates no evidence or sending authority.
- **pattern-picker** is for choosing a thinking framework; **design-reference-lookup** is an optional design reference lookup. Neither overrides an approved design system. Use palette/theme tools only when that is the requested target; changing the Codex application's theme is unrelated to styling a website.
- **UX Oracle** is retired. Its useful question-to-method guidance is preserved in research inputs; its historical library is reference only. **UI UX Designer** is not a dependency.

Research methods, market analysis, MyFonts and Infographic Artist are conditional inputs. Use [research inputs](research-inputs.md) and [typography/brand](typography-brand.md) for their boundaries; do not load all of them for ordinary UI work. Their presence in the current tool catalog proves exposure only, not an executed query or an authenticated account state.

For publication, follow the current provider's permitted deployment and verification path. Read back the actual target identity, audience and successful version/URL receipt. Exercise the supported rendered preview or live journey as required by the task. If the provider runtime cannot test the deployed URL, distinguish verified deployment from untested live behavior; do not bypass its browser restrictions or imply that a receipt proves usability.
