# Stitch Component Assets

Follow [Workbench](workbench.md) for access. Start from a specific slot and purpose, not a request to decorate everything.

1. Define the component’s role, actual content, dimensions/aspect ratio, surrounding surface, state set, interaction, accessibility needs, and required output format. Specify desktop and small-screen behavior.
2. Use real source screenshots or existing approved components where available. Keep original evidence unchanged; mark crops and presentation treatments in the asset record. A new mockup belongs to a new-design or reconstruction category.
3. Request a coherent family using the project’s tokens and visual language. For interactive UI, cover default, focus, hover where relevant, pressed/selected, disabled, loading, error, and success as the component requires. Decorative artwork does not replace semantic buttons, labels, or live text.
4. Follow project-specific icon rules. Use one professional licensed icon family when allowed, or purpose-made assets. Never substitute emoji for interface icons. If a project excludes SVG, request suitable raster outputs; do not introduce inline or external SVG as a workaround. Original screenshots may retain the product’s own icons.
5. Use Stitch for layout and component exploration. Use the available image-generation skill for original raster artwork, icons, textures, or transparent assets when that is the appropriate tool. Follow its source-image, anchor, transparency/green-screen, and verification rules; do not invent an undocumented Stitch alpha-export capability.
6. Inspect at actual intended display size and at a relevant small viewport. Check legibility, optical alignment, edges/halos, contrast, repetition, content fit, and whether the artwork earns its space. Keep essential text as HTML/UI text.
7. Export using [Export handoff](export-handoff.md). Reopen the actual file, verify pixel dimensions and background/transparency, and keep an untouched original alongside web-optimized derivatives. Give production files descriptive names.

## Asset record

For each used asset record: source/origin, original or newly generated status, owner/license if applicable, intended slot, dimensions, crop/variant, alt-text intent, output path, and verification. Decorative assets should have empty alt text; meaningful evidence needs a useful caption and alt text, without repeating nearby prose.

Use responsive image sizes, explicit dimensions, and suitable loading behavior. Do not lazy-load the primary hero by habit or ship multi-megabyte artwork at tiny icon size. Review image weight and rendering in the implemented page.

Deliver the selected asset family and placement map, not a contact sheet of unused experiments as the final product.
