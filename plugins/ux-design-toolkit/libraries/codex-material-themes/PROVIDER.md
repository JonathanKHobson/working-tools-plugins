# Application appearance compatibility record

For app theme choice, readability, font selection, preview or an authorized supported apply, read the complete [internal appearance method](../../skills/design-studio/references/application-appearance.md). It uses current native controls and original semantic palette design; no third-party theme-method pack is required for routine UX work.

The historical `codex-material-themes` package was authored by Robin Li / 瑞彬 李, repository https://github.com/robinli/codex-material-themes. Marketplace distribution under `openai-curated-remote` did not make it an OpenAI-authored runtime. The inspected distribution contained local curated data, previews and a Node builder, not an MCP/app/service. At upstream commit `8c540d86b7af1e4c669ac156969e2a6f77c0df11`, no distribution license/notice had been established. No catalog, builder, preview or source body is imported here.

Exact named catalog palettes and screenshot matches remain omitted. User-defined role-palette validation, original HTML preview and deterministic ordinary `codex-theme-v1:` JSON serialization are implemented independently in the internal appearance tool, without copying the catalog or builder. Its documented dark-format field contract is observed locally; actual native import/application remains unverified where the receiving tool cannot operate Codex. An export/portable preview is prepared output, not an applied setting or proof of native rendering. This record preserves provenance and source-rights limits, not an install recommendation.
