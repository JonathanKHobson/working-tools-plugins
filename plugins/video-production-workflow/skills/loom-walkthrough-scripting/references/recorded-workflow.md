# Worked walkthrough: fictional Harbor Notes review

This synthetic example preserves the complete route/timing lessons from the original locally maintained procedure. It is not a real client design, approval, recording or current product specification. For your own walkthrough, verify the actual supplied design and current notes.

## Scenario and reusable lessons

- A designer refreshes speaker notes after a stakeholder approves a proposed form change. The purpose moves from approval-seeking to explaining approved progress. The closing should not request an approval already supplied.
- The designer adds an independent follow-up editor, moves the script into speaker notes and shortens it. The usable format is glanceable speaking bullets paired with exact navigation cues.
- The demonstration follows a question-level open issue, assignment, submission, the recipient's Description history and separate follow-up input, then a session-level approval and its outcomes. Role changes and state transitions need explicit cues.
- A specific-window design capture without camera is one possible recording choice, not a permanent workflow requirement.
- In this fictional scenario, a recording is paused and canceled at about 3:08 because it lacks Add Detail without an Open Issue, created Open Issues, media, comments and meaningful differences across phenomena types. Coverage must be checked against actual examples before claiming recording readiness. The time is an illustrative interruption point, not evidence of a completed recording.
- The revision uses bullets and consistent terminology, `phenomena types`. A prior prose script does not establish a general preference for verbatim narration.

## Demonstration-specific state contract

In this fictional product, Add returns to the observation draft; Submit sends the request. Question-level open issues and session-level approval are distinct configurations. Follow-up extends Description history through a separate input and is not an extra issue-comments thread. Attached question comments are different again. Completed and Approved are not synonyms for submitted. Approval is session-only for this demonstration. These are example constraints, never assumed facts about a recipient's product.
