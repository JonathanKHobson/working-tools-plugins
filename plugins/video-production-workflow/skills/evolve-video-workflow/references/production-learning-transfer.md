# Carry production discoveries into future work

Use for multi-producer projects, recurring creative failures, reusable video templates, or a project that will become a teaching case study. Extend existing stage owners; do not create a separate skill for each lesson.

## Orient once, then work in one lane

Planning owns audience, purpose, intended feeling, takeaway and scope. Storyboards own temporal composition and the difficult transformation. Typography owns exact fonts/custom glyphs, reading order, scale, contrast and camera-aware reading intervals. Motion owns material behavior, rigging, causal action and generated-asset integration. Audio owns stems, event timing and listening. Rendering owns runtime, cadence, bottlenecks and measured cost. Validation owns encoded-output review. Delivery owns reproducible packaging. Evolution owns promoting a repeated discovery into these methods.

At a handoff, use current artifact paths/hashes and ownership receipts. A cloud model's future queue is not evidence of completion; a local model's queue may omit cloud deliveries. Preserve variants rather than overwriting another producer's work. Declare the current canonical example and keep earlier studies labeled.

A skill appearing in a prompt does not prove it was read. A read does not prove its advice was applied. A code comment does not prove the final movie improved. Record usage evidence separately from output evidence. Link the one relevant reference at the point of work instead of dumping every skill into every prompt.

## Record discoveries as events

Each entry should include ID, affected style/variant or general scope, speaker, observation, frame/time/component, confirmed or suspected cause, change, check performed, before/after evidence, unresolved limitation and reusable rule. Keep self-feedback and client feedback attributed. Use visible production commentary, code, logs and results; do not solicit or reconstruct private internal reasoning.

Statuses should separate observed, source-changed, rendered, verified, user-accepted and unresolved. Do not flatten a proposed correction into a fixed result. A later source hash invalidates earlier acceptance unless the reviewed change is explicitly bounded.

Promote a finding across styles when the causal mechanism generalizes: path portability, glyph bounds during camera motion, frame cadence, shared event functions, asset registration, expensive filter batching, or archive integrity. Keep concrete palettes, lettering geometry, prop designs and per-shot coordinates in the variant. A patch for one shared engine belongs to that engine's adapter, not every renderer.

## Reproduction is a production step

Extract the exact download into a fresh working directory. Follow its own instructions. Record what creative inputs were allowed, whether source code or finished assets were reused, runtime versions and every repair. Preserve originals and capture minimal patches. Distinguish source-based rerendering, docs-only reconstruction, and new-subject adaptation; success at one does not prove the others.

Check that generated packages contain their promised docs and assets. Repository-relative documentation paths and developer-local node_modules/browser paths are common hidden dependencies. The first real launch and standalone finish command are part of the test. Do not call a packet portable based only on source inspection.

Use existing provenance inventory/hash helpers. For portable inventories, run `python scripts/verify_template_bundle.py ROOT MANIFEST.json` from the plugin root. The manifest contains `files` with relative `path`, `bytes`, `sha256`, plus optional `requiredPaths`. It catches declared missing/changed files, duplicates, path escapes and external symlinks without writing sources. Save optional reports to a new file outside the package root; never overwrite an input or a previous report. It does not infer undeclared dynamic dependencies or approve the film. Hash the complete selected input closure, including assets, fonts and audio, not just src/scripts.

Record encoded fps, authored pose rate and continuous-scene evaluation rate separately. A 60 fps stream can contain 30 or 12 evaluated poses. Lossy decoded-frame hashes can differ across a held pose. Inspect source/copy logic or raw-frame/near-equality evidence. For a continuous 60 Hz brief, quantize selected actors deliberately while evaluating camera, light and compositing at frame/60. An exact reference reproduction should preserve and label its reference cadence.

Use SHA-256 to identify files and decoded image/sample comparisons to assess similarity. Document visual tolerance and actual sampled/full comparison scope. Audio PCM equality is reproduction evidence, not a new listening test. Benchmark the slowest scene under actual worker contention; render duration is not a quality score.

## Capture material people can understand

Use a single clear frame for a browsing cover, a timestamped contact sheet for the film's sequence, and a separate making-of section. Label each image as pre-production storyboard, style exploration, asset sheet, render diagnostic, encoded contact sheet, or before/after comparison. Record source hash, capture time and intended role. Never relabel post-render evidence as advance planning. Before/after pairs need comparable framing/timing and a described change.

Separate three deliverables: template content, general studio improvements, and teaching/project evidence. Human-facing case studies should explain intent, visible obstacle, decision, outcome and evidence without requiring code fluency. Preserve actual prompts separately from cleaned reusable prompt recipes. Do not publish private paths/account details or raw chat dumps as tutorial visuals by default. Publication remains a separate task.

## Capture the executable template

Keep the family recipe with the actual source and an exact example. Its `SKILL.md` links the visual `STYLE.md`, prerequisites, reproduction command, customization route and review limits. Existing treatment/timeline documents can supply composition, material, typography and motion grammar without duplicate files. Preserve actual font names/weights or custom glyph source, selected raw artwork, registration maps, code, stems, seed/parameters and pinned dependency metadata. Declare external tools, services and non-bundled assets. Prompts document provenance but do not recreate the selected image bytes.

Keep variants with different construction methods explicit. An MP4 and case study may be a useful reference, but they do not establish an executable template. Pin a tested showcase recipe first; claim a customization route only after a representative adaptation is rendered and checked. Do not assume replacing a font, palette, copy or aspect ratio preserves reading time, joints or composition. Keep creative experiments within the task’s authorized scope.

## Freeze media before deriving review evidence

Complete all render, encode, audio replacement and remux processes before starting contact sheets, frame comparisons, loudness analysis or review receipts. Publish the finished output to a distinct final path only after its writer exits successfully. Bind every derived artifact to that final file hash. For a declared bundle, run the same inventory verification before and after the evidence pass; it checks byte identity, not process ownership or an operating-system lock.

If the media changes or a reader overlaps a writer, discard affected derived evidence, wait for the writer to finish, hash the new output and regenerate those checks. Do not retain an old contact sheet or audio report under the new hash. Concurrent writer prevention remains the production coordinator’s responsibility; the inventory helper cannot make a live output immutable or infer which evidence depends on it.

Review the QA artifacts themselves at their intended display size: timestamps and labels must fit their tiles, remain readable, and identify the actual interval. Shorten labels or change the sheet layout when annotations obscure the frame. A successful image export does not establish a useful review sheet.
