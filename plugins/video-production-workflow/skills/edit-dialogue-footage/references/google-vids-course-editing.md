# Google Vids course recording and editing

Use for a narrated lesson whose visual source is an existing Slides deck, a Vids recording, or exported course clips. This is a conditional path through existing production skills, not a new pipeline. Read only the section needed. UI labels below were observed on 2026-09-27; inspect the current project and controls before acting. No fixed coordinates, duration, pause threshold, or audio level is implied.

## Record from a supplied lesson deck

1. Identify the approved deck, lesson/part, current script, practice files, existing Vids project, and destination Drive folder. Check whether the request is to continue a take or create another segment. Reuse the established course workspace and avoid an accidental duplicate project.
2. Confirm the learner starting state, visible actions, expected result, and stop point. Keep narration, screen actions, exact copyable prompts, optional branches, and production notes distinct. Instructional Design Studio owns changes to the teaching sequence; Writing Quality Studio owns a requested voice pass.
3. Open the deck in its intended presentation state. In the available recording entry point, confirm the selected screen/window and microphone, and check that the shared surface is the lesson rather than a private desktop. Prefer a short recording/playback check before a long take. A share indicator alone does not prove usable audio or legible video.
4. Record the segment; pause/resume deliberately while retaining its intended order. Finish the take and inspect the resulting Vids project, scenes, and save status. If media cannot play, resolve or report the actual playback issue before calling the take reviewed.
5. Preview with sound, compare the visible demonstration to the script, and note the scene/time of corrections. Preserve the source recording. Continue with cleanup below, then final review.

## Edit speech and preserve teaching pauses

- Open the transcript for the selected recording/scene. Review detected pauses and filler words in sentence and screen-action context. A count is a set of candidates, not a deletion target. Keep learner reading time, deliberate pauses, breaths, and the instructor's useful conversational rhythm.
- Use removal for an unwanted interval only after confirming the selection. For Edit/Replace controls, inspect what the current interface changes: transcript text, recorded media, or both. Do not assume changing words repairs the spoken audio. Re-record a passage if needed to make the speech and intended claim agree.
- After a small edit or related group, preview from before the boundary through the following action. Listen for clipped words, changed meaning, abrupt cadence, missing context, or speech that gets ahead of the demonstration. Undo or refine a bad cut before accumulating more edits.
- After splitting, moving, or deleting scenes, verify beginning/end continuity and the learner's action order. Generate or update captions against the edited timeline; check wording and timing, including fragments left by transcript edits. Transcript cleanup, caption review, and audible review are separate checks.

## Balance sound with an explicit scope

In the observed Vids UI, controls included `Balance sound`, `This track`, `All tracks`, and `Apply to all audio`. Inspect which project, scene, clip, and scope are selected before applying a change. Use a track-specific adjustment for a local problem; use project-wide settings only when that scope is intended. Reinspect the retained setting and listen across affected scenes for level jumps, intelligibility, and unintended changes to other audio. A clicked setting or save indicator does not prove the mix is balanced. Use `mix-video-audio` for measurements and delivery targets when exported audio is available; report measurements as unavailable rather than inventing them for an editor-only review.

## Review and hand off exports

Use `validate-video-quality` for the full normal-speed watch/listen pass and targeted cut, caption, and small-screen checks. Track these states separately: recording created, project saved, edited preview reviewed, export requested, export completed, exported file reviewed, course asset attached, learner playback verified, released. Record only states with evidence. In particular, `Saved to Drive` is a project save, not an MP4 export.

For exported clips, use `ingest-video-assets`: preserve originals, identify each source/version, probe streams and duration, and inspect embedded timed captions before deciding to retranscribe. Repeated part names do not establish duplicates. Compare clip content and intended order; keep a standalone tip separate unless the course plan includes it in the sequence. If joining clips, retain the source-to-output chapter mapping and recompute caption/chapter offsets after trims. Review privacy masks on delivery copies while preserving demonstrated controls and text readability.

Hand the checked files, clip/chapter map, transcript/captions, outstanding issues, and exact reviewed version to Instructional Design Studio's `course-production-handoff` for lesson-page integration. A media QA pass does not establish that the learner can launch the right course revision.

## Evidence and limits

These are generalized first-party production procedures. Historical private event locators and host cache paths are excluded from this distribution. UI labels are dated observations; inspect current controls before use. This method does not establish that a particular source project passed delivery review.
