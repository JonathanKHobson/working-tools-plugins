# Digital workshop launch rehearsal and closeout

Use for a requested rehearsal or launch check on a specific remote/hybrid workshop platform. Keep the normal speakable practice and [rehearsal rubric](rehearsal-rubric.md); this conditional reference adds observable delivery checks. The procedure is generic: course titles, session dates, accounts, rooms and private participant facts belong in the owning task.

## Establish the rehearsal boundary

Record target URL/app/version, session/room, roles, source course revision, learner prerequisites, device/browser, access needs, expected participant output and which live mutations are authorized. Prefer a disposable room and fictional responses. A simulated participant transcript, author preview or presenter tab switch cannot establish what a real learner or audience sees. Use separate sessions/accounts/devices for distinct roles when supported; shared cookies can invalidate permission checks. Use current provider documentation for its actual controls rather than inventing controls named here.

Before visual claims, map 3–8 anchors: ID, role/source/state, viewport/region, control/node if available, observed fact and intended action. Capture only bounded evidence with identifiers and private responses removed.

## Exercise entry and roles

| Path | Deliberate action | Required readback |
| --- | --- | --- |
| First-time participant | Open the actual invitation/direct link in an unseeded session; complete prerequisites and join | What appears before joining, pending/error response, confirmed membership, correct first task; reload/rejoin and recovery/help route |
| Presenter | Start the intended lesson/activity, reveal and advance a step | Presenter status and the corresponding audience/participant state actually change; no unpublished edit or private facilitator note leaks |
| Audience | Open the display independently and inspect the same step | Correct public content, readable view and intended response visibility; independently verify hidden/private states |
| Participant | Submit fictional input, revise when supported, leave/rejoin | Visible result and authoritative saved/received state; correct identity, resume and permitted peer visibility |
| Privacy and room controls | Exercise configured visibility, access/lock, pause/resume, remove/rejoin and end controls relevant to the target | Role boundary holds, room status is observable in every affected role, paused/ended state behaves as expected; unauthorized access is denied in a separate session |

Test only applicable supported controls. Record not available/not applicable with reason; do not silently count a missing role as passed. Exercise one plausible interruption such as a delayed join, lost connection or unavailable asset, then use the planned text/analog fallback. Timing the opening also verifies that instructions fit the real allotted time.

Use keyboard and assistive technology checks on the actual participant entry/action when those are in scope. Provide accessible original materials separately when screen sharing cannot preserve structure. Verify captions and shared audio from the receiver's session; an organizer setting alone is insufficient. These priorities follow [W3C remote meeting guidance](https://www.w3.org/TR/remote-meetings/) and [accessible event planning](https://www.w3.org/WAI/teach-advocate/accessible-presentations/); they do not constitute a platform conformance audit.

## Recording setup and consent

Recording is a distinct action. Confirm the applicable organization/venue policy and authorized purpose, access, retention and consent procedure before starting it. This procedure does not make a legal determination or treat attendance as consent. State whether screen, voices, cameras, chat, responses and captions/transcript will be captured, who can access them and the participation alternative. Verify the actual notice/consent route, including late arrivals; if it cannot be honored, continue without recording or hold that portion.

With authorized fictional/test content, verify the selected microphone, shared audio, camera/screen region, caption source, destination and available capacity. Make a short sample only when authorized; stop it, locate the actual output and play back speech, shared sound, visible text and captions. Keep a presenter-only rehearsal recording separate from consent for a participant session. Recording accessibility needs are planned before capture. [W3C media planning](https://www.w3.org/WAI/media/av/planning/)

## Closeout and readiness

End the test activity and room as intended; independently confirm participant/audience behavior. Stop recording, confirm the actual file or processing state, verify access and playback when ready, and keep publishing/sharing at its authorized stage. Preserve the learner output and consent/readiness evidence in the task record; remove only task-owned test data/sessions when authorized. Recheck any failed role/path on the same target revision after correction.

Return a compact trace: check → role/path → action → expected → observed → capture/log → pass/fail/unverified → owner/fallback. A launch is ready only for the exercised configuration when required paths pass and remaining dependencies are explicit. A saved revision, verbal rehearsal or prepared checklist remains that state.
