# Verify a template as a reusable authoring tool

Load when building, substantially extending or delivering a reusable template. Ordinary selection still uses the existing source-hash handoff. This method does not relabel retained Office sources as runtime-tested templates or require rebuilding the collection.

## Define its job

Name the audience, author task, target application and output format. A live talk, an asynchronous reading deck, an analytical appendix and a print handout can share identity while needing different density and navigation. Choose ratios, layouts and content families from the intended work, not a universal layout count.

Read the selected DESIGN.md, source manifest and WORKFLOW.md. Bind the approved brand and writing sources by selected ID and revision in the current project record. Retain native token names and source conventions. Graphic Design owns visual direction, Writing Quality owns prose review, and the appropriate native provider owns editing/export. Work Management's work-handoff method covers packages composed across studios.

## Separate source, starter and example

Keep the editable master, clean starting state, populated example and minimal author instructions identifiable. They need not be four files. State what an author should replace, preserve, duplicate and remove. Mark sample claims/data as fictional; do not let them silently survive into real client work. Include only assets whose permitted use covers the handoff, with declared font/data dependencies.

For a presentation that claims reusable native layouts, verify actual themes, masters, layouts and typed placeholders in the selected app. Duplicating a polished slide or exporting screenshot slides does not establish this claim. Add a slide from each delivered layout family, insert realistic content, then reset/reapply the layout as supported. Verify that typography, pictures, footers and reading order survive. If the request only needs an editable reference deck, label it that way instead of inventing native-template support.

For documents, exercise headings, lists, table/caption styles and pagination with a long section. For spreadsheets, use representative replacement data and inspect formulas, units, totals, missing-data behavior and charts. Do not change data meaning or analytical scales merely to make branding consistent. Sites retain their token check plus actual viewport and interaction review.

## Test adaptation, then delivery

Use sparse, typical and stress content where each reveals a plausible failure. Select relevant stressors, such as a long title, translated phrase, dense table, missing image, alternate brand variant or unavailable font. Do not multiply every combination or impose the same style on different consumers.

Check output appearance at intended use size and applicable accessibility structure in the actual target. Visual rendering alone cannot prove reading order, native object editability, formulas or template behavior. An accessibility checker is useful evidence with its own coverage limits. Preserve a test copy so the approved source stays intact.

Open the final delivered package from a clean location, perform a meaningful author edit, save, reopen and export the requested format when those capabilities are claimed. Record the exact artifact revision, application/version, task and result. Report supported, tested, untested or unavailable per target format, rather than a single universal pass. Target-app access can remain an explicit open gate; do not install software or publish merely to improve a checklist.

When a retained source defect is found, capture the source ID and reproducible failure for its owner. Repair the working copy within scope; update a library source only when authorized and regenerate its integrity records using the existing maintenance workflow. Do not weaken source-hash checks.

## Primary documentation and status

The acceptance sequence is an internal production convention, not an external standard. Microsoft documents [PowerPoint template creation using masters and layouts](https://support.microsoft.com/en-us/powerpoint/create-and-save-a-powerpoint-template) and [checking reading order](https://support.microsoft.com/en-us/powerpoint/make-slides-easier-to-read-by-using-the-reading-order-pane). Those mechanics are app-specific; verify the current target instead of assuming all editors preserve them. Last checked 2026-10-09. No new template, renderer, runtime or source collection is installed by this guidance.
