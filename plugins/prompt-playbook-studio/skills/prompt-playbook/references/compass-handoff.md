# Prompt Compass workflow boundary

Use Prompt Compass for an authorized prompt diagnosis, improvement, build, preflight or guided workflow when its structured tools are available and fit the task; an exact Compass-name request is not required. Briefly explain the relevant outcome when orientation helps. Simple wording edits can use the studio method; offer guided or panel depth when it would resolve a material uncertainty. Call `route_prompt_request` first for a general Compass request; don't begin a rewrite by browsing framework catalogs unless the returned route permits it.

Follow the chosen direct or guided lane. If a tool returns `must_pause=true`, ask only its current question through native input UI when available. Do not invent an answer. If `final_prompt_ready=false`, preserve that state rather than presenting a final rewrite. General prompt editing without a Compass workflow can use the studio's direct method. If Compass is absent, continue with the full first-party method and do not claim a Compass diagnosis or guided state.

Agent Mode requires explicit opt-in and retains the three-role protocol. A generic mention of a council does not trigger it. Do not launch recursive committees or dump full transcripts into role prompts. Personal overlay and saved library writes remain distinct from shared core lookup, and a plugin install never authorizes them implicitly.

The [backend integration guide](../../../docs/backend-integration.md) identifies the actual compact tool profile, launch boundary and verified runtime. Full-profile functions can remain available through deliberate configuration when needed; do not infer availability from a name in this document.
