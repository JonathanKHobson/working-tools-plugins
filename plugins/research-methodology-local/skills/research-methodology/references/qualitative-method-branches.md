# Codebook/framework and qualitative content-analysis branches

Use after the shared analysis charter, permissions, corpus inventory and familiarization in [qualitative analysis](qualitative-analysis.md). These are distinct methods, not extra checks bolted onto reflexive TA. Return to shared reporting/limitations/quote verification after executing the appropriate branch.

## Codebook thematic or framework analysis

Useful when an applied question needs a structured account across cases and a team or established framework needs transparent categories. State the particular variant and rationale. Do not claim that every codebook approach treats coding as objectively correct, requires independent coders or uses the same epistemology.

1. **Specify analytic units and framework origin.** Define case (participant, group, document), context and segment to be coded. Record which categories come from the question/theory/previous work and which are data-led. Include an open route for unanticipated relevant meaning and counterexamples. Read full cases; isolated keyword matches do not replace context.
2. **Draft the framework.** Give each code ID, name, definition, inclusion/exclusion criteria, examples with source IDs and boundaries from nearby codes. Document permitted multiple coding, missing/unclear evidence and treatment of negation. Keep a version and change log. A label such as 'trust' needs an operational definition before systematic application.
3. **Pilot on a purposive, varied portion of the actual set.** Include different item types and difficult/contradictory cases. Record the exact pilot coverage. Compare ambiguous assignments with definitions and refine the framework. If several authorized analysts are involved, discuss disagreements to improve clarity and preserve interpretive differences where warranted. A sole analyst can pilot and review without pretending a second coder existed.
4. **Choose any agreement procedure deliberately.** If the study actually uses a coding-reliability approach, predefine independent coding, sampling/unit, code type, overlap rules, metric, denominator and decision criteria before calculating agreement. Distinguish initial agreement from consensus after discussion. Report the procedure and limitations; there is no universal acceptable threshold or assurance of valid interpretation. Do not invent reliability scores. When calibration is interpretive discussion in a codebook/framework study, describe it as such without falsely claiming statistical reliability.
5. **Apply the revised framework systematically.** Code every included case with source locators, contextualized excerpts and notes. Add or revise categories when needed; log changes and recode affected earlier material so the final version is actually applied. Keep version-specific coverage visible if some material cannot be revisited.
6. **Chart a case-by-category matrix.** Each cell holds a concise contextualized summary plus source/excerpt IDs, not only a checkmark. Preserve variation within a case and contradictions between cases. Mark 'not discussed', 'unclear' and 'not applicable' separately from a substantive negative response. A focus group is not automatically a set of independent interview participants.
7. **Interpret across and within cases.** Compare patterns, conditions, outliers and links between categories against the question. Inspect original excerpts for any proposed interpretation. Topic/category summaries can be valid outputs; deeper thematic claims require actual interpretive support. Do not infer a universal behavior from repeated statements in a purposive sample.
8. **Report the real process.** Include framework origin/version, pilot and revision decisions, analytic ownership, matrix/excerpt trail, findings and material exceptions. Distinguish case coverage counts from population prevalence. A predefined framework can miss meanings it was not designed to capture; explain the open-category route and remaining limits.

## Qualitative content analysis

Useful for interpreting text categories with a defined unit; counts are optional. State which design is being applied. Hsieh and Shannon distinguish conventional (categories developed from text), directed (initial coding informed by theory/research) and summative (counts/comparisons followed by contextual interpretation) approaches; see [provenance](qualitative-provenance.md). Do not reduce all three to word-frequency analysis.

1. **Define material and units.** Set sampling/recording unit (document, response, sentence, meaning segment), context unit (surrounding response or full item) and any counting unit. Define inclusion, excluded/duplicate items, languages, empty/missing responses and multi-author/group material. Record the denominator before percentages.
2. **Develop categories matched to design.** Conventional: open-code a varied portion, group meaning-related codes into categories, draft definitions and retain source links. Directed: list the theoretical categories and rationale, define boundaries, and keep a procedure for relevant text that does not fit or contradicts the theory. Summative: define terms/categories and a transparent count procedure, then examine uses and meanings in context, including synonyms, negation, irony and absences. Software token matches remain candidate evidence until checked.
3. **Pilot definitions and rules.** Test a varied subset and difficult cases; refine inclusion/exclusion, overlap/multiple coding, ambiguous/missing classifications and examples. Preserve category version and analytic decisions. If agreement is a design requirement, use the explicit procedure described above; it is not mandatory just because categories are present.
4. **Code the specified set.** Use the final/revised rules consistently and retain excerpt-to-category traceability. If rules change, revisit affected items and record coverage. Keep text that fits no category visible; do not force it into the nearest theory box.
5. **Count only if the question/design needs it.** Specify whether the number is mentions, distinct responses, participants or documents. A participant with ten mentions is not ten participants. If multiple categories are allowed, their percentages may exceed 100%; state that. Show the numerator/denominator and missing/uncoded treatment. 'Three of five included responses mention scheduling' is a bounded corpus result, not '60% of customers struggle with scheduling.' Unmentioned issues may reflect the prompt rather than their absence.
6. **Interpret categories in context.** Return to examples, co-occurrence, variation and disconfirming material; explain what counts do and do not mean. A frequent category may be a prompt artifact; a rare one can be important. Avoid claiming a latent belief from a keyword count alone. Compare theory-led categories with material that challenges them.
7. **Write the account.** Report design, units, category development, coding/counting rules, actual checks, coverage, contextualized categories, exceptions and limits. Present any table with source IDs and denominator notes. Separate description from inferred meaning and from recommendations. Apply the shared quality review with branch-specific items.

## Method mismatch triggers

- 'Reflexive TA' plus frozen codes, independent accuracy checking and a compulsory kappa: select the method the actual protocol represents or revise the incompatible procedure transparently.
- A client wants counts of predefined issues: a codebook/content approach may fit better than inventing themes.
- A codebook matrix cell says 'no concern' solely because the issue was unmentioned: replace with 'not discussed' and revisit the interpretation.
- A word-cloud request: deliver the bounded descriptive visualization if authorized; do not call it a complete thematic analysis.
