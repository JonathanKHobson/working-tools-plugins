# Revise a spoken lesson script

Use only for an instructional narration or walkthrough voice pass. Instructional Design Studio owns objectives, source accuracy, task sequencing, and practice design; Video Production Workflow owns the recorded edit. This reference keeps an existing instructor's voice while making a script easier to say and follow.

## Work from actual delivery

Compare the supplied draft with a small, relevant sample of the instructor's earlier transcript or recording when available. Name what is observed: how they frame the task, explain a choice, invite a pause, check a result, or recover from an unexpected response. Use timestamps/line locators for claims about that sample. A transcript supports word choice and structure; delivery claims about pacing, emphasis, or tone require listening. If only text is available, say so.

Preserve useful cadence, first-person explanation, direct invitations to check, and deliberate repetition. Remove tangents or duplicated setup when they delay the learner's first meaningful action. Do not force every instructor into a polished presenter voice or assume pauses/fillers are always defects.

## Make the revision recordable

1. Prioritize source accuracy and the learner decision, then sequence, then sentence rhythm. Give the highest-impact changes with exact draft locators, reason, and replacement wording when the user asks for recommendations; provide a revised script only when requested or within scope.
2. Separate spoken narration from screen actions, exact prompts, optional/conditional branches, production cues, editor notes, and references. A marker in narration may point to an action; the editor instruction itself is not spoken. Preserve any explicit “do not submit” or example-only boundary.
3. Distinguish the spoken reason for an action from a long prompt learners can copy from the guide. Use concrete source checks instead of a vague “check the answer.” Ask the learner to notice something in the source before comparing it with an AI response when that serves the approved objective.
4. Preserve uncertainty: “The note says the export was supplied” is different from “we inspected the export.” Never imply an unavailable file has been read, a message has been sent, or a draft has been published. If a demonstration produces a correct result, do not manufacture an error to fit the correction script; label the correction as conditional.
5. Reconcile each changed instruction with the current slide, handout filename, existing workspace, visible result, and next lesson. A prior review's proposed folder or file format is not authoritative after the course changes.
6. Do a timed read or rehearsal of changed passages and verify their screen-action fit. End on the actual opened/checked learner artifact where the lesson calls for one. A written review is not proof that the recording, download, or learner page has been updated.

## Small constructed example

Before: “Now verify everything and save it.”

After: “Let's check the two claims against the handoff note. Which one is confirmed, and which still needs an answer? Once those agree with the source, save the briefing and open the file.”

This is an illustrative rewrite, not a quotation from a recording. Adapt it to the supplied source and learning goal; do not invent two claims for every lesson.

## Provenance and limits

This method was adapted from a reviewed course-production workflow. Supply the current script, slide or screen evidence for the recipient task; historical private production records are not bundled.
