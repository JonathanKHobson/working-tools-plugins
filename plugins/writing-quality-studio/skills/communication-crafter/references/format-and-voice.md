# Format and shared voice choices

Use when the task is to shape a business document, public article, newsletter passage, or reusable organization/creator voice guide. A routine message with a clear ask needs no format audit. The reader's decision and the supplied evidence come before a template.

## Choose the document's job

| Requested form | Useful order | Verify before delivery |
| --- | --- | --- |
| Executive summary | situation → finding → recommendation → decision or next action | findings and implications have the same scope as the source |
| Memo or stakeholder update | purpose/current state → few material facts → consequence → owner or answerable ask | status, responsibility and timing are actually known |
| Proposal passage | client's problem → bounded approach → comparable proof → scope, cost or next step as authorized | benefit, price, timeline and capacity are supported |
| Announcement | what changed → why this reader cares → when/how it affects them → next action | dates, availability and access links are verified |
| Blog/article | reader's concrete question → answer or useful tension → evidence, steps and limitations → earned takeaway | no invented first-hand story or case result |
| Newsletter passage | editorial promise for this issue → one clear insight → evidence or example → a useful reader action | issue voice, source links and send/publication state are clear |

For a blog or article, headings should answer real reader questions; examples should carry a point. A headline option is useful when packaging is requested, not an automatic set of variants. For newsletter strategy or platform posting, hand off to `social-content-studio:social-content` or `social-content-studio:social-publishing` as appropriate; for SEO and campaign planning, use `marketing-strategy-studio:marketing-strategy-operator`. This reference shapes prose within a chosen plan; it does not decide a campaign.

## Build or apply a shared voice guide

Only build a durable guide when the user asks for one or repeated team content needs it. Start with a few approved, attributable examples across relevant channels. Shared-file ownership is not proof of authorship or brand approval. Record 3–4 observable traits as decisions, each with a positive example and a boundary: for example, “direct about the result; do not imply a test that was not run.” Include audience, formality, preferred terms, terms to avoid when they obscure meaning, channel differences, and one before/after application. Keep claims, legal terms, accessibility requirements and required product labels outside discretionary tone changes.

When applying a guide, compare the revised passage to both the guide and the source facts. A brand voice can change rhythm, vocabulary and warmth; it cannot make a draft's weak evidence sound like a verified result. If the guide conflicts with a current approved sample or the user's requested voice, surface the choice rather than silently treating an old guide as policy.
