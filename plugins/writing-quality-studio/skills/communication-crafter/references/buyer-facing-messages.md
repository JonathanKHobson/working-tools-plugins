# Buyer-facing message choices

Read when writing contractor service copy, a homepage message, client outreach, an inquiry reply, or proposal language. Start at the buyer's current uncertainty and stage: orientation, trust, inquiry, discovery, proposal, or contract. Do not rush to a proposal when the buyer only needs to see fit; do not send vague networking language after they have named a concrete problem. Marketing Strategy owns offer and campaign decisions; Portfolio owns case evidence; this reference shapes supported language within them.

Build the message from the buyer situation, stakes, bounded offer, comparable proof, process, and a safe next step. A useful positioning sentence identifies audience, problem, method, outcome, and point of view; leave an unknown visible instead of filling it with a promise. For a service offer, name deliverables, timeline only if supplied or approved, exclusions, what changes scope, fit conditions, and what happens after contact. Use the [service-offer template](../templates/service-offer.md) when a reusable card or page section is requested.

For homepage copy, lead with the service, audience, and supported outcome. Follow with real proof, the buyer problem, named services, a simple process, cases or samples, a point of view, and an inquiry action. A tool list, decorative badge, or clever tagline cannot substitute for proof. Proof is strongest when it is a verified outcome, a decision influenced, or a source-backed artifact; a method or credential can support a narrower claim. Mark missing proof and never invent clients, testimonials, revenue, availability, or timelines.

For human-controlled outreach, use a specific observed context, the decision it may raise, relevant service proof, and an easy-to-decline ask. For an inquiry, restate the decision, ask only the few scope questions that change the next step, and suggest a bounded path. For a proposal, state the buyer's problem, recommended approach, deliverables, approved timing and scope, assumptions, relevant proof, and next action. Use the [client-message template](../templates/client-message.md) for these shapes. Keep price, capacity, terms, and approval aligned with the current source; drafting does not send the message or commit to work.
