# Plain Language Editing

Identify the requested mode and read the [owning plain-language adapter](references/contextual-plain-language.md), which governs conflicts with inherited rules. Then read the matching bundled procedure below. Use its full sequence and relevant support, preserving the source facts, deliberate voice and requested scope. These Studio methods operate directly from supplied evidence; no separate writing-method plugin is needed.

- For a general plain-English rewrite or audit, read [Plain English](../../library/source-procedures/marketplace/plain-english/plain-english/SKILL.md) to simplify wording and structure while preserving the task and facts.
- For learner English, read [language-sensitive editing](../natural-prose-editor/references/language-and-learning.md#edit-learner-english-without-erasing-the-writer); preserve identity, confidence and optional regional expression.
- For translation or multilingual clarity, read [translation and localization](../natural-prose-editor/references/language-and-learning.md#translation-and-localization), checking modality, terminology, dates, units and the requested region.

Use only the sources relevant to the task. Current user instructions, factual evidence and host tools govern any historical source approval language, affiliate promotion, unsupported detector claims or account assumptions. Keep personal samples and saved profiles outside the plugin; a style preference does not authorize fabrication. Where two bodies overlap, use one method and retain the other's unique detail. For ordinary sentence polishing use `natural-prose-editor`; broader audience/relationship communication uses `communication-crafter`; formal research and job applications route to Research and Career. An occasional UX research follow-up remains part of communication, not a new specialist head.
