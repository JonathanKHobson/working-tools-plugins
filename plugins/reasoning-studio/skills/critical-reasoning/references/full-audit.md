# Full Critical Compass audit from Reasoning Studio

Use this route only for an explicitly requested advanced human-loop audit or independent panel. The standing MCP connection remains the ten-tool routine profile. `scripts/critical_full_client.py` starts the canonical full-profile backend for one named call, writes the complete JSON result, and exits; it does not add 47 schemas to host discovery. It reads the explicitly selected `critical-compass` binding and leaves that file unchanged. Run it from the installed Reasoning Studio plugin root, using absolute request and output paths:

```bash
python3 scripts/critical_full_client.py --binding /path/to/compass-binding.json discover /private/task/full-tools.json
python3 scripts/critical_full_client.py --binding /path/to/compass-binding.json schema /private/task/advanced-schema.json --tool advanced_audit
python3 scripts/critical_full_client.py --binding /path/to/compass-binding.json call /private/task/advanced-01.json --request /private/task/advanced-request.json
```

For `call`, the request file is JSON with an exact full-profile tool name and its arguments, for example `{"tool":"advanced_audit","arguments":{...}}`. Read the specific tool schema before constructing the first call. The small stdout receipt includes the output path, hash, error status and pause flags; the complete `result.structuredContent` and MCP content live in the output file. Treat `is_error=true` as failure and inspect the file. Keep task files private: essays, human answers and reports may be sensitive. The optional `--state-db-path` is for isolated testing; production uses the bound backend's normal state path. A subprocess exits after every request, so save/load progress explicitly when a workflow crosses turns.

1. Obtain the actual essay, intended audience/use and explicit panel opt-in. Call `advanced_audit` with `mode="agent"`, guided human loop and a truthful host capability profile. For ordinary full text critique without a panel, use the routine `audit_text` tool instead.
2. If `human_loop_host_action.must_pause` or `PAUSE_REQUIRED` is true, ask only the returned current `questions_for_user` through native user input. Stop until the user answers. Preserve `human_loop_state`, prompt IDs, session ID and the exact subject text. Do not use silent or smoke-test overrides to pass a human gate. At every stage, call `save_audit_progress` with a stable `audit_id`, subject text, stage, resume marker, prior payload and real state; then call `get_audit_progress` to verify `prior_stage_payload` before resuming.
3. Present the panel plan for human approval. Carry the returned plan hash and only set `plan_approved=true` after actual approval. If declined, continue with ordinary audit. Only after approval, run four genuinely independent host analysts using the returned role contracts: evidence/argument, systems/context, uncertainty/methods, and missing voice/power. Do not claim independence when one agent sequentially writes all four. The MCP returns scaffolds; it does not spawn these agents.
4. Feed the distinct analyst artifacts to `define_audit_agents`, `run_independent_audit_analysis`, `map_audit_tensions`, `run_audit_debate`, then `synthesize_audit_verdict`. Read each schema just before its call. Preserve dissent, traceable CIS revision decisions and typed `agentic_state`. Checkpoint and read back progress between meaningful stages. At the reflection checkpoint, first display the returned findings preview in the user's main chat: the strongest supported reading, the main limitation, and any material council disagreement. A preview saved in a tool result or seen only by a subagent has not been shown to the user. Then present the returned reflection questions through native input and wait for the user's answers before finalizing. For an explicitly authorized simulation, label invented answers as sample reviewer responses and preserve the distinction from actual user interaction evidence.
5. The synthesis's `report_ready_payload` is a draft. Fill its canonical `audit_data` from actual essay, answers and panel evidence. For a requested full PDF, call `validate_report_payload` with `report_depth="full"` and `allow_placeholders=false`; repair missing fields until readiness passes. Call `generate_audit_report` with the same data and inspect the rendered PDF. Save the completed result separately with `save_audit_result`.

Consult the [Critical Compass integration contract](../../../docs/critical-compass-integration.md) for ordinary routing. The backend's stage schemas and returned pause/report contracts control the exact arguments; this reference does not replace them.
