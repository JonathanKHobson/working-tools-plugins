# Critical Compass in Reasoning Studio

Critical Compass is an existing local MCP dependency. This plugin packages a small stdio bridge plus cross-domain reasoning guidance. The server, runtime, database, and private state remain outside the plugin.

Use the bounded MCP tool surface when a user asks to critique supplied reasoning, research methods, a claim, or an audit-ready source. Do not call it for ordinary source retrieval or every research question. The host may launch `server.py --tool-profile routine` to expose ten common tools with compact descriptions and a compact overview/quick-scan response. The default `full` profile retains all 47 tools and their original contracts for advanced panels, persistence, and administration. For an explicitly requested advanced lifecycle, the packaged `scripts/critical_full_client.py` launches a task-scoped full-profile subprocess through the existing private binding, then exits after each named call. It does not change the standing routine registration or its tool catalog; read the `critical-reasoning` skill's full-audit reference before using it. Use one standing connection per host. When enabling the packaged connection, disable a duplicate global registration after verifying the bridge.

Common route: `critical_compass_overview` for tool choice; `quick_scan` for a first look at supplied text; `audit_text` for a full guided review; `claim_stress_test` for a specific claim; `search_knowledge_base` for local lenses (use `retrieval_profile="research_methodology"` only for research-method questions; retain the general profile for other domains); `get_framework` for a selected framework; `prepare_audit_source` for an explicitly named local source; `factcheck_lookup` only when public external lookup is authorized and the claim contains no private text; `validate_report_payload` before `generate_audit_report` for a requested local report. The fact-check tool is annotated as open-world; its default guided-research provider does not itself prove a claim.

Preserve `human_loop_host_action.must_pause`, the current `questions_for_user`, mode consent, dissent, provenance, and report readiness. The host asks the current question through native UI when available and never supplies an answer on the user's behalf. A local KB match is a reasoning lens, not external evidence. Tool output is diagnostic support; source verification and claim scope remain the researcher's responsibility. Research Studio owns manuscript craft and evidence discovery; Academic Writing Toolkit supplies bounded citation/BibTeX/prose checks. Work Management owns operational decision councils.

## Packaged connection

The optional `scripts/compass_mcp.py critical-compass --binding /path/to/compass-binding.json` launcher reads the operator-selected runtime binding; it never installs a backend or downloads dependencies. Configure its `critical-compass` entry with absolute `interpreter` and `server` paths and `args: ["--tool-profile", "routine"]`. Keep the virtualenv interpreter path intact, rather than resolving its Python symlink. The on-demand client uses this same binding and replaces only the child process's profile with `full`; bindings and data are not bundled or shared.

Install the plugin through the host, verify initialize/tools-list and a harmless overview call, then disable a duplicate global Critical Compass registration. Reopen the host session to refresh its tool catalog. Missing mounts or bindings produce a setup error without fallback downloads. No public network service or registered cloud app is created.

Verification on 2026-09-29 with MCP SDK 1.30.0, arm64 Python 3.12, isolated state: full profile exposed 47 tools and matched pre-change metadata and sample results byte for byte (63,879, 97,934, and 29,716 bytes). Routine profile exposed 10 tools; metadata was 9,982 bytes, overview 2,673 bytes, and quick scan 16,128 bytes. The quick scan remains larger because it preserves the integrity snapshot, fairness context, and selected lens information. The arm64 environment uses WeasyPrint 70.0. On macOS, the report timeout worker invokes its Python-module backend through a fresh CLI process to avoid a forked-process proxy-discovery crash. No extra launch environment flag is needed. `python -m pytest -q tests/test_report_renderer.py` passed all 52 renderer checks, and the focused profile, onboarding, consent, agentic-flow, and trust suite passed 65 checks, using the arm64 virtualenv Python. Source tests and a packaged bridge handshake passed. Host installation/readback is recorded separately in the consolidation receipt.

## Migration

The stable Critical Compass backend, private binding key, tool names, profiles and state paths are unchanged. Research Studio no longer registers this server. Its legacy critical-reasoning route forwards here. The original files are preserved under `provenance/research-origin/`; dated receipts there are historical, not fresh validation.
