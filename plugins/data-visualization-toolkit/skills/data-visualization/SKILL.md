# Data Visualization Toolkit

For a capabilities or getting-started question, consult the [human guide](../../README.md), name the relevant reader question, source data, and expected visual result, then use the route below. For a defined chart or review, proceed directly without a repeated tour or any claimed persistent onboarding state.

Start with the viewer's question, the decision or claim, source/grain, and target surface. Choose the smallest truthful form and honor a requested format unless it distorts the evidence. For substantive web visualization work, **read the complete relevant source procedure in the preserved library before working**; the dispatch heads below are navigation, not substitutes for those procedures.

Default to a lay reader unless the user explicitly selects a scientific or academic audience. Make the answer understandable at a glance with minimal decoding. Use everyday, trait-specific labels such as **Casual / Neutral / Formal** when they accurately describe the measure; generic Low / Medium / High and a higher-is-better color treatment can misrepresent a trait. Keep scientific jargon, raw IDs, coefficients, ordinal terminology, MATTR and opaque decimals in expanded methods unless that audience needs them upfront. Rounding and translation must preserve the underlying values, ordering and limits.

Every scale must explain its meaningful ends and middle, numeric values/ranges and what a displayed span represents. Separate observed spread, uncertainty, estimates and recommended target ranges; simplification never turns a target into an observation. Each upfront view must answer a distinct reader question rather than repeat the same dimension in another chart. Prefer the compact, familiar incumbent layout with a clearly named details button for methods and secondary evidence; do not hide the whole reading path behind blanket accordions. Ordinary web reading text should be at least 16px. Apply the [reader-comprehension gate](../visualization-verification/SKILL.md#reader-comprehension-gate) before signoff. These maintained audience rules govern adaptation of the preserved methods.

The full source is a method library, not a chart engine, installed dependency, MCP, connector, or publishing permission. Use the selected surface's actual execution owner. The local [surface boundary reference](references/surfaces-and-providers.md) lists current owners. For an in-conversation interactive visual, route to the installed `interactive-explanations`/Visualize owner and follow its complete provider contract when it is available; do not infer its runtime from this library. Before a quality claim, inspect the rendered artifact when the task produces one. Verify known values, the primary comparison, accessible meaning, relevant interaction, narrow layout, and requested export. A source read, successful build, generated preview, exported file, and verified published result are distinct states.
