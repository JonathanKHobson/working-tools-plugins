# Delivery surfaces and provider boundaries

First establish what the user wants delivered: a short chat explanation, an inline interactive visual, a standalone scientific figure, a figure inside an existing document, a Data Analytics app, a bespoke website, a dashboard in an existing product, a native mobile/desktop view, or a static composed infographic. Use the selected surface's real tools and output contract. A skill reference never makes a provider installed, callable, authenticated or authorized.

| Surface | Owning execution | This toolkit contributes |
| --- | --- | --- |
| Plain chat explanation or comparison | Normal response, table or Mermaid where sufficient | Chart choice and truthful explanation; no visual file by default |
| Inline in-conversation interactive visual | `interactive-explanations`/Visualize owner when exposed in the current host | Data/encoding judgment; read its complete provider runtime and output contract before authoring |
| Existing Data Analytics report/dashboard/chart | `data-analytics:visualize-data`, `build-dashboard`, `build-report` and its app contract | Chart question, alternatives, uncertainty and QA; use its supported runtime and inspect sources |
| Bespoke web visualization | Owning web app framework and the matching complete source procedure | Visual brief, renderer choice, semantic contract and tests; retain the existing project stack |
| Static scientific/research figure | Requested plotting tool or document workflow | Publication-ready chart design, uncertainty, source note and rendered QA |
| PDF, slide or document figure | PDF/Documents/Presentations or selected project renderer | Figure package, dimensions, source/caption and export inspection |
| Static editorial infographic | `graphic-design-studio:infographic-design` | Quantitative chart semantics; Graphic Design owns composition, print and assets |
| Dashboard UX and visual hierarchy | `ux-design-toolkit:dashboard-design` or `design-studio` | Encodings, comparisons, filter semantics and chart QA |
| iOS/macOS/mobile implementation | Native platform plugin or owning app code | Surface-independent meaning, accessibility and fallbacks |
| Infographic Artist app | Its installed app binding, if exposed and requested | Optional brand/mechanism precedent or critique input; app operation stays there |

Visualize's inline output is different from a standalone website or project edit; use its dedicated owner and full provider contract rather than a paraphrase in this method reference. Data Analytics retains data discovery, metric definitions, calculation, report/dashboard creation, connectors, publication and refresh jobs. Build Web Data Visualization is an MIT method source for deep web chart implementation; this toolkit does not silently install libraries or run its examples. Infographic Artist is app-only, not a generic infographic generation API. When a named provider is unavailable, use an authorized local tool or report the missing capability rather than claiming a provider action occurred.

For any web or live surface, identify the authoritative data source, loading and empty states, connection/refresh status, update cadence, last-known-good behavior, URL or saved-view state, main interaction and export path. A draft, generated preview, implemented page, exported file, published page and verified public journey are different end states. Publishing or sending follows the owning provider and the user's authorization.
