# Web chart engineering

Choose the relevant **full** original procedure and read it before implementation; follow its own task-specific references and examples in the unchanged library:

- [Grammar of Graphics and Declarative Visualization](../../libraries/build-web-data-visualization/skills/grammar-of-graphics-and-declarative-visualization/SKILL.md) for Observable Plot, Vega-Lite or Vega specs and the boundary of declarative fit.
- [D3 Data Visualization](../../libraries/build-web-data-visualization/skills/d3-data-visualization/SKILL.md) for custom SVG/DOM geometry, labels, annotations, joins and behavior.
- [TypeScript Data Visualization Engineering](../../libraries/build-web-data-visualization/skills/typescript-data-visualization-engineering/SKILL.md) for typed data, renderer-neutral geometry, state codecs and product contracts.
- [React and Next.js Data Visualization](../../libraries/build-web-data-visualization/skills/react-and-nextjs-data-visualization/SKILL.md) for component ownership, client/server boundaries, hydration, loading and app integration.

Load only the applicable full procedures, often a renderer plus the language/framework procedure. The [root router](../data-visualization/SKILL.md) resolves visual form; [dense and GPU rendering](../dense-and-gpu-rendering/SKILL.md) takes over when DOM/SVG density or redraw cost changes the architecture. Verify the current APIs of selected libraries before coding.
