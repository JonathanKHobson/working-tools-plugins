# Live dashboards

Read the complete [Dashboards and Real-Time Visualization procedure](../../libraries/build-web-data-visualization/skills/dashboards-and-real-time-visualization/SKILL.md) before designing the live surface. Follow its original monitoring-versus-analysis, streaming, interaction and degradation references. The source distinguishes live, delayed, stale, partial, offline and reconnecting states and defines scan-first layout, mobile behavior, instance count and performance costs; this head does not substitute for those methods.

Pair with [web chart engineering](../web-chart-engineering/SKILL.md) for the chosen app framework, and with [visualization verification](../visualization-verification/SKILL.md) for data, reconnect, interaction and rendered QA. Use the actual data and dashboard owner's runtime and permissions.

For filtering, record comparison, arithmetic scenarios or computed findings, select and read the relevant full method from [exploration state and comparison](references/exploration-state-and-comparison.md). This is conditional depth, not a required dashboard shell; a static KPI request does not load it.
