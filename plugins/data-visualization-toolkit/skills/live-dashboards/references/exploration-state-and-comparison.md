# Exploration state and comparison: choose the complete method

Use only for task-relevant interactive exploration. Keep the complete existing live dashboard procedure for freshness, streaming, stale/offline, accessibility, performance and exports. This index does not replace any method.

- Filtering or empty results: read [scope and attributable recovery](scope-and-empty-results.md).
- Arithmetic what-if: read [scenario overlays](scenario-overlays.md); a predictive relationship needing a model belongs to [statistical evidence](../../statistical-evidence/SKILL.md).
- Comparing two records: read [comparison selection, encoding and evidence](two-item-comparison.md).
- Claims that change with filters: read [computed prose](computed-prose.md).
- Multi-step exploration and undo: use the complete UX `design-studio/references/exploration-recovery.md` procedure through the existing UX owner. If that owner is unavailable, state that dependency and use this package's worked examples as examples, not a substitute claimed to be the missing procedure.

Keep the sources immutable, record source/derived/hypothetical distinctions, and choose the actual task's scope, denominator, reset and accessibility tests. A static KPI request does not need these interactive procedures.

For whole-experience choices or requested alternatives, first use UX Design Studio `dashboard-design` and its complete `references/experience-architecture-selection.md`. If UX is unavailable, preserve the requested task/format and state the missing method; do not infer its cache location. Existing chart engineering and the full inherited dashboard procedure remain sufficient for ordinary static KPI rendering.
