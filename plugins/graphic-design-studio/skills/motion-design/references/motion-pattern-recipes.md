# Original motion pattern recipes

Select a pattern for the message, not to fill a gallery. These are original production briefs informed by two batches of user-supplied stills associated with [Charlie Hills' motion article](https://charliehills.substack.com/p/opus-55-motion-graphics). They are not the author's missing prompts, code or exact motion specifications. The supplied stills now cover all sixteen named effects, including an overview board. The original prompt collection and executable board remain unavailable. This is original guidance covering the sixteen mechanisms, not an import of the author's kit.

## Shared recipe contract

Each selected recipe inherits the [reference-to-motion prompt](reference-to-motion-prompt.md): route/deliverable, audience/message, approved assets, start/change/hold/end, trigger and replay policy, static alternative and checks at delivery size. Fill only the selected recipe, not all sixteen. For a first trial, one bounded transition followed by a readable hold is sufficient; infer timing, then tune against actual playback. Use the existing stack; no recipe implies a library installation, model choice, fixed duration or automatic loop.

### 01. Button becoming a player — batch B Photo 8

**Use:** connect a demo call to action to its actual media, or illustrate that relationship in a clearly labeled promo.

**Sequence:** recognizable button → expanded media frame → usable player or illustrative playback state → close/return. Preserve the visual relationship without retaining duplicate controls.

**Prompt:** “Expand [demo action] into [actual media frame or labeled illustration]. Keep the action recognizable and reserve the needed space. For a real player, preserve keyboard controls, loading/error states, appropriate focus management, close/reopen and user control over audio. Show a usable static player with reduced motion. Verify the transition, media failure and repeated activation; do not imply playback succeeds from a poster alone.”

### 02. Query becoming results — batch B Photo 7

**Use:** show a product's retrieval experience. Choose functional search or a labeled demonstration before authoring the motion.

**Sequence:** query context → result state → readable result list → deliberate rest/replay. Real results follow actual data, never an illustrative timer.

**Prompt:** “Show [query] leading to [approved results] in [functional/illustrative mode]. Preserve the query and result identity as the list appears. Illustrative typing must not overwrite a visitor's input or announce every decorative character. Functional search needs loading, empty, failed and out-of-order response handling. Keep results readable without motion. Verify query changes, focus, reading order and pause/replay where applicable.”

### 03. Card becoming a workspace — batch B Photo 6 and overview Photo 9

**Use:** establish continuity from an item summary to its editing context. The detailed still shows an expansion outline; the overview supplies a small editor view, not proof of working editing or saving.

**Sequence:** item card → expanded container → usable workspace → return to original item/context. Keep document identity and existing edits intact.

**Prompt:** “Open [existing item] into [existing workspace] while preserving its identity through the visual transition. Keep actual editing, save/error behavior and navigation unchanged. Define route or dialog behavior, focus destination and return, plus interruption during open/close. Reduced motion opens the workspace directly. Verify keyboard entry/return, unsaved changes and rapid reopening; do not create an editor backend solely for an illustrative feature animation.”

### 04. Tab indicator and panel change — batch B Photo 5

**Use:** clarify a visitor-selected switch between related panels. A promo may illustrate selection, but a functional tab set must not cycle itself while someone reads.

**Sequence:** selected tab/panel → new selection → indicator moves and corresponding panel changes → stable new state. Content state should not wait for a decorative transition to finish.

**Prompt:** “Animate the existing selected-tab indicator between [panels], keeping selection, labels and visible content synchronized. Preserve the component's accessible keyboard model and prevent hidden panels from receiving focus. Handle unequal panel heights without clipping. Interrupt toward the latest selection instead of queuing transitions. With reduced motion switch immediately. Verify rapid switching, keyboard selection, focus and content at narrow widths.”

### 05. Bars becoming a line — batch B Photo 4

**Use:** explain two valid encodings of the same ordered series. Avoid connecting unrelated categories or suggesting continuous measurements that do not exist. The supplied image explicitly labels its data illustrative.

**Sequence:** labeled bars → corresponding endpoints remain fixed while bar emphasis fades and connections emerge → line with the same points and scale → readable hold. A crossfade or side-by-side comparison is preferable if correspondence is unclear.

**Prompt:** “Transition [approved ordered dataset] from bars to a line while preserving values, units, baseline, axis scale and point identity. First confirm that a line is a valid encoding; otherwise use a non-morphing comparison. Keep every value available in a static/table alternative and mark samples as illustrative. Avoid smoothing that introduces unsupported extrema or implied measurements. Verify each endpoint against the source data and inspect the transition for misleading intermediate geometry.”

Quantitative encoding and correctness belong to the existing Data Visualization specialist; Graphic Design owns visual continuity. Do not inherit the reference's unlabeled scale or sample figures as production facts.

### 06. Dashboard detail expansion — batch B Photos 2–3

**Use:** emphasize one metric while preserving its relationship to an overview. Avoid zooming away the comparison a user needs to make a decision.

**Sequence:** overview with selected tile → related detail card expands → metric context and trend hold → return to overview. Maintain filters, time range, units and selection.

**Prompt:** “Expand [metric tile] into a detail view using the same approved value, period, units, comparison basis and filters. Keep the connection to its overview visible without hiding essential context. For real interaction define focus, close/back and scroll restoration; for a promo label example figures. Reduced motion reveals detail directly. Verify value consistency, comparison labels, close/reopen and narrow-screen fit; a decorative sparkline must not masquerade as measured data.”

### 07. Card fan and settle — screenshot 07 / Photo 10

**Use:** introduce a small set of case studies, products or related items. Avoid stacked content when all items must be compared simultaneously.

**Sequence:** compact stack → spread with limited stagger → damped settle → stable readable selection. Retain each card's identity and deliberate paint order. Rotation is optional; constrain it when copy is long.

**Prompt:** “Present [approved items] as a compact stack that opens into [readable arrangement] on [trigger]. Preserve each card's content and identity. Use restrained overshoot and settle once; keep [selected item] clear. On narrow screens use [list or single-item layout]. With reduced motion show the final arrangement. Verify that all required content and actions remain accessible, card edges do not clip, and repeated triggers do not accumulate transforms.”

### 08. Proximity dock — screenshot 08 / Photo 9

**Use:** emphasize a small set of familiar tools or destinations. A labeled navigation row may be better for unfamiliar icons or touch-first tasks.

**Sequence:** stable row → bounded visual enlargement near pointer or focused item → readable label → neutral rest on exit. Keep hit areas and ordering fixed while the inner artwork moves.

**Prompt:** “Give [existing destinations] proximity emphasis without changing their navigation behavior. Scale only the visual layer inside stable targets; make labels available on keyboard focus and touch as well as pointer use. Keep the focused item visible, prevent neighboring overlap from intercepting input, and use a static emphasis for reduced motion. Verify pointer exit, keyboard traversal and touch activation without a hover prerequisite.”

### 09. Image-filled lettering — screenshot 09 / Photo 8

**Use:** a short campaign heading with approved artwork. Avoid for body text or words whose identity depends on the moving fill.

**Sequence:** readable word → image moves within the stationary letter mask → settled crop and reading hold. Keep the word shape stable; the artwork supplies the change.

**Prompt:** “Fill [short heading] with [authorized artwork] using a bounded reveal within the letterforms. Preserve a readable outline or solid fallback through every state. Keep a single accessible text equivalent and avoid duplicate announcements from decorative layers. Show a legible static treatment when motion or the image is unavailable. Check contrast at the least legible intermediate frame, not just the final crop.”

### 10. Elastic lettering — screenshot 10 / Photo 7

**Use:** an expressive short title or brand accent. Avoid distortion of instructions, prices or long reading passages.

**Sequence:** legible word at rest → small variation in selected glyphs → settle onto one baseline → readable hold. A verified variable font may provide suitable axes; a transform treatment is an alternative, not an equivalent font capability.

**Prompt:** “Animate [title] with restrained letter expansion anchored to one baseline, preserving the word's recognition and spacing. Use only axes supported by [chosen font], otherwise choose a simple bounded transform. Reserve the maximum visual extent so adjacent content stays still. Keep one accessible heading and return to undistorted text. Verify long-word fit, font-loading fallback, baseline stability and a motion-free resting state.”

### 11. Headline becoming a composition — screenshot 11 / Photo 6

**Use:** demonstrate how an idea becomes an editorial or product layout. For an actual article, immediate access to the completed page takes priority.

**Sequence:** headline → same headline positioned in the final hierarchy → supporting text and image appear → complete composition holds. Keep source and destination identity clear without showing duplicate readable headlines unnecessarily.

**Prompt:** “Transform [headline] into the heading of [approved final composition], then introduce [supporting elements] in reading order. Reserve final geometry from the start and preserve semantic DOM order. Keep all content available without waiting for the animation. On small screens use the actual responsive final layout. Verify that the transition neither shifts surrounding content nor steals focus.”

### 12. Segmented image reveal — screenshot 12 / Photo 5

**Use:** a launch image or portfolio detail where a brief reveal adds emphasis. The still shows the image; moving slats are described by the heading, not observed in playback.

**Sequence:** image already loaded beneath decorative strips → strips retract in a modest stagger → unobstructed image holds. Do not make the reveal a loading gate.

**Prompt:** “Reveal [authorized image] with a few decorative segments retracting across its reserved frame. Preserve crop and focal point at each breakpoint. Keep meaningful alternative text attached to the underlying image; decorative segments are noninteractive. Reduced motion shows the image directly. Verify slow/failed image loading, no remaining slivers over the final image, and no flashing or pointer-blocking overlay.”

### 13. Separated perspective layers — screenshot 13 / Photo 4

**Use:** explain a layered service, document or architecture. Avoid implying actual 3D structure or system dependencies unsupported by the content.

**Sequence:** aligned assembly → layers separate in a consistent depth direction → labels and relationships hold → optional user-controlled return. Prefer a flat exploded view when perspective makes text hard to read.

**Prompt:** “Explain [verified layers] by separating an aligned composition into labeled planes. Preserve layer order and show [actual relationship] without invented dependencies. Keep rotation and depth within the available frame. Provide a flat labeled view for narrow screens and reduced motion. Verify labels, overlaps and reading order; the sequence must explain more than the static stack alone.”

### 14. Moving focus band — screenshot 14 / Photo 3

**Use:** guide attention through an illustrative list or narrated sequence. Blur is unsuitable when visitors need to compare actual prices, metrics or terms.

**Sequence:** complete readable list → emphasis band moves to selected row → bounded hold → next row or rest. Transfer focus emphasis rather than treating the source's blur as mandatory.

**Prompt:** “Guide attention to [selected row] with a subtle focus band while all factual rows remain readable. For real tables, use border, background or weight rather than blurring alternatives. Distinguish visual emphasis from keyboard focus and selection. Keep values unchanged. Reduced motion places the band immediately or uses static emphasis. Verify contrast, row alignment and access to every value throughout.”

### 15. Pulses along connections — screenshot 15 / Photo 2

**Use:** explain approved process or data-flow relationships. An illustrative pulse does not establish throughput, completion, latency or live operation.

**Sequence:** labeled graph → one path activates in the intended direction → destination receives emphasis → readable rest. A static directional diagram remains complete without the pulse.

**Prompt:** “Explain [verified process] using labeled nodes and directional connections. Animate a pulse along [chosen path] and emphasize its destination without implying measured timing or live status. Label illustrative operation where needed. Preserve node meaning in a static diagram and text equivalent. Verify branch direction, pulse/edge alignment after resize, label collisions and pause behavior for repeats.”

### 16. Dots assembling a mark — screenshot 16 / Photo 1

**Use:** a brief brand flourish or ending. Do not delay site entry or access to navigation until assembly finishes.

**Sequence:** sparse starting positions → bounded convergence → recognizable approved mark → static hold. Use deterministic positions and a restrained number of elements for repeatable review.

**Prompt:** “Assemble [approved/original mark] from a modest number of dots inside a reserved frame. Keep motion bounded and make the final silhouette recognizable at the smallest delivery size. Treat particles as decoration with one accessible brand name. Show the completed mark for reduced motion and if animation fails. Verify convergence, reset, offscreen pause/teardown and device performance; simplify before increasing particle count.”

## Handoff and acceptance

Graphic Design owns composition, continuity, readable holds and original asset direction. For website behavior pass the selected recipe and contract to `ux-design-toolkit:motion-and-performance`, using its `motion-pattern-web-adaptation.md` reference and Sites handoff. For rendered media retain Video Production as owner. If another plugin is unavailable, carry the selected brief directly to the actual builder; do not invent a connection.

Before acceptance of an implementation, map the selected recipe's source anchors to the actual component and viewport, then verify entrance, change, hold and exit/reset in playback. Check narrow/wide layout, static/reduced motion, keyboard/touch where interactive, content truth, asset failure and repeated activation. Use Graphic Design Review for visual composition and UX Design Review for a product interface. Record the evidence and untested states. This text reference itself is not a rendered demonstration or proof that an effect performs well.
