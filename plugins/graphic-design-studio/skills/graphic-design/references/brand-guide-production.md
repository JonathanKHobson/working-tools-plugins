# Produce a usable brand guide

Use for a requested brand guide, identity board or reusable visual kit. A simple
graphic edit does not trigger a new branding project. Marketing Strategy Studio's
`brand-design` owns identity meaning, rule status and kit relationships. Here,
translate the supplied scope into visual instructions and usable assets. If only
templates are supplied, label extracted rules as observations and new identity
choices as proposals; source colors do not establish positioning or a mission.

## Start with the supported uses

Choose the smallest guide that lets its intended reader make the next artifact.
An overview introduces the system; production guidance resolves recurring
decisions. Neither a one-page board nor a long manual is automatically complete.
Read the retained source and compare its render before composing the guide. Use
UX Design Studio's `design-systems` template contract for native extraction
coverage and conflicts, and [the graphic specification handoff](design-specification-handoff.md)
for source/Markdown closure. Keep the accepted identity and composition unless
the user authorized changing them.

Make a guide instructional: pair a relevant rule with its intended context, an
actual visual example, a failure example when useful, and the asset needed to
apply it. Put explanations beside their specimens and give the page a deliberate
reading order. Keep values and links available as text rather than placing the
only usable information inside a raster board.

## Demonstrate what carries this identity

| Element | Useful demonstration and checks |
| --- | --- |
| Identifiers | Show the actual primary mark/wordmark and useful existing or authorized compact, monochrome and reverse variants. Demonstrate clear space, minimum usable size and supported backgrounds with the correct files. Preserve a logo-free source as such unless logo creation is requested; missing variants are not an invitation to invent them. |
| Color | Label values by source role and show relevant pairings. Separate page ground, reading ink, emphasis, surfaces and functional/data colors. A purple header does not imply purple body text. Add print values only for a supported, checked color workflow; a generic CMYK conversion is not a verified print match. |
| Typography | Set real headings, body copy and utility labels in the stated fonts and weights. Show hierarchy, spacing and density, not only an alphabet. Confirm which font actually rendered. If using a portable substitute, name it beside the specimen and document changed metrics or layout; do not label it as the unavailable original. |
| Graphic language | Demonstrate the source's meaningful line, shape, border, texture, image treatment or compositional rhythm. Do not reduce every identity to the same neutral grid and two swatches. Include a motif only when it is present or explicitly part of the requested creative development. |
| Applications | Use a realistic application that exercises the distinguishing rules, plus a demanding size/content case when the supported use needs one. Label invented application copy as sample. A mockup demonstrates use, not adoption, audience response or publication. |
| Verbal expression | Use a supplied or explicitly proposed sample with its scope. Link the writing owner's style/voice resource and version rather than duplicating it. Tone may change by situation; a visual aesthetic alone does not establish a writing voice. |

Use professional guides as evidence of decisions to explain, not as reusable
identity assets. For example, [IBM's logo guidance](https://www.ibm.com/design/language/ibm-logos/8-bar/)
shows optically distinct positive and reversed drawings; its specific geometry
and restrictions apply to IBM. [NASA's guide](https://www.nasa.gov/nasa-brand-center/brand-guidelines/)
distinguishes identifier and medium roles. [Mailchimp's voice guidance](https://styleguide.mailchimp.com/voice-and-tone/)
distinguishes voice from situational tone. None prescribes a universal page count,
logo family or visual style for this work.

## Keep specimens, assets and rules in agreement

Use actual delivered logo files in guide specimens. Keep an editable master when
available and inspect exported geometry, edges, transparency and small-size
behavior. An SVG containing a bitmap is not an editable vector logo. Generated
concept art can inform a production mark; it is not evidence of vector paths,
font identity, exclusivity or trademark clearance.

Bundle only assets whose redistribution is supported. Record the original font,
bundled font or dependency, license/notice, and tested fallback separately;
embedding permission is not necessarily permission to distribute a raw font.
Do not copy third-party reference-board images into a new kit as owned assets.
Use the existing preflight for extracted-bundle links, source fingerprints and
actual export checks instead of declaring completeness from a file list.

## Keep acceptance checks separate

- **Source fidelity:** compare guide specimens and claims with named native-source
  and rendered anchors, including palette/type roles and signature composition.
  A style omitted by extraction is a conflict to resolve, not a license to revise
  the original. Label intentional departures with their authorized scope.
- **Visual craft and usability:** inspect the overview and detailed pages at their
  intended viewing sizes. Review hierarchy, legibility, meaningful examples,
  spacing and accessible information. Color swatches alone cannot establish
  [text contrast in use](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html).
- **Delivery:** inspect the final exports and extracted kit after revisions;
  confirm the advertised assets and current versions are actually included.
  Technical validation, human selection and publication are separate states.

Use [Graphic Design Review](../../graphic-design-review/SKILL.md) for named
anchors and changed-region checks. Do not average away a failed fidelity or
delivery check because the guide looks polished. For multiple identities, fixed
sample content can reveal whether their defining relationships survive without
all outputs converging on the same styling. That comparison is a design
diagnostic, not an audience recognition study. Record the inspected sources,
pages, renderer/fonts and any untested medium rather than promising identical
results across every AI or application.
