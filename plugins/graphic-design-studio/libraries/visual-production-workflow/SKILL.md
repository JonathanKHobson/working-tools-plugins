# Visual Production Workflow

Carry one visual deliverable from its brief to verified output. This is a
portable production contract, not a replacement for a specialist poster,
flyer, document, or presentation skill already installed on the current host.
Read only the relevant specialist and its resources; preserve its useful local
methods rather than replacing them with generic rules.

1. Lock the brief: audience, intended action, exact copy, format, output sizes,
   brand/reference source, and delivery destination. Separate editable text,
   immutable supplied assets, and generated illustration before production.
2. Establish a compact reference board. Label sources by identity, composition,
   material, palette, or mood; one role does not authorize copying another.
   Define the focal subject, action, environment, crop, and excluded details.
3. Reuse a suitable existing layout and test its capacity with the actual copy
   and longest intended variant. Preserve a declared visual style; simplicity
   means removing elements without a purpose, not erasing the subject's identity.
4. Choose the available authoring and image-generation tools from this host's
   tool catalog. Generate one reusable asset at a time and persist its source
   bytes to a stable project path before proceeding. Record role, dimensions,
   source/prompt provenance, and SHA-256. Never treat a chat preview as storage.
5. Integrate at the destination size. Give important copy a quiet reading field,
   a deliberate hierarchy, sufficient contrast, and a crop that protects the
   focal subject. Judge illustration/story correctness independently from layout.
6. Inspect the actual exported output: full composition, intended viewing size,
   text-heavy and edge crops. For web delivery, check representative desktop and
   mobile views; for print, use the actual printer template and physical size.
   Verify exact wording, dates, contact information, URLs, clipping, fonts,
   image quality, and source-to-export parity. Decode any QR code and confirm its
   destination if one is present. Do not infer correctness from a fit flag.
7. Use a small anchor map for revisions: region, observed defect, intended change,
   and verification evidence. Fix the few defects that most affect comprehension
   or craft, then re-export and inspect the changed regions and full composition.
8. Deliver the final artifact with its source and relevant verification evidence.
   Keep production notes out of audience-facing artwork. Approval applies to
   the identified version and action; publishing or ordering prints needs the
   user's authorization, including authorization already given in the task.

## Preservation and handoff

For an immutable approved image, preserve its bytes. A correction creates a new
version with new provenance; approval does not silently transfer. Keep batches
bounded to one completed and inspected asset at a time. Prepare a handoff before
25 generated images or 500 MB of task storage, earlier when context becomes
unwieldy. Record accepted paths, checksums, decisions, pending work, and disposable
intermediates. Never edit live conversation stores to reduce attachment size.
Close only task-owned renderers, browser sessions, and helper processes.

## Cross-computer learning

Compare complete skill folders, including references, scripts, and templates.
Preserve an inventory and file hashes before a merge. Identical copies need no
replacement; install missing packages; review differing files semantically and
keep both preimages before editing. Never resolve a conflict by timestamp alone.

If a destination has a poster/flyer specialist, inspect its actual instructions
and examples before extracting reusable methods. Keep page-format details there;
bring proven source, typography, export, and QA improvements into this common
workflow only when they apply across formats. Do not claim to have learned from
an inaccessible computer. Transfer skills and their resources, not credentials,
conversation databases, account configuration, or private project assets.

## Proven design and export refinements

For posters and flyers, use the installed `graphic-design` family for exact
composition and print details. Carry these cross-format lessons into other work:

- Recompose for a new aspect ratio; preserve factual content and visual identity
  while changing crop, line breaks, scale, and supporting detail. Scaling alone
  does not prove a usable adaptation.
- Judge optical mass and transparent padding, not just geometric centers.
  Thumbnail, intended-size, and detail reviews answer different questions.
- Verify exported files and destination bytes. A preview is not a saved export,
  an HTTP 200 is not the correct asset, and a decoded QR is not a physical scan.
- Preserve historical source imagery and honest proposal/reconstruction labels.
  Optimize derivatives and cap responsive candidates at native resolution.
- Use current tool-supported transparency; chroma is an optional fallback unless
  the active workflow explicitly requires a connected keyed aperture.

Keep optional partner consultation bounded to one useful question and a verified
return artifact. Read only the owning skill and relevant references. Do not
claim speed, token, energy, conversion, or audience improvements without measured
evidence; reduced instruction volume is only a loader-size observation.
