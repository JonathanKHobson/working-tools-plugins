# The Pop-Up Plan brand

Read [DESIGN.md](DESIGN.md) first. Then read only the linked specifications needed for the requested format. The [human guide](guide.pdf) and [guide text](guide.md) show the system; [brand.json](brand.json), [tokens.json](tokens.json) and [asset register](assets/manifest.json) provide exact values and usable files.

1. Identify audience, output format, supported content and intended size. Treat examples as fictional content, not facts to reuse.
2. Preserve the recognition rules in DESIGN.md. Use the supplied vector logo; select primary, compact, monochrome or reverse from [LOGO.md](LOGO.md).
3. Use exact palette values from [COLORS.md](COLORS.md). Read [TYPOGRAPHY.md](TYPOGRAPHY.md) before choosing fonts. Source families and included substitutes are explicitly different where licensing or portability requires it.
4. Apply [LAYOUT.md](LAYOUT.md), [COMPONENTS.md](COMPONENTS.md) and [ADAPTATIONS.md](ADAPTATIONS.md). For an exact native-template adaptation, use the linked design template as well as this brand kit; the brand kit alone does not replace its native artifact.
5. Use [STYLE.md](STYLE.md) for voice. Keep evidence, attribution, uncertainty, numerical meaning and task facts intact.
6. Render the complete output. Check the opening, a dense case, smallest mark, type wrapping, grayscale/reverse use and relevant interactive states. Compare against the guide and source-relative records. Report any substitutions and intentional departures.

Do not claim installation until the host actually installs this skill. Do not claim identical rendering across models or systems from textual compliance alone. The named files form the execution guidance; an extra persona or AGENTS.md is unnecessary for this kit.
