# Design a recognizable, usable expression system

## Establish the brief and protect existing evidence

Read the relevant profile scope and actual artifacts. Name the intended impression, audience task, proof, context, constraints, existing recognition and open questions. Distinguish a refresh, new identity, campaign treatment and exploratory direction. Specify Change / Keep / Defer before altering approved work. A refresh may preserve more than it changes.

Map 3–8 useful source anchors when reviewing visual material: ID, artifact/viewport/page, region, selector/node if available, observed fact and intended action. This records what was actually seen. Do not claim an asset looks coherent from its filename or extracted text.

Design may expose a better question or an unsupported promise; return that specific issue to discovery. It need not be a one-way funnel from a fixed positioning statement. Ask how the experience behaves as well as how it looks: welcoming, reliable, participatory or careful must become observable choices if used in the brief.

## Develop creative territories with a reason to exist

Use references and anti-references to identify mechanisms—contrast, pacing, framing, information hierarchy, material, imagery, composition, metaphor or interaction—not just colors. Retain source links and rights limits. Never copy a distinctive identity or assume downloaded assets are reusable.

When a real direction choice exists, make two or three concise territories. For each describe:

- Organizing idea and intended relationship, with supporting evidence and the main tension.
- What it looks, sounds and behaves like; one repeatable signature and its contextual range.
- What it rejects, when it would fail, and its production demands.
- A comparable rough application that demonstrates the idea.

Names such as “bold,” “minimal” and “premium” are insufficient without decisions. Change the organizing idea, image-making, hierarchy or voice behavior, not just the palette. Keep facts, sample length and finish comparable so polish does not decide the comparison. Respect an explicitly chosen single direction; alternatives are an uncertainty-reduction tool, not mandatory extra deliverables.

## Translate the idea into components

Choose only components the real applications need. Explain how each supports the intended relationship and how it combines with the others.

| Component | Decisions and proof needed |
| --- | --- |
| Name, descriptor, wordmark and symbol | Role of each; spoken/read recognition; lockups; small-size behavior; when the name must accompany a new symbol. Naming or similarity checks are not legal clearance. |
| Color | Semantic and expressive roles, usable pairings, light/dark contexts, accessible text/control use; measured contrasts in actual applications. Avoid universal emotion claims or a compulsory color proportion formula. |
| Typography | Character and hierarchy, readability at target sizes, language coverage, font licenses, fallback behavior; test actual headlines and dense text. |
| Composition | Grids, rhythm, density, alignment, whitespace and focal hierarchy; rules that allow more than one layout. |
| Imagery and illustration | Subjects, perspective, lighting, framing, texture, source rights and exclusion examples; image treatment should support the message. |
| Personal presence, when requested | Portrait, wardrobe, environment and on-camera choices as voluntary expression; no body/identity diagnosis or assumption that appearance must be standardized. |
| Voice and message | Observable wording, sentence movement, argument/proof, metaphor and invitation; tone range by audience and situation. Link the writing owner's samples. |
| Motion and sound, when useful | Purpose, pacing, transitions, sonic cues, accessibility/reduced-motion needs, licensing and platform constraints. A reusable signature must not delay the audience's task. |
| Behavior and experience | Response, facilitation, service, interface or delivery choices that demonstrate the stated promise; unresolved delivery gaps go back to operations. |

Design tokens can express approved color/type/spacing decisions for implementation; token completeness does not prove strategic quality. A generated moodboard is exploration. Exact logo geometry, color values, fonts and editable assets require the appropriate production tools and export checks.

## Make the system work in different settings

Define invariants (recognition/meaning), variables (contextual adaptation) and prohibited conflicts. For a multifaceted person, name or authorship may be the shared cue while aesthetic intensity varies. For a company with multiple offers, identify inheritance and endorsement rules. Do not make every context look the same or automatically create a new sub-brand for each platform.

Demonstrate the design on the hardest relevant applications, not only attractive mockups: a small avatar, a dense explanation, a short mobile introduction, an event sign, a product state or a monochrome reproduction. Select a few based on actual use. Compare an existing baseline when changing something people already recognize.

Check whether the system allows a second independently made asset. If every new piece needs a fresh art direction, simplify or document the missing rule. If every piece looks like a rigid copy, identify the variable that can change while preserving recognition. Craft templates only for recurring tasks, with editable content and long/short copy behavior.

## Evaluate and hand off

Use [evaluation](evaluation.md) to separate preference, personal fit, comprehension, recognition and commercial response. Tradeoffs need decisions rather than an averaged score that hides them. Record why the selected direction serves the brief, what it sacrifices and what would change the choice.

For visual output, use the relevant Graphic Design review and target-size inspection, then verify changed anchors. Normal digital text and controls need applicable WCAG checks; the logo exception does not exempt surrounding text or interface components. Include relevant crops, font fallback, reading order, captions/alt text, reduced motion and language expansion. Passing contrast alone is not a full accessibility assessment.

Hand off the selected scope, rationales, concrete examples/non-examples, reusable rules, editable sources, checked exports, rights and remaining tests. Use only the guide depth needed by the next maker. Human selection, technical QA, file delivery, native application and public verification are distinct states. Preserve prior versions and a scoped rollback when replacing a live identity; do not publish or change accounts merely because a design was selected.
