# Search-facing marketing language and SEO

Use this reference for an actual page, landing section, search snippet, or refresh decision. Search performance depends on the site and market; copy alone cannot promise rankings, traffic, citations, or conversions.

## Frame the reader task

1. Name the reader, situation, and job they came to the page to complete. Map the query or audience question to intent: learn, compare, choose, buy, troubleshoot, or navigate. One page should satisfy a coherent task; do not cram incompatible intents into a keyword list.
2. Inspect the existing page, user-provided search data, and current public results when recency matters. Separate observed SERP features and competitor wording from first-party Search Console or analytics measurements. A public search observation is not the site's impression, click, rank, or conversion history.
3. Identify the page promise and the proof available now: shipped capability, concrete example, process detail, customer-approved evidence, or verifiable constraint. Turn a feature into a benefit only when the causal bridge is defensible. “Exports a CSV” can support “take your data into a spreadsheet”; it cannot support “saves hours” without measured evidence.
4. Draft an answer that completes the reader task. Put the essential answer or offer early; use examples and clear next steps. Respect technical accuracy, user terminology, accessibility, and trust signals. Avoid repeating keywords where natural language conveys the same topic.
5. Write title, H1, and meta description as accurate summaries of the page. Keep the promise consistent across snippet and page. Metadata is a candidate search presentation, not a guaranteed displayed snippet. Add an FAQ only when actual recurring questions are useful to the reader and the page can answer them substantively; do not add FAQ solely for schema or keyword coverage. Use structured data only when it truthfully represents visible content and fits current platform rules.
6. Review internal links by the next reader task and destination relevance. Record technical issues separately from copy problems, and choose refresh, expand, merge, remove, or no-op based on evidence. Do not rewrite a page merely because a keyword tool says to.

## Claim and measurement gate

- Keep product facts, proposed value, testimonials, and measured outcomes distinct. Do not invent search volume, CTR, position, time savings, engagement, revenue, authority, or customer language.
- For a before/after SEO claim, retain source, URL set, time window, denominator, comparison period, and known changes. Rank movement is an observation, not proof that one copy edit caused it.
- If source evidence is thin, write a modest promise and mark the proof task. Do not hide missing evidence behind persuasive phrasing.

## Small deliverable

Return the reader task and intent, page promise, supporting proof, proposed copy, title/meta if needed, any appropriate FAQ, a concise change rationale, and a checkable review date or measurement plan. For a one-paragraph copy request, provide the copy directly and only the material caveat.

## Landing pages and constrained copy

For a landing-page draft, start with the reader's problem and a supported promise; add a short explanation, concrete benefits tied to features, credible proof, answers to material objections, and one clear next action. Use the brief to choose order and depth rather than force every section into a short page. Never invent testimonials or outcomes to fill a proof slot. UX Design Studio owns the interface; this reference owns the message.

Before delivering ad headlines or platform copy, verify the current destination's character/format requirements and count the final text where a limit is binding. For search titles and descriptions, put distinguishing meaning early, remove repetition and preview likely clipping across widths. Google does not define universal 60/160-character limits; display truncation depends on the presentation. Treat a draft length target as a heuristic, not a compliance rule or a guaranteed rendered snippet.
