# Survey question design

Write or revise survey questions, response choices and scales for valid, neutral and analyzable measurement.

## Complete procedures to load

Read the task-matching files below in full before applying that procedure. Load only the relevant variant and its required support. These contain the operative methods, examples and templates; this entrypoint does not replace them. A plugin is a package, not a requirement to read every skill.

- [Complete question-writing procedure](../survey-strategist/references/question-writing.md) — read when drafting or revising respondent wording.
- [Complete question-types procedure](../survey-strategist/references/question-types.md) — read when selecting an answer format for a construct.
- [Complete response-options-and-scales procedure](../survey-strategist/references/response-options-and-scales.md) — read when writing choices, scales and coded values.
- [Complete validated-measures procedure](../survey-strategist/references/validated-measures.md) — read when considering an established measure or adapting its wording.
- [Canonical instrument contract](../../references/instrument-contract/instrument-contract.md) — read when reviewing or changing stable question IDs, codes and analysis lineage.

## Workflow

1. Identify the construct, target population, recall window and analysis use.
2. Apply the complete question/scale procedures. Preserve validated wording/scoring when required and disclose any adaptation.
3. Check one construct per question, neutrality, mutually exclusive options, missing responses and stable coding.

## Deliver and verify

Return respondent copy plus rationale, construct, codes and analysis mapping.

## Example boundary

Good: ask about one bounded recent behavior. Bad: ask whether service was “fast and helpful” in one item.

Keep one canonical instrument in its owning project. Preserve decision → construct → question → coded value → analysis use. Never infer anonymity, scale validity, legal compliance or platform compatibility. For rendered deliverables verify the changed visual and respondent path; a schema check alone is insufficient.
