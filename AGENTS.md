# Working Tools public source

Read README.md, docs/project-map.md and the selected package's README before editing. catalog/packages.json owns package identity, version, requirements and distribution state. Package source is under plugins/. Marketplace catalogs are generated by scripts/packages.py; never edit them independently.

Run `python3 scripts/packages.py catalog`, `python3 scripts/packages.py validate` and `python3 -m unittest discover -s tests -v`. Run each changed package's documented behavioral tests. Build with `python3 scripts/packages.py build`. Do not label an artifact released until GitHub bytes and native installation have been verified.

These are reviewed public editions. Private canonical source, personal configuration and installed caches are not inputs to public CI. Preserve per-file provenance, upstream licenses and complete operative procedures. Do not import private paths or provider binaries. A public contribution needs deliberate reconciliation with the author's source before a later export; do not overwrite it with an old export.

Before publication, use `python3 scripts/packages.py release --canonical-root "$CANONICAL_PLUGINS"` and verify downloaded archives against its source-release manifest. `build` alone does not clear release readiness. Preserve the reviewed source inventory and audit baseline; resolve named differences rather than regenerating either from an incomplete output tree.

After an authorized completed public update, apply [release management](docs/release-management.md) and run `.venv/bin/python scripts/complete_update.py --config "$RELEASE_CONFIG"`. Supply diff-grounded change records as part of authoring; finish the Site adapter/readback before reporting complete. Use `--reconcile-only` after a partial publication. Do not publish on interim saves or expand private exclusions.
